MPOtpField ​

A row of one-character slots: a PIN, a texted verification code, an invite key. One hidden value behind however many inputs.

ReactFlutter
tsx
import { MPOtpField } from 'material-plus-ui';

<MPOtpField label="Verification code" onComplete={(code) => verify(code)} />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPOtpField(label: const Text('Verification code'), onComplete: (String code) => verify(code));

The label is above the row, not in a notch ​

This is the one place the control departs from MPTextField's shell.

A notched label belongs to one outlined box; a code is six of them, and cutting the notch into the first would name the first digit rather than the field. Everything else is the same object: the same corner-extra-small, the same hairline in outline, the same two-pixel primary ring on focus.

Examples ​

length ​

Clamped to 2–12. A single box is an MPTextField, and past twelve the row stops fitting a phone.

groupSize and separator ​

ReactFlutter
tsx
import { MPOtpField } from 'material-plus-ui';

/**
 * `groupSize` splits the row with a separator, and `charset` decides what may
 * be typed at all — anything rejected is dropped rather than shown.
 */
export default function OtpFieldGrouping() {
  return (
    <div style={{ display: 'grid', gap: 24, justifyItems: 'start' }}>
      <MPOtpField label="Two blocks of three" length={6} groupSize={3} />
      <MPOtpField
        label="Licence key"
        length={8}
        groupSize={4}
        charset="alphanumeric"
        separator="—"
        size="sm"
      />
      <MPOtpField label="PIN" length={4} mask size="sm" />
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// `groupSize` splits the row with a separator, and `charset` decides what may
/// be typed at all: anything rejected is dropped rather than shown.
class OtpFieldGrouping extends StatelessWidget {
  const OtpFieldGrouping({super.key});

  @override
  Widget build(BuildContext context) {
    return const Column(
      mainAxisSize: MainAxisSize.min,
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 24,
      children: <Widget>[
        MPOtpField(label: Text('Two blocks of three'), length: 6, groupSize: 3),
        MPOtpField(
          label: Text('Licence key'),
          length: 8,
          groupSize: 4,
          charset: MPOtpFieldCharset.alphanumeric,
          separator: Text('—'),
          size: MPSize.sm,
        ),
        MPOtpField(label: Text('PIN'), length: 4, mask: true, size: MPSize.sm),
      ],
    );
  }
}

charset ​

numeric is the default because that is what a texted code is, and it is also what puts a number pad in front of a phone. Anything the charset rejects is dropped rather than shown, and onValueInvalid reports it.

onComplete ​

Fires the moment the last slot is filled — which is the moment to verify the code, rather than waiting for a submit button nobody is going to press. autoSubmit goes one step further and submits the MPForm the field is in.

errorMessage ​

There is no separate error boolean. The message is what puts the field into its error state, and it re-points every slot's outline, ink and caret at error together.

ReactFlutter
tsx
import { useState } from 'react';
import { MPOtpField } from 'material-plus-ui';

/**
 * There is no `error` boolean: the message is what puts the field into its
 * error state. Type `000000` to see it.
 */
export default function OtpFieldStates() {
  const [code, setCode] = useState('000000');

  return (
    <div style={{ display: 'grid', gap: 24, justifyItems: 'start' }}>
      <MPOtpField
        label="Verification code"
        value={code}
        onValueChange={setCode}
        errorMessage={code === '000000' ? 'That code has expired.' : undefined}
      />
      <MPOtpField label="Verification code" defaultValue="4821" length={4} disabled />
      <MPOtpField label="Recovery code" defaultValue="931204" readOnly />
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// There is no `error` boolean: the message is what puts the field into its
/// error state. Type `000000` to see it.
class OtpFieldStates extends StatefulWidget {
  const OtpFieldStates({super.key});

  @override
  State<OtpFieldStates> createState() => _OtpFieldStatesState();
}

class _OtpFieldStatesState extends State<OtpFieldStates> {
  String _code = '000000';

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 24,
      children: <Widget>[
        MPOtpField(
          label: const Text('Verification code'),
          value: _code,
          onChanged: (String next) => setState(() => _code = next),
          errorMessage: _code == '000000' ? const Text('That code has expired.') : null,
        ),
        const MPOtpField(
          label: Text('Verification code'),
          initialValue: '4821',
          length: 4,
          disabled: true,
        ),
        const MPOtpField(label: Text('Recovery code'), initialValue: '931204', readOnly: true),
      ],
    );
  }
}

size ​

Every rung is the control height of the same name, so a code sits at the same height as the fields above and below it in a form. The width is not: a slot holds one character, so it is drawn narrower than it is tall — which is what makes a row of them read as places for one character each rather than as a row of tiny fields.

The type scale goes well above the control ladder for the same reason. A verification code is read out loud off a phone and typed with the other hand; it is the one piece of text in a form that should be larger than the label above it.

ReactFlutter
tsx
import { MPOtpField } from 'material-plus-ui';
import type { MPSize } from 'material-plus-ui';

/**
 * Every rung is the control height of the same name, so a code sits at the same
 * height as the fields above and below it in a form.
 *
 * The **width** is not: a slot holds one character, so it is drawn narrower than
 * it is tall — which is what makes a row of them read as places for one
 * character each rather than as a row of tiny fields. The type scale goes above
 * the control ladder for the same reason a code is read out loud off a phone.
 */
const SIZES: { size: MPSize; note: string }[] = [
  { size: 'xs', note: '32 tall, 28 wide' },
  { size: 'sm', note: '40 tall, 36 wide' },
  { size: 'md', note: '56 tall, 48 wide — the default' },
  { size: 'lg', note: '64 tall, 56 wide' },
  { size: 'xl', note: '72 tall, 64 wide' }
];

export default function OtpFieldSizes() {
  return (
    <div style={{ display: 'grid', gap: 20, justifyItems: 'start' }}>
      {SIZES.map(({ size, note }) => (
        <MPOtpField
          key={size}
          size={size}
          length={4}
          defaultValue="4821"
          label={`size="${size}" — ${note}`}
        />
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// Every rung is the control height of the same name, so a code sits at the
/// same height as the fields above and below it in a form.
///
/// The width is not: a slot holds one character, so it is drawn narrower than
/// it is tall, which is what makes a row of them read as places for one
/// character each rather than as a row of tiny fields.
const List<(MPSize, String)> _sizes = <(MPSize, String)>[
  (MPSize.xs, '32 tall, 28 wide'),
  (MPSize.sm, '40 tall, 36 wide'),
  (MPSize.md, '56 tall, 48 wide — the default'),
  (MPSize.lg, '64 tall, 56 wide'),
  (MPSize.xl, '72 tall, 64 wide'),
];

class OtpFieldSizes extends StatelessWidget {
  const OtpFieldSizes({super.key});

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 20,
      children: <Widget>[
        for (final (MPSize size, String note) in _sizes)
          MPOtpField(
            size: size,
            length: 4,
            initialValue: '4821',
            label: Text('size: MPSize.${size.name} — $note'),
          ),
      ],
    );
  }
}

Accessibility ​

  • Base UI owns the hidden value behind the slots, paste spread across them from wherever the caret was, backspace stepping back a box, a click landing on the first empty slot rather than the one under the pointer, and the autofill hook that lets a phone offer the code straight from the message.
  • The separator is aria-hidden: the dash is punctuation inside one value, not a break between two things, and a reader that announces it once per group is reading out the shape of the box instead of the code in it.
  • Focus is drawn on :focus rather than :focus-visible, because a slot is put in focus by clicking it as often as by typing into it — and the ring is the only thing saying which character the next keystroke lands on.
  • One editor stands behind the slots, so paste spreads across them from wherever the caret was, backspace steps back a box, and a press anywhere in the row lands after the last character rather than on the slot under the pointer. The editor asks for AutofillHints.oneTimeCode, which lets a phone offer the code straight from the message.
  • A long press, or a right click with a mouse, opens a menu with Paste in it when the clipboard holds text: iOS's own menu where the system offers it, and Material's elsewhere. The editor is hidden behind the boxes, so there is nothing for selection handles to hold, and this is how a phone pastes a code it copied. A screen reader opens the same menu with its long-press action.
  • The field is one text field node for a screen reader, holding the code itself; with mask it says so and reads dots.
  • The separator is kept off the semantics tree: the dash is punctuation inside one value, not a break between two things, and a reader that announces it once per group is reading out the shape of the box instead of the code in it.
  • The ring is drawn whenever the field has the focus, by pointer or keyboard, because a slot is put in focus by pressing it as often as by typing into it — and the ring is the only thing saying which character the next keystroke lands on.

Differences from the React build ​

Most of this page is the same in both packages. These are the places where it is not, and why.

ReactFlutterWhy
onValueChangeonChangedFlutter's name. onComplete and onValueInvalid keep theirs.
defaultValueinitialValueFlutter's name.
autoFocusautofocusFlutter's name.
separator (a node)separator (a widget)const Text('–') by default, set in the slot's type.
autoSubmit (owning <form>)autoSubmit (owning MPForm)Flutter has no native form; the field submits the MPForm around it.
className, style—There is nothing to pass them through to.
—semanticLabel, focusNodeA name for a field with no visible label, and the focus from outside.

The rest is matched deliberately: the slot sizes and type, the label above the row, the ring that does not grow the slot, the charset and the clamp on length.
