MPNumberField ​

A field that only holds a number, wearing `MPTextField`'s shell to the pixel. Arrow keys and steppers move by `step`, the value clamps to `min` and `max`, and `format` writes it as currency or a percentage while the value stays a plain number.

ReactFlutter
tsx
import { MPNumberField } from 'material-plus-ui';

const [quantity, setQuantity] = useState(1);

<MPNumberField label="Quantity" value={quantity} onValueChange={setQuantity} min={1} max={20} />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPNumberField(
  label: const Text('Quantity'),
  value: quantity,
  onChanged: (double? next) => setState(() => quantity = next),
  min: 1,
  max: 20,
);

The field is controlled when value is given, null included, which is an empty field. Leave value out and the field keeps its own number, starting at initialValue. What does not carry across from the React package is in differences from the React build.

Why not <input type="number"> ​

The native one is worth being explicit about, because it looks like it would do.

It silently accepts text in some browsers. Its spinner cannot be styled, and in Safari there is no spinner at all. It scrubs on scroll by default, so a page scrolling under the pointer changes the value. And it reports '' for anything it fails to parse, which means a field that is slightly wrong and a field that is empty are indistinguishable to the code reading it.

This is type="text" with inputmode="numeric" and a role description, which is what Base UI's number field does — so a phone still shows the numeric keypad and a screen reader still says it is a number field, while the parsing is done against the locale rather than against whatever the browser feels like.

What is under it ​

A text field with the numeric keyboard, and the number kept apart from the text. A lone - on the way to -5 is text that does not parse yet, not a number, so the field reports null while it is there and settles the box when the field is left. Everything a number field adds — the steps, the clamp, the formatting — is the field's own work, so it behaves the same on every platform.

Examples ​

format ​

format goes straight to Intl.NumberFormat, so the box can say $1,240.00 while onValueChange still hands over 1240.

format is a function from the number to the text in the box, so the box can say $1,240.00 while onChanged still hands over 1240. parse is the other half, from typed text back to a number. Left out, it drops everything but digits, a sign and a decimal point, which is enough to read back a currency or a unit; a percentage needs its own, since 15% is 0.15.

ReactFlutter
tsx
import { useState } from 'react';
import { MPNumberField } from 'material-plus-ui';

/**
 * The field shows a written number; the value stays a plain one.
 *
 * `format` goes to `Intl.NumberFormat`, so the box says `$1,240.00` while
 * `onValueChange` still hands over `1240` — which is the whole reason this is a
 * prop rather than something a caller does to `value` on the way in. Type into
 * it: the separators and the symbol come back on their own.
 */
export default function NumberFieldFormat() {
  const [price, setPrice] = useState<number | null>(1240);
  const [share, setShare] = useState<number | null>(0.15);

  return (
    <div style={{ display: 'grid', gap: 20, maxWidth: 300 }}>
      <MPNumberField
        label="Price"
        value={price}
        onValueChange={setPrice}
        format={{ style: 'currency', currency: 'USD' }}
        step={10}
        min={0}
        fullWidth
      />
      <MPNumberField
        label="Commission"
        value={share}
        onValueChange={setShare}
        format={{ style: 'percent', maximumFractionDigits: 1 }}
        step={0.01}
        min={0}
        max={1}
        fullWidth
      />
      <small className="text-mp-on-surface-variant">
        The values behind those are <code>{String(price)}</code> and <code>{String(share)}</code>.
      </small>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// The field shows a written number; the value stays a plain one.
///
/// `format` writes the box as `$1,240.00` while `onChanged` still hands over
/// `1240`, which is the whole reason it is a parameter rather than something a
/// caller does to `value` on the way in. Type into it: the separators and the
/// symbol come back on their own.
class NumberFieldFormat extends StatefulWidget {
  const NumberFieldFormat({super.key});

  @override
  State<NumberFieldFormat> createState() => _NumberFieldFormatState();
}

/// Thousands separated by commas, two decimal places, a dollar sign.
String _currency(double value) {
  final String fixed = value.abs().toStringAsFixed(2);
  final String whole = fixed
      .substring(0, fixed.length - 3)
      .replaceAllMapped(RegExp(r'(\d)(?=(\d{3})+$)'), (Match match) => '${match[1]},');

  return '${value < 0 ? '-' : ''}\$$whole${fixed.substring(fixed.length - 3)}';
}

/// A share written as a percentage, to one decimal place at most.
String _percent(double value) {
  final String fixed = (value * 100).toStringAsFixed(1);

  return '${fixed.endsWith('.0') ? fixed.substring(0, fixed.length - 2) : fixed}%';
}

/// What a percentage is typed as, read back as a share.
double? _readPercent(String text) {
  final String digits = text.replaceAll(RegExp(r'[^0-9.\-]'), '');
  final double? number = double.tryParse(digits);

  return number == null ? null : number / 100;
}

class _NumberFieldFormatState extends State<NumberFieldFormat> {
  double? _price = 1240;
  double? _share = 0.15;

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 300),
      child: Column(
        mainAxisSize: MainAxisSize.min,
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 20,
        children: <Widget>[
          MPNumberField(
            label: const Text('Price'),
            value: _price,
            onChanged: (double? next) => setState(() => _price = next),
            format: _currency,
            step: 10,
            min: 0,
            fullWidth: true,
          ),
          MPNumberField(
            label: const Text('Commission'),
            value: _share,
            onChanged: (double? next) => setState(() => _share = next),
            format: _percent,
            parse: _readPercent,
            step: 0.01,
            min: 0,
            max: 1,
            fullWidth: true,
          ),
          MPTypography(
            'The values behind those are $_price and $_share.',
            level: MPTypographyLevel.caption,
          ),
        ],
      ),
    );
  }
}

That separation is the whole reason this is a parameter rather than something a caller does to value on the way in: formatting on the way in means parsing on the way out, and the parsing is the part that is hard.

steppers ​

Three arrangements, and no fourth.

ReactFlutter
tsx
import { useState } from 'react';
import { MPNumberField } from 'material-plus-ui';
import type { MPNumberFieldSteppers } from 'material-plus-ui';

/**
 * Three arrangements, and no fourth.
 *
 * There is deliberately no stacked pair of half-height chevrons — the shape a
 * native `<input type="number">` grows. At `xs` each arrow would be under three
 * pixels tall, and a target that small is a target nobody hits.
 */
const LAYOUTS: { steppers: MPNumberFieldSteppers; note: string }[] = [
  { steppers: 'end', note: 'both at the trailing edge — the default' },
  { steppers: 'split', note: 'one either side, for a quantity that is nudged' },
  { steppers: 'none', note: 'no buttons; the arrow keys and clamping stay' }
];

export default function NumberFieldSteppers() {
  const [values, setValues] = useState<Record<string, number | null>>({});

  return (
    <div style={{ display: 'grid', gap: 20, maxWidth: 300 }}>
      {LAYOUTS.map(({ steppers, note }) => (
        <div key={steppers} style={{ display: 'grid', gap: 6 }}>
          <small className="text-mp-on-surface-variant">
            <code>steppers=&quot;{steppers}&quot;</code> — {note}
          </small>
          <MPNumberField
            label="Quantity"
            steppers={steppers}
            min={0}
            max={99}
            value={values[steppers] ?? 1}
            onValueChange={(next) => setValues((all) => ({ ...all, [steppers]: next }))}
            fullWidth
          />
        </div>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// Three arrangements, and no fourth.
///
/// There is deliberately no stacked pair of half-height chevrons, the shape a
/// native number input grows. At `xs` each arrow would be under three pixels
/// tall, and a target that small is a target nobody hits.
const List<(MPNumberFieldSteppers, String)> _layouts = <(MPNumberFieldSteppers, String)>[
  (MPNumberFieldSteppers.end, 'both at the trailing edge — the default'),
  (MPNumberFieldSteppers.split, 'one either side, for a quantity that is nudged'),
  (MPNumberFieldSteppers.none, 'no buttons; the arrow keys and clamping stay'),
];

class NumberFieldSteppers extends StatefulWidget {
  const NumberFieldSteppers({super.key});

  @override
  State<NumberFieldSteppers> createState() => _NumberFieldSteppersState();
}

class _NumberFieldSteppersState extends State<NumberFieldSteppers> {
  final Map<MPNumberFieldSteppers, double?> _values = <MPNumberFieldSteppers, double?>{};

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 300),
      child: Column(
        mainAxisSize: MainAxisSize.min,
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 20,
        children: <Widget>[
          for (final (MPNumberFieldSteppers steppers, String note) in _layouts)
            Column(
              mainAxisSize: MainAxisSize.min,
              crossAxisAlignment: CrossAxisAlignment.stretch,
              spacing: 6,
              children: <Widget>[
                MPTypography(
                  'steppers: MPNumberFieldSteppers.${steppers.name} — $note',
                  level: MPTypographyLevel.caption,
                ),
                MPNumberField(
                  label: const Text('Quantity'),
                  steppers: steppers,
                  min: 0,
                  max: 99,
                  value: _values.containsKey(steppers) ? _values[steppers] : 1,
                  onChanged: (double? next) => setState(() => _values[steppers] = next),
                  fullWidth: true,
                ),
              ],
            ),
        ],
      ),
    );
  }
}

There is deliberately no stacked pair of half-height chevrons — the shape a native number input grows. At xs each arrow would be under three pixels tall, and a target that small is a target nobody hits.

A stepper that has run into min or max is disabled rather than merely inert, so a reader can see there is nowhere left to go before they press it. readOnly drops both buttons entirely: leaving them there disabled is two ways of saying the same thing, and the disabled one looks broken. A held stepper repeats after a short pause.

floatingLabel ​

While the field holds no number and is unfocused, the label rests on the field's own line and rises into the notch on focus or on the first digit. See MPTextField for the rule in full.

steppers="split" pins it in the notch, for the same reason a startIcon does: the minus sits exactly where a resting label would.

steppers: MPNumberFieldSteppers.split pins it in the notch, for the same reason a startIcon does: the minus sits exactly where a resting label would.

step, largeStep and smallStep ​

step is one arrow key. Shift takes largeStep (10 by default) and Alt takes smallStep (0.1), which is Base UI's own convention and matches what a spreadsheet does. Page Up and Page Down take largeStep too, and Home and End go to min and max when the range has them.

tsx
<MPNumberField label="Opacity" step={0.05} smallStep={0.01} min={0} max={1} />
dart
MPNumberField(label: const Text('Opacity'), step: 0.05, smallStep: 0.01, min: 0, max: 1)

onValueCommitted ​

onValueChange fires on every change — every keystroke, every step, every notch of the wheel. onValueCommitted fires once the value settles: on blur after typing, on pointer release after a press, and together with onValueChange for the keyboard.

onChanged fires on every change — every keystroke, every step, every notch of the wheel. onValueCommitted fires once the value settles: on blur or Enter after typing, on pointer release after a press, and together with onChanged for the keyboard.

Use the first to keep a form in sync and the second for anything expensive.

Accessibility ​

  • The label sits in the outline's notch and is wired to the input by id, exactly as on a text field.
  • Both steppers are real buttons with names — incrementLabel and decrementLabel, which are English by default and are meant to be replaced in a localised application.
  • allowWheelScrub is off by default. A page that scrolls under the pointer and a field that changes under it are the same gesture, and only one of them was meant.
  • The field is one text field node for a screen reader, named by its label, exactly as a text field is.
  • Both steppers are buttons with names — incrementLabel and decrementLabel, which default to the words in locale. They are not Tab stops: the arrow keys that step the number belong to the field, so a stop on each stepper is two more presses on the way past it.
  • allowWheelScrub is off by default. A page that scrolls under the pointer and a field that changes under it are the same gesture, and only one of them was meant.

Differences from the React build ​

Most of this page is the same in both packages. These are the places where it is not, and why.

ReactFlutterWhy
onValueChangeonChangedFlutter's name for a plain change. onValueCommitted keeps its name.
defaultValueinitialValueFlutter's name. Left out, value is a marker that is not a number, which is what makes the field uncontrolled; value: null is a controlled empty field.
format (Intl.NumberFormatOptions)format and parse (functions)The Dart SDK has no Intl.NumberFormat and this package has no dependencies, so the writing and the reading are yours.
locale (Intl.LocalesArgument)locale (String?)It names the steppers' language only. How the number is written is format's.
onKeyDown, onKeyUponKeyEventOne callback, returning a KeyEventResult.
onFocus, onBluronFocusChangeOne callback with a bool. The settle a blur causes still happens.
onClick, onDoubleClick, onContextMenu—Wrap the field in a GestureDetector for the pointer.
id, className, style—There is nothing to pass them through to.
—semanticLabel, focusNode, autofocusA name for a field with no visible label, and the focus from outside.
