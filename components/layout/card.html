MPCard ​

An MPBox with the parts a card is made of laid out on it: a picture, a heading, a subheading, a body and a footer. MD3's own card anatomy, in slots.

ReactFlutter
tsx
import { MPCard, MPButton } from 'material-plus-ui';

<MPCard
  variant="elevated"
  title="Weekly digest"
  subtitle="Sent every Monday at 09:00"
  footer={<MPButton>Send now</MPButton>}
>
  Forty-two people opened the last one.
</MPCard>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPCard(
  variant: MPVariant.elevated,
  title: const Text('Weekly digest'),
  subtitle: const Text('Sent every Monday at 09:00'),
  footer: MPButton(onPressed: send, child: const Text('Send now')),
  child: const Text('Forty-two people opened the last one.'),
);

Every MPBox prop passes straight through, so a card is styled on exactly the same axes as the box it is.

The card takes the box's variant, elevation, size and density itself, so it is styled on the same axes as a box. footer is one widget: a footer with two buttons in it brings its own Wrap or Row, which the card then lays out with the same 8px gap.

Why the sections are props ​

There is no <MPCard.Header> or <MPCard.Title>, and that is the same decision MPDialog makes.

The arrangement of a card is fixed — media, headline, subhead, body, actions, in that order, because that is MD3's own anatomy. What a caller wants to decide is what goes in each slot, not what order the slots come in, and compound sub-components would offer an ordering that has one correct answer.

What they would also offer is a card that is silently missing its heading because somebody forgot to nest one. A slot that is left empty draws nothing at all: no wrapper, no padding, no gap.

The surface is MD3's card ​

corner-medium, and three of the five variants are the specification's own card variants to the letter — filled is surface-container-highest, elevated is surface-container-low under a level-1 shadow, outlined is a hairline in outline-variant.

None of them is dyed, and there is no color. The argument is MPBox's, unchanged: what a card holds is somebody else's content, and it arrived with its own colours.

media ​

ReactFlutter
tsx
import { MPButton, MPCard, MPImage } from 'material-plus-ui';

/**
 * `media` is drawn edge to edge across the top, so the card's own corners crop
 * it.
 *
 * It is a slot of its own rather than part of `children` because it is the one
 * part of a card that must not be padded — and because the sheet only clips when
 * there is something to crop, so a card with no picture keeps its focus rings
 * intact.
 */
export default function CardMedia() {
  return (
    <div style={{ display: 'grid', gap: 12, width: '100%', maxWidth: 320 }}>
      <MPCard
        variant="filled"
        title="Sunrise over the terraces"
        subtitle="05:41, from the top of the ridge"
        media={
          <MPImage
            src="/samples/photos/thumbs/misty-tea-terraces-sunrise.webp"
            alt="Rows of tea terraces in low mist, with the sun just over the hills"
            ratio="16 / 9"
          />
        }
        footer={<MPButton variant="text">Open</MPButton>}
      >
        The picture reaches all four edges of the top. Nothing above it is padded.
      </MPCard>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class CardMedia extends StatelessWidget {
  const CardMedia({super.key});

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 320),
      child: MPCard(
        variant: MPVariant.filled,
        title: const Text('Sunrise over the terraces'),
        subtitle: const Text('05:41, from the top of the ridge'),
        media: const MPImage(
          image: NetworkImage('/samples/photos/thumbs/misty-tea-terraces-sunrise.webp'),
          semanticLabel: 'Rows of tea terraces in low mist, with the sun just over the hills',
          ratio: 16 / 9,
        ),
        footer: MPButton(variant: MPVariant.text, onPressed: () {}, child: const Text('Open')),
        child: const Text(
          'The picture reaches all four edges of the top. Nothing above it is padded.',
        ),
      ),
    );
  }
}

Drawn edge to edge across the top, so the card's own corners crop it. It is a slot of its own rather than part of children because it is the one part of a card that must not be padded — and the vertical track the other sections sit in starts below it, so a picture is never framed by the sheet's own padding.

The card only clips when there is media. A clip on every card would shave the focus ring off a control sitting against the sheet's edge, for no gain on a card with nothing to crop.

dividers ​

ReactFlutter
tsx
import { MPButton, MPCard } from 'material-plus-ui';

/**
 * Space or rules, which is one prop and two different trades.
 *
 * Without `dividers` the *sheet* carries the vertical padding and the sections
 * are told apart by a gap. With them each section carries both axes, so a
 * hairline can reach the sheet's own edges — the same trade `MPDialog` makes,
 * and the reason to turn it on is the same: the lines are what say the parts are
 * parts.
 */
export default function CardDividers() {
  return (
    <div style={{ display: 'grid', gap: 16, width: '100%', maxWidth: 420 }}>
      <MPCard title="Separated by space" footer={<MPButton variant="text">Act</MPButton>}>
        The default.
      </MPCard>

      <MPCard dividers title="Separated by rules" footer={<MPButton variant="text">Act</MPButton>}>
        The rules reach both edges, because the padding moved off the sheet and onto each section.
      </MPCard>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class CardDividers extends StatelessWidget {
  const CardDividers({super.key});

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 420),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        mainAxisSize: MainAxisSize.min,
        spacing: 16,
        children: <Widget>[
          MPCard(
            title: const Text('Separated by space'),
            footer: MPButton(variant: MPVariant.text, onPressed: () {}, child: const Text('Act')),
            child: const Text('The default.'),
          ),
          MPCard(
            dividers: true,
            title: const Text('Separated by rules'),
            footer: MPButton(variant: MPVariant.text, onPressed: () {}, child: const Text('Act')),
            child: const Text(
              'The rules reach both edges, because the padding moved off the sheet and onto '
              'each section.',
            ),
          ),
        ],
      ),
    );
  }
}

Off by default. Turning it on is a trade, not just a line appearing:

OffOn
Vertical paddingThe sheet carries itEach section carries it
Between sectionsA gapA hairline reaching both edges

The rule is the same outline-variant as the card's own edge, so it reads as the sheet being scored rather than as a second, unrelated line. There is never a rule above the first section — or under the media, which is already the break.

Why a card is not pressable ​

There is no href and no onClick, and in Flutter no onPressed.

MD3 does describe a card as a container that may be interactive, and a whole-card target would be the wrong shape for this card: one with a heading, a body and two buttons in its footer that is also one big link is a link containing links, which the HTML parser takes apart on the way in. Every keyboard reader then meets a control the screen reader cannot describe.

What to do instead:

tsx
// The heading is the link.
<MPCard title={<MPTextLink href="/digests/42">Weekly digest</MPTextLink>}>…</MPCard>

// Or the footer holds the action.
<MPCard title="Weekly digest" footer={<MPButton onClick={open}>Open</MPButton>}>…</MPCard>

A grid of tiles where the whole tile is one target is a different component, and it is a plain MPBox with an <a> inside it — nothing in it competes for the click.

dart
// The footer holds the action.
MPCard(
  title: const Text('Weekly digest'),
  footer: MPButton(onPressed: open, child: const Text('Open')),
  child: const Text('…'),
);

A whole tile that is one target is a different widget: a pressable surface of your own with nothing inside it competing for the press.

Examples ​

title as a heading element / headingLevel ​

A card that should appear in the document outline needs a real heading. Pass one, and it keeps the card's typography rather than the browser's:

tsx
<MPCard title={<h3>Totals</h3>}>…</MPCard>

A plain string is deliberately not made into a heading. A page of cards would then be a page of <h3>s in whatever order they happen to render, which is an outline nobody wrote.

A card that should appear in the screen's outline needs its title announced as a heading. A widget has no tag to say so, so the level is a parameter beside the title, and the typography stays the card's:

dart
MPCard(title: const Text('Totals'), headingLevel: 3, child: body);

Without it the title is deliberately not a heading. A screen of cards would then be a screen of headings in whatever order they happen to build, which is an outline nobody wrote.

headerAction ​

Stays on the title's line while the title wraps beside it:

tsx
<MPCard title="Weekly digest" headerAction={<MPIconButton icon={…} label="More" size="xs" />}>
  …
</MPCard>
dart
MPCard(
  title: const Text('Weekly digest'),
  headerAction: MPIconButton(icon: moreIcon, label: 'More', size: MPSize.xs, onPressed: openMenu),
  child: body,
);

A card with only a body ​

Every slot is optional, and a card with none of them filled is an MPBox — which is exactly what it is:

tsx
<MPCard>Just the sheet.</MPCard>
dart
const MPCard(child: Text('Just the sheet.'));

Accessibility ​

  • A card has no role of its own. It is a <div> with a surface, and it stays that way for the same reason a box does: a region a screen reader should announce needs a name and an element that takes one, which is what render is for.
  • title is not silently a heading. Pass a heading element when the card belongs in the outline.
  • Nothing is pressable, so nothing here can nest one control inside another.
tsx
<MPCard render={<article />} aria-labelledby="digest-title" title={<h3 id="digest-title">…</h3>}>
  …
</MPCard>
  • A card adds no semantics node of its own and takes no focus stop, which is right for a container. Wrap it in a Semantics with a label when it is a region a screen reader should announce.
  • title is not silently a heading. Give it a headingLevel when the card belongs in the outline.
  • Nothing is pressable, so nothing here can nest one control inside another.
