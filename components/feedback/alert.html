MPAlert ​

A message about something that happened, set into the page it is about. One component with different slots filled — a bare line, a line with a glyph, or a glyph with a headline and the detail under it.

ReactFlutter
tsx
import { MPAlert, MPButton } from 'material-plus-ui';

<MPAlert
  color="error"
  title="We could not charge your card"
  action={<MPButton variant="text">Retry</MPButton>}
  onClose={dismiss}
>
  The bank declined the payment. Nothing has been billed.
</MPAlert>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPAlert(
  color: MPColor.error,
  title: const Text('We could not charge your card'),
  action: MPButton(variant: MPVariant.text, onPressed: retry, child: const Text('Retry')),
  onClose: dismiss,
  child: const Text('The bank declined the payment. Nothing has been billed.'),
);

Why this is not a snackbar ​

An alert belongs to the flow of the page it interrupts. A snackbar floats over it and leaves on a timer.

That is not a styling difference, and it is the whole of how to choose between them:

  • A message the reader has to act on must not be able to disappear before it has been read.
  • A message about the page's current state has to still be there when they look back at it.
  • If it can be missed without consequence, it is a snackbar.

An alert is also the only one of the two a reader can arrive at. A snackbar raised before the page was open is a snackbar nobody saw.

Why the default variant is tonal ​

Every other component in this library defaults to the loudest sensible surface, and a button defaults to filled. An alert does not.

A container tone is MD3's own answer for a message set into a page: it separates itself from the surface without competing with the primary action that is usually sitting right beside it. A page with three saturated alerts on it has no emphasis left to spend on the thing it actually wants pressed.

ReactFlutter
tsx
import { MPAlert } from 'material-plus-ui';
import type { MPVariant } from 'material-plus-ui';

/**
 * The five surfaces, in the order they get quieter.
 *
 * An alert takes the accent onto its *own* surface rather than staying neutral,
 * which is the whole difference between it and a card: a card is a box holding
 * somebody else's content, and an alert is the message.
 *
 * `tonal` is the default here rather than `filled` — a container tone separates
 * itself from the page without competing with the primary action usually sitting
 * beside it.
 */
const VARIANTS: { variant: MPVariant; note: string }[] = [
  { variant: 'filled', note: 'the loudest — one per screen at most' },
  { variant: 'tonal', note: 'the default: MD3’s answer for a message in a page' },
  { variant: 'elevated', note: 'neutral, separated by a shadow instead of colour' },
  { variant: 'outlined', note: 'a hairline and the accent on the glyph' },
  { variant: 'text', note: 'no surface at all — for a form that is already busy' }
];

export default function AlertVariants() {
  return (
    <div style={{ display: 'grid', gap: 12, width: '100%' }}>
      {VARIANTS.map(({ variant, note }) => (
        <MPAlert key={variant} variant={variant} title={variant}>
          {note}
        </MPAlert>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// The five surfaces, in the order they get quieter.
///
/// An alert takes the accent onto its *own* surface rather than staying neutral,
/// which is the whole difference between it and a card: a card is a box holding
/// somebody else's content, and an alert is the message.
///
/// `tonal` is the default here rather than `filled`: a container tone separates
/// itself from the page without competing with the primary action usually
/// sitting beside it.
class AlertVariants extends StatelessWidget {
  const AlertVariants({super.key});

  static const List<(MPVariant, String)> _variants = <(MPVariant, String)>[
    (MPVariant.filled, 'the loudest — one per screen at most'),
    (MPVariant.tonal, 'the default: MD3’s answer for a message in a page'),
    (MPVariant.elevated, 'neutral, separated by a shadow instead of colour'),
    (MPVariant.outlined, 'a hairline and the accent on the glyph'),
    (MPVariant.text, 'no surface at all — for a form that is already busy'),
  ];

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      spacing: 12,
      children: <Widget>[
        for (final (MPVariant variant, String note) in _variants)
          MPAlert(variant: variant, title: Text(variant.name), child: Text(note)),
      ],
    );
  }
}

Note what changes between them. On filled and tonal the container is the accent, so the glyph and the heading ride on it as one ink. On the three neutral surfaces the accent has nowhere else to go, so it is spent on exactly the two things that say which kind of alert this is — and the message stays ordinary reading text.

Four families, not a severity ladder ​

There is no info, success or warning.

The specification's colour system does not have them, and the token sheet has no way to derive them — offering three more families would be promising roles the theme cannot produce, and an application that themed primary would find its "success" alerts unchanged.

What there is instead: error, which is the one severity Material does name, and an emphasis choice for everything else. A message that means something the palette has no word for says so with a glyph rather than by borrowing a colour.

ReactFlutter
tsx
import { MPAlert, MPIcon, ICONS } from 'material-plus-ui';

/**
 * Four families, not a severity ladder.
 *
 * There is no `success` or `warning` here, because the specification's colour
 * system has no way to derive them — offering them would promise roles the token
 * sheet cannot produce. What you get instead is `error`, which Material does
 * name, and an emphasis choice for everything else.
 *
 * A message that means something the palette has no word for says so with a
 * glyph of its own rather than by borrowing a colour, which is what the last two
 * rows do.
 */
export default function AlertColors() {
  return (
    <div style={{ display: 'grid', gap: 12, width: '100%' }}>
      <MPAlert color="primary">A notice: the default, and the informational one.</MPAlert>
      <MPAlert color="error">
        Something failed. This is the one family the specification names.
      </MPAlert>
      <MPAlert color="tertiary" icon={<MPIcon icon={ICONS.success} size={20} />}>
        “It worked” — a family for emphasis, and a glyph for the meaning.
      </MPAlert>
      <MPAlert color="secondary" icon={<MPIcon icon={ICONS.warning} size={20} />}>
        “Proceed carefully” — the same trade, one step quieter.
      </MPAlert>
    </div>
  );
}

import 'package:material_plus_ui/material_plus_ui.dart';

import 'package:material_plus_ui_example/demos/glyphs_feedback.dart';

/// Four families, not a severity ladder.
///
/// There is no `success` or `warning` here, because the specification's colour
/// system has no way to derive them: offering them would promise roles the
/// theme cannot produce. What you get instead is `error`, which Material does
/// name, and an emphasis choice for everything else.
///
/// A message that means something the palette has no word for says so with a
/// glyph of its own rather than by borrowing a colour, which is what the last
/// two rows do.
class AlertColors extends StatelessWidget {
  const AlertColors({super.key});

  @override
  Widget build(BuildContext context) {
    return const Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      spacing: 12,
      children: <Widget>[
        MPAlert(
          color: MPColor.primary,
          child: Text('A notice: the default, and the informational one.'),
        ),
        MPAlert(
          color: MPColor.error,
          child: Text('Something failed. This is the one family the specification names.'),
        ),
        MPAlert(
          color: MPColor.tertiary,
          icon: MPIcon(icon: DoneGlyph(), size: 20),
          child: Text('“It worked” — a family for emphasis, and a glyph for the meaning.'),
        ),
        MPAlert(
          color: MPColor.secondary,
          icon: MPIcon(icon: CautionGlyph(), size: 20),
          child: Text('“Proceed carefully” — the same trade, one step quieter.'),
        ),
      ],
    );
  }
}

Which live region it lands in ​

The family decides by default, because it is the only thing that knows how urgent the message is:

colorliveWhat that does
errorassertiveInterrupts whatever a screen reader is in the middle of
primary, secondary, tertiarypoliteWaits for a pause

"This failed" is worth interrupting for and "Saved" is not.

live overrides it, and the value worth knowing about is the third one. A live region is for content that arrives. An alert that was in the markup when the page loaded did not arrive — it is part of the page, and interrupting to read it is interrupting to say something the reader was going to reach anyway:

tsx
// An error summary the server rendered. Still an alert on the screen; not an
// announcement.
<MPAlert color="error" live="off">
  Three fields need attention.
</MPAlert>
dart
// An error summary that was on the screen when it was built. Still an alert;
// not an announcement.
const MPAlert(
  color: MPColor.error,
  live: MPAlertLive.off,
  child: Text('Three fields need attention.'),
);

And the other way, for a message that is quiet by family and urgent in fact:

tsx
<MPAlert live="assertive">Your session ends in one minute.</MPAlert>
dart
const MPAlert(live: MPAlertLive.assertive, child: Text('Your session ends in one minute.'));

Flutter's live region has one politeness level, and it is polite. So off the web an assertive alert is announced at the next pause, as a polite one is. On the web the engine also reads a node's role, and there an assertive alert is role="alert", as the React build's is. MPAlertLive.off is no live region on either.

Examples ​

title ​

With a heading the alert is two-part; without one the whole thing is a single line. Under a heading the message steps back to on-surface-variant, the same role a field's supporting text takes — on its own it is the alert, and stays reading text.

tsx
<MPAlert>One line.</MPAlert>

<MPAlert title="Two parts">And the detail under it.</MPAlert>
dart
const MPAlert(child: Text('One line.'));

const MPAlert(title: Text('Two parts'), child: Text('And the detail under it.'));

icon ​

Defaults to the glyph that goes with color. Only two defaults exist because only two are honest: the error family gets the error glyph and everything else gets the informational one.

tsx
<MPAlert icon={false}>No glyph at all.</MPAlert>

<MPAlert icon={<MPIcon icon={ICONS.success} size={20} />}>Something more specific.</MPAlert>
dart
const MPAlert(showIcon: false, child: Text('No glyph at all.'));

MPAlert(icon: MPIcon(icon: mySet.success, size: 20), child: const Text('Something more specific.'));

Dart has no value that is neither null nor a widget, so "take it away" is showIcon: false rather than a third value of icon.

The glyph is centred on the first line of text rather than on the whole message, so a one-line alert looks centred and a three-line one still has its glyph at the top.

action and onClose ​

action is kept out of children so it stays on the first line while the message wraps. onClose is what makes the × appear at all — there is no dismissible boolean, because a dismiss button with nothing to call is a button that does nothing.

tsx
<MPAlert action={<MPButton variant="text">Retry</MPButton>} onClose={() => setShown(false)}>
  Upload failed.
</MPAlert>
dart
MPAlert(
  action: MPButton(variant: MPVariant.text, onPressed: retry, child: const Text('Retry')),
  onClose: () => setState(() => shown = false),
  child: const Text('Upload failed.'),
);

onClose fires once the alert has finished leaving, not on the press. The alert sits in the flow of the page, so the press folds its height away first and everything under it closes the gap; onClose is the moment to stop rendering it. With reduced motion, or MediaQuery.disableAnimations in Flutter, it fires at once.

locale ​

The × has no text of its own, so its accessible name is a word this library has to invent. It comes from locale, or from the nearest MPLocaleProvider, or from closeLabel when neither is right.

tsx
<MPAlert locale="ko" onClose={dismiss}>
  저장했습니다.
</MPAlert>
dart
MPAlert(locale: 'ko', onClose: dismiss, child: const Text('저장했습니다.'));

Accessibility ​

  • The whole alert is a live region, so a message that appears after the page has loaded is announced. See the table above for which kind.
  • The × is a real button with a name, and it is the last thing in the row rather than the first, so a reader hears the message before the way out of it.
  • The default glyph is decorative and hidden from the accessibility tree — the family it stands for is already in the words.
  • The alert is one semantics node and, unless live is MPAlertLive.off, a live region, so a message that appears after the screen is built is announced.
  • The × is a button node of its own with a name, after the message, so a reader hears the message before the way out of it. Tab reaches it and Enter or Space presses it. The focus ring is secondary, drawn outside it, on keyboard focus only.
  • From the press until it is gone, the alert is out of the semantics tree, the focus order and the pointer's reach, so nothing can walk into an alert that is leaving.
  • The default glyph says nothing to a screen reader: the family it stands for is already in the words.
