색상 ​

Material Plus는 하나의 소스 색상에서 스킴 전체를 생성합니다. Material Design이 하는 방식 그대로입니다. 그것만 지정하면 모든 롤이 따라오고, 결과가 마음에 들지 않는 롤만 따로 지정합니다.

css
:root {
  --mp-source-color: #7c3aed;
}

provider도 테마 객체도 없습니다. 컴포넌트가 그리는 모든 색이 CSS 커스텀 프로퍼티이므로 테마 설정이 곧 CSS입니다. 그리고 그것이 이미 자체 머터리얼 토큰을 가진 프로젝트 안에 들어갈 수 있게 하는 부분입니다.

팔레트 ​

브라우저가 실제로 계산한 값을 읽어온 것이고, 두 스킴을 동시에 보여줍니다. 페이지는 언제나 한쪽 스킴에만 있으므로 각 스와치가 어느 쪽에서 측정된 것인지 표시합니다.

50개가 아니라 5개 ​

머터리얼은 색상 롤을 약 50개 정의합니다. outlined text field가 읽는 것은 그중 5개이고, 여기 있는 것도 그 5개뿐입니다.

의도적이고, 토큰 전체가 따르는 같은 규칙입니다 — 아무도 읽지 않는 토큰은 그 이름을 계속 지원하겠다는 약속입니다. 롤은 필요한 컴포넌트가 생길 때 도착합니다. Button이 on-primary와 primary-container를 데려올 것이고, Card가 surface-container 단계들을 데려올 것입니다. 그때까지는 없는 것이 정직합니다.

이것이 이 라이브러리가 머터리얼을 완전히 재현하려 하지 않는 이유이기도 합니다. 페이지가 이미 돌리고 있는 머터리얼 구현을 대체하는 게 아니라 공존해야 하므로, 주장하는 표면은 컴포넌트가 필요로 하는 만큼만 유지합니다.

롤이 파생되는 방식 ​

각 롤은 소스 색상의 명도와 채도를 바꾼 것이고, CSS 상대 색상 문법을 씁니다.

css
oklch(from var(--mp-source-color) var(--tone) var(--chroma) h)

끝의 h는 소스 자신의 hue를 그대로 유지한다는 뜻입니다. 즉 롤은 씨앗과 같은 색 계열을 다른 톤에서 본 것이고, 그것이 바로 머터리얼 톤 팔레트입니다.

라이트와 다크는 하나의 팔레트를 두 번 읽은 것 ​

머터리얼의 두 스킴은 서로 다른 두 색 집합이 아닙니다. 같은 톤 팔레트를 다른 톤에서 읽은 것입니다 — 라이트 primary는 톤 40, 다크 primary는 톤 80입니다.

여기서도 그렇게 동작하므로, 다크 스킴은 모든 값을 다시 쓴 두 번째 사본이 아니라 톤 번호의 재배정입니다. 소스 색상을 바꾸면 두 스킴이 함께 움직이고, 따로 동기화할 것이 없습니다.

숫자의 출처 ​

톤과 채도 값은 눈대중이 아니라 머터리얼 자신의 baseline 레퍼런스 팔레트를 OKLCh로 변환해 읽어온 것입니다. 스펙의 baseline 소스 색상을 넣으면 파생 결과가 스펙의 baseline 스킴에 도달합니다.

primaryon-surfaceon-surface-variantoutlineerror
라이트 ΔE0.00000.00260.00410.00380.0000
다크 ΔE0.00720.00460.00470.00360.0000

primary와 error는 두 스킴 모두 레퍼런스 hex와 정확히 일치하고, 중성 롤은 전부 0.02(차이가 보이지 않는 임계값) 아래입니다.

알려진 차이 하나는 인정하고 갑니다. 모든 파생 롤이 소스 색상의 hue를 유지하는데, 머터리얼의 중성 팔레트는 거기서 1020° 떨어져 있습니다. 채도 0.010.02에서 그것은 a/b 기준 수천분의 몇 차이이고 — 지각 한계 아래이며, 회색에 그만큼 가까우면 hue 자체가 거의 결정되지 않으므로 이를 쫓는 것은 노이즈에 맞추는 일이 됩니다.

error는 여러분의 색에서 파생되지 않습니다 ​

머터리얼의 error 팔레트는 씨앗이 무엇이든 고정된 빨강이고, 여기서도 그렇습니다. 브랜드에 따라 hue가 움직이는 오류색은 오류로 읽히지 않게 됩니다.

기본값 ​

기본 소스 색상은 깊은 azure, #00639b입니다.

머터리얼 자신의 baseline은 #6750a4인데, 라이브러리가 그것을 기본값으로 두는 것은 보기보다 큰 주장입니다. 보라는 누구도 우연히 도달하지 않는 유일한 hue라서, 아직 색을 정하지 않은 애플리케이션이 그 색을 고른 것처럼 보이게 됩니다.

azure는 hue만큼이나 채도 때문에 선택했습니다 — 0.118로 baseline의 0.130에 가깝고, 모든 롤이 채도를 거기서 가져가기 때문입니다. 더 선명한 파랑(구글의 #0b57d0은 0.199)은 스킴 전체를 어떤 레퍼런스 머터리얼 팔레트보다 밝게 끌어올려, 머터리얼이 아니라 브랜드로 읽히게 됩니다.

소스 색상은 회색에 가까우면 안 됩니다

채도가 대략 0.05 아래로 내려가면 파생된 primary가 outline과 구분되지 않고, 포커스 링이 아무 변화도 아닌 것으로 읽힙니다. #4a5c6a 같은 슬레이트는 그럴듯한 중성 브랜드 색으로 보이지만 씨앗으로는 쓸 수 없습니다.

바꾸기 ​

소스 색상 ​

@theme 안이 아니라 평범한 :root에 한 줄입니다. 라이브러리 기본값은 cascade layer 안에 선언되어 있고 레이어에 든 규칙은 레이어에 들지 않은 모든 규칙에 지므로, 여러분의 override는 @import 앞에 있든 뒤에 있든 이기고 순서를 신경 쓸 필요가 없습니다.

css
@import 'material-plus-ui/styles.css';

:root {
  --mp-source-color: #7c3aed;
}

롤 하나 ​

css
:root {
  --mp-sys-color-outline: #d0d0d8;
}

일부 토큰 시스템과 달리 여기서 롤 하나를 덮는 것은 나머지 열한 개를 낡은 값으로 남기지 않습니다. 롤들은 서로에게서 파생된 트리가 아니라 씨앗에서 파생된 형제이기 때문입니다. outline을 지정하면 outline만 바뀝니다.

tsx
import { MPTextField } from 'material-plus-ui';
import { DEFAULT_LOCALE, type Locale } from '../../data/i18n';

/**
 * The three levels of control, side by side and all resolved live.
 *
 * Each panel is the same markup with one attribute's worth of difference, which
 * is the point: none of them is a provider, a theme object or a re-render.
 */
const CAPTIONS = {
  derived: {
    ko: '아무것도 지정하지 않음 — 기본 소스 색상에서 파생',
    en: 'Nothing set — derived from the default source colour'
  },
  source: {
    ko: '--mp-source-color 만 지정 — 모든 롤이 따라옴',
    en: 'Only --mp-source-color — every role follows'
  },
  role: {
    ko: '--mp-sys-color-primary 만 지정 — 그 롤만 바뀜',
    en: 'Only --mp-sys-color-primary — that one role changes'
  }
} as const;

function Panel({ caption, style }: { caption: string; style?: React.CSSProperties }) {
  return (
    <div style={{ display: 'grid', gap: 8, ...style }}>
      <small className="text-mp-on-surface-variant">
        <code>{caption}</code>
      </small>
      {/* Focused-looking without needing focus: the ring and label take
          `primary`, which is the role all three panels differ in. */}
      <div
        style={{
          border: '2px solid var(--color-mp-primary)',
          borderRadius: 'var(--mp-sys-shape-corner-extra-small)',
          padding: '14px 16px',
          color: 'var(--color-mp-primary)',
          fontSize: 14
        }}
      >
        primary
      </div>
      <MPTextField label="At rest" value="hello@example.com" fullWidth />
    </div>
  );
}

export default function ColorOverride({ locale = DEFAULT_LOCALE }: { locale?: Locale }) {
  return (
    <div style={{ display: 'grid', gap: 20, gridTemplateColumns: 'repeat(3, minmax(0, 1fr))' }}>
      <Panel caption={CAPTIONS.derived[locale]} />
      <Panel
        caption={CAPTIONS.source[locale]}
        style={{ '--mp-source-color': '#8f4c38' } as React.CSSProperties}
      />
      <Panel
        caption={CAPTIONS.role[locale]}
        style={{ '--mp-sys-color-primary': '#00696d' } as React.CSSProperties}
      />
    </div>
  );
}

루트만이 아니라 어디에나 ​

모든 토큰은 평범한 상속되는 커스텀 프로퍼티이고, 파생 롤은 :root가 아니라 *에 선언되어 있어서 각 엘리먼트가 자기 자리의 스코프로 다시 해석합니다.

html
<section style="--mp-source-color: #00696d">…</section>

그것이 스코프 override가 애초에 동작하는 이유입니다. var()는 그 프로퍼티를 선언한 엘리먼트에서 치환되므로, :root에 한 번 선언된 롤은 거기서 확정됩니다 — 트리 아래에서 지정한 소스 색상이 조상의 값을 되돌릴 수 없고, <html>이 아니라 <body>에 붙은 .dark도 마찬가지입니다.

사용자가 런타임에 고른 색도 같은 메커니즘이고, 리렌더도 테마 재생성도 없습니다.

tsx
<div style={{ '--mp-source-color': userColour } as React.CSSProperties}>
  <MPTextField … />
</div>

값에 대한 주의사항 하나

파생에 상대 색상 문법을 쓰므로 소스는 완전한 색상이어야 합니다. #7c3aed, oklch(0.49 0.24 292), rgb(124 58 237) 같은 것들입니다. 채널만 담은 디자인 토큰은 감싸야 합니다 — var(--brand)가 아니라 hsl(var(--brand))입니다.

롤 값을 읽어 쓰기 ​

직접 만든 마크업에 이 색을 쓰려면 Tailwind 쪽 이름을 읽거나, Tailwind를 쓴다면 유틸리티를 씁니다.

css
.my-hint {
  color: var(--color-mp-on-surface-variant);
}
html
<p class="text-mp-on-surface-variant">…</p>

비대칭에 주의하세요. 쓸 때는 --mp-sys-color-*, 읽을 때는 --color-mp-*입니다. 쓰는 쪽 이름은 기본적으로 비어 있는 override 슬롯이라 읽어도 아무것도 나오지 않고, 읽는 쪽 이름에 계산된 값이 담깁니다.

이미 있는 머터리얼 환경과의 공존 ​

Material Web을 쓰는 프로젝트에는 이미 페이지에 --md-sys-color-*가 있습니다. Material Plus는 그것을 읽기만 하고 절대 쓰지 않으므로, 설정 없이 기존 스킴을 따르고 자기가 소유하지 않은 테마를 덮어쓸 수 없습니다.

지정한 것결과
--mp-sys-color-primary무조건 승리
--md-sys-color-primary가 이미 있음그 값을 그대로 사용
둘 다 없음--mp-source-color에서 파생

섞어 쓰는 것이 정상입니다. 가지고 있는 롤은 고정하고 나머지는 파생시키면 됩니다.

tsx
import { MPTextField } from 'material-plus-ui';
import { DEFAULT_LOCALE, type Locale } from '../../data/i18n';

/**
 * What happens when the page already defines Material's own tokens.
 *
 * The right-hand panel sets `--md-sys-color-primary` and `--md-sys-color-outline`
 * the way a project running Material Web already would, and sets a source colour
 * as well. The two pinned roles are taken as given; everything else keeps
 * deriving. That mix is the normal case, not a special one.
 */
const CAPTIONS = {
  plain: { ko: '페이지에 MD3 토큰이 없음', en: 'No MD3 tokens on the page' },
  coexist: {
    ko: '--md-sys-color-primary·outline 이 이미 있음',
    en: '--md-sys-color-primary and outline already present'
  }
} as const;

function Panel({ caption, style }: { caption: string; style?: React.CSSProperties }) {
  return (
    <div style={{ display: 'grid', gap: 10, ...style }}>
      <small className="text-mp-on-surface-variant">
        <code>{caption}</code>
      </small>
      <div style={{ display: 'flex', gap: 8 }}>
        {(['primary', 'outline', 'on-surface-variant', 'error'] as const).map((role) => (
          <span
            key={role}
            title={role}
            style={{
              flex: 1,
              height: 34,
              borderRadius: 6,
              background: `var(--color-mp-${role})`,
              outline: '1px solid var(--vp-c-divider)',
              outlineOffset: -1
            }}
          />
        ))}
      </div>
      <MPTextField label="At rest" value="hello@example.com" fullWidth />
    </div>
  );
}

export default function ColorCoexist({ locale = DEFAULT_LOCALE }: { locale?: Locale }) {
  return (
    <div style={{ display: 'grid', gap: 20, gridTemplateColumns: 'repeat(2, minmax(0, 1fr))' }}>
      <Panel
        caption={CAPTIONS.plain[locale]}
        style={{ '--mp-source-color': '#00696d' } as React.CSSProperties}
      />
      <Panel
        caption={CAPTIONS.coexist[locale]}
        style={
          {
            '--mp-source-color': '#00696d',
            '--md-sys-color-primary': '#b3261e',
            '--md-sys-color-outline': '#79747e'
          } as React.CSSProperties
        }
      />
    </div>
  );
}

다크 모드 ​

설정할 것이 없습니다 — prefers-color-scheme을 스스로 따릅니다. 직접 제어하려면 아무 엘리먼트에나 속성이나 클래스를 붙입니다.

html
<html data-mp-scheme="dark">
  <!-- … -->
</html>

Tailwind의 dark: 변형이 기준으로 삼는 .dark도 동작합니다. [data-mp-scheme='light']는 시스템 설정이 다크인 페이지 안에서도 해당 서브트리를 라이트로 되돌립니다.
