MPSnackbar ​

이미 일어난 일에 대한 짧은 메시지이고, 애플리케이션 어디에서든 띄울 수 있습니다. 트리를 MPSnackbarProvider로 한 번 감싸면, 이후 모든 호출 지점은 무슨 일이 있었는지를 말하는 한 줄이 됩니다.

ReactFlutter
tsx
import { MPSnackbarProvider, useMPSnackbar } from 'material-plus-ui';

// 애플리케이션 바깥에서 한 번
<MPSnackbarProvider>
  <App />
</MPSnackbarProvider>;

// 그 아래 어디에서든
const snackbar = useMPSnackbar();

snackbar.add({ message: '메시지를 보관했습니다', actionLabel: '실행 취소', onAction: restore });
dart
import 'package:material_plus_ui/material_plus_ui.dart';

// 앱 안에서 한 번
WidgetsApp(
  // …
  builder: (BuildContext context, Widget? child) => MPSnackbarProvider(child: child!),
);

// 그 아래 어디에서든
MPSnackbarProvider.of(context).add(
  MPSnackbarOptions(
    message: const Text('메시지를 보관했습니다'),
    actionLabel: const Text('실행 취소'),
    onAction: restore,
  ),
);

provider는 앱 바깥이 아니라 앱 안에 둡니다. 앱 바깥에는 아직 Directionality가 없기 때문입니다. 스택은 provider가 감싼 것 위에 그려지므로 Overlay가 필요 없습니다. builder 안에 두면 navigator 위에 놓이고, navigator가 여는 모든 페이지와 대화상자가 스택 아래에 들어갑니다.

왜 이름이 Toast가 아닌가 ​

머터리얼에는 이 컴포넌트의 이름이 있고, 그 이름은 snackbar입니다. "Toast"는 안드로이드의 더 오래된 알림으로, 액션이 없고 닫을 수 없으며 Material Design 3에 들어 있지 않습니다. 그래서 여기서 Toast라는 이름을 쓰면, 명세가 여전히 제공하는 컴포넌트의 이름을 다른 컴포넌트가 빌려 입는 셈이 됩니다.

컴포넌트가 아니라 hook ​

메시지가 필요해진 순간 호출자 손에 있는 것은 트리 안의 자리가 아니라 클릭 핸들러입니다. 계속 마운트해 두고 메시지마다 상태를 하나씩 두어야 하는 <MPSnackbar open={…}/>가 바로 이 컴포넌트가 피하려는 모양입니다.

위젯이 아니라 컨트롤러 ​

메시지가 필요해진 순간 호출자 손에 있는 것은 트리 안의 자리가 아니라 콜백입니다. 계속 마운트해 두고 메시지마다 상태를 하나씩 두어야 하는 MPSnackbar(open: …)가 바로 이 컴포넌트가 피하려는 모양입니다.

MPSnackbarProvider.of(context)는 MPSnackbarController를 돌려줍니다. Navigator.of와 같은 방식의 조회입니다. context 위에 provider가 없으면 assert로 멈추고, MPSnackbarProvider.maybeOf는 그 대신 null을 돌려줍니다.

예시 ​

message ​

제목과 본문이 아니라 한 칸입니다. MD3의 스낵바에는 보조 텍스트 한 줄(최대 두 줄)만 있습니다. 제목이 필요한 메시지는 스낵바가 아니라, 아직 보여주지 않은 대화상자입니다.

actionLabel과 onAction ​

액션은 많아야 하나입니다. 이름만 다를 뿐 text 버튼이고, primary가 아니라 inverse-primary를 씁니다. 그 토큰이 있는 이유가 이것입니다. primary는 페이지와 대비되도록 만든 색이라, 페이지를 뒤집은 판 위에서는 오히려 읽히지 않습니다.

tsx
snackbar.add({ message: '메시지를 보관했습니다', actionLabel: '실행 취소', onAction: restore });
dart
snackbar.add(
  MPSnackbarOptions(
    message: const Text('메시지를 보관했습니다'),
    actionLabel: const Text('실행 취소'),
    onAction: restore,
  ),
);

액션을 눌러도 스낵바는 닫히지 않습니다. 닫고 싶다면 액션이 id로 직접 닫습니다.

timeout ​

0 / Duration.zero이면 닫힐 때까지 남습니다. 사용자가 행동해야 하는 메시지에는 그쪽이 맞습니다. 읽히기 전에 사라지는 스낵바는 아무 말도 하지 않은 셈입니다.

포인터가 스낵바 위에 머무는 동안, 키보드 포커스가 액션이나 ×에 있는 동안, 애플리케이션이 백그라운드에 있거나 창이 포커스를 잃은 동안에는 시계가 멈춥니다. 다시 움직일 때는 멈춘 자리에서 이어갑니다.

id ​

같은 id를 다시 쓰면 그 스낵바를 제자리에서 갱신하고 타이머를 다시 시작합니다. "업로드 중… / 업로드됨"에 필요한 동작이 이것입니다. 둘이 겹쳐 쌓이는 대신, 하나가 내용을 바꿉니다.

position ​

ReactFlutter
tsx
import { useState } from 'react';
import { MPButton, MPSegmentedButton, MPSnackbarProvider, useMPSnackbar } from 'material-plus-ui';
import type { MPSnackbarPosition } from 'material-plus-ui';

const POSITIONS: MPSnackbarPosition[] = ['bottom-start', 'bottom-center', 'top-end'];

function Raise() {
  const snackbar = useMPSnackbar();

  return (
    <MPButton size="sm" onClick={() => snackbar.add({ message: 'Draft saved' })}>
      Raise one
    </MPButton>
  );
}

/**
 * `bottom-start` is MD3's own placement. The stack is remounted here as the
 * position changes, which is what a real application never does — it picks one.
 */
export default function SnackbarPosition() {
  const [position, setPosition] = useState<string[]>(['bottom-start']);
  const current = (position[0] ?? 'bottom-start') as MPSnackbarPosition;

  return (
    <div style={{ display: 'grid', gap: 16, justifyItems: 'start' }}>
      <MPSegmentedButton
        aria-label="Position"
        value={position}
        onValueChange={setPosition}
        items={POSITIONS.map((name) => ({ value: name, label: name }))}
      />
      <MPSnackbarProvider key={current} position={current} timeout={2500}>
        <Raise />
      </MPSnackbarProvider>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

const Map<String, MPSnackbarPosition> _positions = <String, MPSnackbarPosition>{
  'bottom-start': MPSnackbarPosition.bottomStart,
  'bottom-center': MPSnackbarPosition.bottomCenter,
  'top-end': MPSnackbarPosition.topEnd,
};

/// `bottomStart` is MD3's own placement. The stack is built again here as the
/// position changes, which is what a real app never does: it picks one.
class SnackbarPosition extends StatefulWidget {
  const SnackbarPosition({super.key});

  @override
  State<SnackbarPosition> createState() => _SnackbarPositionState();
}

class _SnackbarPositionState extends State<SnackbarPosition> {
  List<String> _position = <String>['bottom-start'];

  @override
  Widget build(BuildContext context) {
    final String current = _position.isEmpty ? 'bottom-start' : _position.first;

    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: <Widget>[
        MPSegmentedButton(
          semanticLabel: 'Position',
          value: _position,
          onChanged: (List<String> next) => setState(() => _position = next),
          items: <MPSegment>[
            for (final String name in _positions.keys) MPSegment(value: name, label: Text(name)),
          ],
        ),
        SizedBox(
          width: double.infinity,
          height: 200,
          child: MPSnackbarProvider(
            key: ValueKey<String>(current),
            position: _positions[current]!,
            timeout: const Duration(milliseconds: 2500),
            child: const Align(alignment: AlignmentDirectional.topStart, child: _Raise()),
          ),
        ),
      ],
    );
  }
}

class _Raise extends StatelessWidget {
  const _Raise();

  @override
  Widget build(BuildContext context) {
    return MPButton(
      size: MPSize.sm,
      onPressed: () =>
          MPSnackbarProvider.of(context).add(const MPSnackbarOptions(message: Text('Draft saved'))),
      child: const Text('Raise one'),
    );
  }
}
bottom-start / MPSnackbarPosition.bottomStart가 MD3의 배치입니다. 두 조각을 한 단어로 쓴 것은 둘이 독립이 아니기 때문입니다. 스낵바 스택은 언제나 위나 아래에 붙고, 옆에는 붙지 않습니다.

이 값은 판이 움직이는 방향도 정합니다. 스낵바는 스택이 붙은 가장자리에서 200ms 동안 들어오고, 같은 쪽으로 나갑니다.

어느 쪽으로 밀어 없앨 수 있는지도 같은 사실에서 정해지고, 둘은 일치해야 합니다. 위에서 내려왔는데 위로만 밀어낼 수 있는 판은 되돌려 달라고 하는 것처럼 보입니다.

움직임을 줄여 달라고 설정한 사용자에게는 이동 없이 페이드만 남습니다.

스낵바는 옆으로 밀어서 없앨 수 있습니다. 움직임을 줄여 달라고 설정한 사용자에게는 페이드도 이동도 없이 바로 나타납니다.

스낵바 하나만 provider가 고른 스택을 벗어날 수 있고, add에 같은 이름의 값을 주면 됩니다.

tsx
snackbar.add({ message: '저장하지 못했습니다', position: 'top-center' });
dart
snackbar.add(
  const MPSnackbarOptions(
    message: Text('저장하지 못했습니다'),
    position: MPSnackbarPosition.topCenter,
  ),
);

아래쪽 구석이 툴바인 페이지의 오류처럼, 무엇인지 때문에 자리가 달라져야 하는 메시지를 위한 값입니다. 취향을 위한 값은 아닙니다. 스낵바가 전부 같은 엉뚱한 자리에 뜬다면 provider를 옮기세요.

여섯 스택은 aria-live 영역 하나를 함께 쓰고, 그 영역은 안이 비어 있어도 첫 렌더부터 페이지에 있습니다. 숨겨 둘 만한 구현 세부가 아닙니다. 안의 메시지와 같은 순간에 문서에 들어온 영역은 스크린 리더가 비교할 대상이 없어 읽지 않습니다. 영역은 창 전체를 덮되 포인터를 모두 통과시키고, 각 모서리의 스택은 그 모서리에 메시지가 생기면 영역 안에 그려집니다. 영역이 여섯이 아니라 하나라서 우선순위가 높은 메시지도 한 번만 읽힙니다.

스택은 판 옆을 누른 입력을 모두 애플리케이션으로 넘기고, 메시지마다 자기 live region을 가집니다(접근성 참고).

기본값이 없습니다. MPTooltip이 같은 이유로 내린 결정과 같습니다. MD3의 스낵바는 inverse-surface 바탕에 inverse-on-surface 글자입니다. 중립 팔레트를 스킴의 반대쪽 끝에서 읽은 색이라, 밝은 페이지에서는 판이 어둡고 어두운 페이지에서는 밝습니다.

값을 주면 그 강조 계열의 container로 바뀝니다. 메시지가 전부 한 종류인 애플리케이션이라면 그럴 만하지만, "이건 오류"라고 말하는 방법으로는 맞지 않습니다. 오류가 있을 자리는 스낵바가 아닙니다.

접근성 ​

  • live region, 타이머와 hover·창 blur에서의 일시정지, limit, 스와이프, 스택으로 포커스를 옮기는 F6 단축키는 Base UI가 맡습니다.
  • priority: 'high'는 스크린 리더를 끊고 low는 쉬는 지점을 기다립니다. 오류는 끊을 만하고 저장 확인은 아닙니다.
  • ×는 스택에 포커스가 오기 전까지 aria-hidden입니다. live region을 듣는 사람이 지나가는 메시지마다 닫기 버튼을 듣지 않게 하려는 것이고, 포인터에게는 여전히 진짜 버튼입니다.
  • live region은 메시지 하나뿐입니다. 스크린 리더는 사용자가 그쪽으로 옮겨 가지 않아도 메시지를 읽고, 지나가는 메시지마다 "닫기"를 덧붙여 읽지 않습니다.
  • 액션과 ×는 따로 떨어진 노드이고, 판 위의 평범한 포커스 정지점입니다. ×의 이름은 closeLabel이거나 locale의 "닫기"입니다.
  • 두 우선순위 모두 사용자가 쉬는 지점에서 읽힙니다. Flutter의 live region에는 공손한 단계 하나뿐이라, React 빌드처럼 high가 말을 끊지는 못합니다.
  • 포인터가 판 위에 머물거나, 손가락이 판을 누르고 있거나, 키보드 포커스가 스택 안에 있거나, 애플리케이션이 전면에서 벗어나면 시계가 멈춥니다.
