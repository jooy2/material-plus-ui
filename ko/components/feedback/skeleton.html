MPSkeleton ​

아직 도착하지 않은 것의 모양입니다. 진짜가 차지할 공간을 미리 잡아 두는 것이 일의 전부입니다 — 이미지가 도착하면서 200px 자라는 카드는 누군가 읽고 있는 동안 그 아래 전부를 밀어낸 카드입니다.

ReactFlutter
tsx
import { MPSkeleton } from 'material-plus-ui';

<MPSkeleton shape="circle" />
<MPSkeleton lines={3} />
<MPSkeleton shape="rect" height={180} label="차트를 불러오는 중" />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

const MPSkeleton(shape: MPSkeletonShape.circle);
const MPSkeleton(lines: 3);
const MPSkeleton(shape: MPSkeletonShape.rect, height: 180, label: '차트를 불러오는 중');

Props ​

Prop타입기본값설명
shape'line' | 'rect' | 'circle''line'무엇을 대신하고 있는지
linesnumber1`shape="line"`일 때 그릴 줄 수. 마지막 줄은 짧게 그려집니다
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
color'primary' | 'secondary' | 'tertiary' | 'error'—대체 표시를 물들일 계열. **기본값이 없습니다** — 지정하지 않으면 `surface-container-highest`입니다
widthnumber | string—너비. 숫자는 픽셀입니다
heightnumber | string—높이. 숫자는 픽셀입니다
animatedbooleantrue맥동 애니메이션. 모션 감소 설정은 이것과 무관하게 이미 존중됩니다
labelstring—스크린 리더에게 알릴 문장. 없으면 `aria-hidden`이고, 있으면 살아 있는 `status`가 됩니다
renderRenderProp—`<div>` 아닌 것으로 렌더링합니다
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다
Prop타입기본값설명
shapeMPSkeletonShapeMPSkeletonShape.line무엇을 대신하고 있는지
linesint1`shape="line"`일 때 그릴 줄 수. 마지막 줄은 짧게 그려집니다
sizeMPSize?MPSize.md컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
colorMPColor?—대체 표시를 물들일 계열. **기본값이 없습니다** — 지정하지 않으면 `surface-container-highest`입니다
widthdouble?—너비(논리 픽셀). 부모가 늘이려 해도 이 너비를 지킵니다. 너비의 일부는 `FractionallySizedBox`로 감싸서 줍니다
heightdouble?—높이(논리 픽셀). 줄 여러 개를 쌓은 스켈레톤에는 적용되지 않습니다. 각 막대가 이미 타입 크기의 높이를 가집니다

labelString?—스크린 리더에 무엇을 말할지. 비워 두면 아무것도 말하지 않습니다. 영역 전체를 대표하는 스켈레톤 하나에 주면 상태 역할과 이 라벨을 가진 노드가 됩니다

모든 native <div> 속성이 그대로 전달되고, ref는 루트에 닿습니다.

레이아웃이 세 가지로 이루어져 있으므로 모양도 셋입니다 ​

ReactFlutter
tsx
import { MPSkeleton } from 'material-plus-ui';

export default function SkeletonShapes() {
  return (
    <div style={{ display: 'grid', gap: 20, width: '100%', maxWidth: 420 }}>
      <MPSkeleton lines={2} />
      <MPSkeleton shape="rect" height={80} />
      <MPSkeleton shape="circle" />
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class SkeletonShapes extends StatelessWidget {
  const SkeletonShapes({super.key});

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 420),
      child: const Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 20,
        children: <Widget>[
          MPSkeleton(lines: 2),
          MPSkeleton(shape: MPSkeletonShape.rect, height: 80),
          MPSkeleton(shape: MPSkeletonShape.circle),
        ],
      ),
    );
  }
}

각각은 진짜 컴포넌트가 쓰는 사다리로 크기가 정해집니다. md 줄은 md 타입만큼 높고, md 원은 md의 MPAvatar 바로 그것, 같은 단계의 컨트롤 높이인 56px입니다.

줄의 높이는 줄 상자가 아니라 대체하는 타입의 em 상자입니다. 행간만큼 높은 자리표시자는 다음 것과 사이에 공기가 없는 막대이고, 그런 문단은 바코드입니다.

lines는 줄무늬 상자 하나가 아니라 막대의 더미입니다 ​

사이의 간격이 진짜 간격입니다. 글에는 행간이 있고 — 줄무늬 그러데이션은 호출자가 이 블록을 flex 행에 넣는 순간 무너집니다. 마지막 줄은 문단의 마지막 줄처럼 짧게 그려지므로 여러 개를 쌓으면 본문으로 읽힙니다.

label이 말할지 말지를 정합니다 ​

라벨이 없으면 aria-hidden 배경입니다. 그것이 옳은 기본값입니다. 상자 열두 개가 각자 자기를 알리는 것은 침묵보다 나쁩니다.

영역 전체를 대표하는 하나의 스켈레톤에 라벨을 주면 aria-busy를 가진 살아 있는 role="status"가 됩니다.

tsx
<div>
  <MPSkeleton label="프로젝트를 불러오는 중" />
  <MPSkeleton />
  <MPSkeleton />
</div>

라벨이 없으면 스크린 리더에 아무것도 말하지 않습니다. 그것이 옳은 기본값입니다. 상자 열두 개가 각자 자기를 알리는 것은 침묵보다 나쁩니다.

영역 전체를 대표하는 하나의 스켈레톤에 라벨을 주면, 상태 역할과 그 라벨을 가진 자기만의 노드가 됩니다.

dart
const Column(
  children: <Widget>[
    MPSkeleton(label: '프로젝트를 불러오는 중'),
    MPSkeleton(),
    MPSkeleton(),
  ],
);

color에는 기본값이 없습니다 ​

자리표시자는 아직 무엇이 아니므로 나를 의미가 없습니다. 지정하지 않으면 surface-container-highest입니다 — 아무것도 들어 있지 않은 컨테이너를 위한 MD3의 역할이고, 이것이 정확히 그것입니다. color를 주면 계열의 container 색으로 바뀝니다. 기다림 자체가 브랜드인 드문 페이지를 위한 것입니다.

면은 평평합니다 ​

라이브러리의 다른 모든 컨테이너는 surface-container 역할을 읽고 그림자를 드리울 수 있습니다. 스켈레톤은 거기 없는 것의 모양이므로 색 하나가 전부입니다 — 높이도, 가장자리도 없습니다. 자리표시자 서른 개짜리 페이지가 그림자 서른 개를 요구하지 않게 하는 효과도 있습니다.

animated={false}(Flutter에서는 animated: false)는 그것이 수십 개 있는 페이지, 또는 기다림이 길어서 움직임이 소음이 되는 곳에서 맥동을 멈춥니다. 접근성 스위치는 아닙니다. 모션 감소 설정, Flutter에서는 MediaQuery.disableAnimations가 요청하지 않아도 애니메이션을 멈추고, 상자는 여전히 알맞은 크기입니다 — 일하고 있던 부분은 그쪽이었습니다.

상자에 담긴 스피너가 아닙니다 ​

스피너는 공간을 잡아 둘 수 없습니다. 그것이 차이이고, 이것이 진행 표시의 variant가 아니라 독립된 컴포넌트인 이유입니다.

React 빌드와 다른 점 ​

ReactFlutter이유
width와 height가 숫자나 아무 CSS 길이를 받습니다width와 height는 논리 픽셀입니다CSS 길이가 없습니다. 너비의 일부는 히어로 데모의 짧은 두 줄처럼 스켈레톤을 FractionallySizedBox로 감싸서 줍니다.
문자열 shapeMPSkeletonShape 값의 shape세 값은 같습니다.
라벨이 있으면 aria-busy를 가진 role="status"상태 역할과 라벨을 가진 노드Flutter에는 busy 플래그가 없습니다. 영역이 기다리는 중이라는 것은 라벨이 말합니다.
render—바꿔 끼울 엘리먼트가 없습니다.
className, style, 네이티브 속성—넘겨줄 곳이 없습니다.

줄과 블록은 React 빌드의 w-full처럼 주어진 너비를 채웁니다. 그래서 Row 안에서는 Expanded로 감쌉니다. width를 준 스켈레톤과 원은 부모가 늘이려 해도 자기 너비를 지킵니다.
