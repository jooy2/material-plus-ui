이 페이지 콘텐츠

MPEmpty ​

내용이 있었어야 할 자리에 서는 것입니다. 글리프 하나, 제목 하나, 문장 하나, 그리고 빠져나갈 길. MPSkeleton의 나머지 절반입니다 — 그쪽이 오는 중인 것의 모양이라면 이쪽은 오지 않는 것의 모양입니다.

tsx
import { MPEmpty, MPButton } from 'material-plus-ui';

<MPEmpty title="“oklch”에 대한 결과 없음" action={<MPButton size="sm">필터 지우기</MPButton>}>
  이 저장소에는 일치하는 것이 없습니다.
</MPEmpty>;

Props ​

Prop타입기본값설명
titleReactNode | false'Nothing here'제목. `false`를 주면 제목 없이 글리프와 문장만 남습니다
iconReactNode | false—제목 위의 글리프. 생략하면 빈 쟁반, `false`면 없음, 노드를 주면 교체됩니다
actionReactNode—글 아래에서 할 수 있는 일 — "첫 항목 만들기" 버튼, "필터 지우기" 링크
variant'filled' | 'tonal' | 'elevated' | 'outlined' | 'text''text'칠하는 면의 양. 어떤 값이든 면은 중립 색으로 남습니다
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
renderRenderProp—`<div>` 아닌 것으로 렌더링합니다: `render={<td colSpan={5} />}`
childrenReactNode—제목 아래 문장 — 왜 비어 있는지, 다음에 무엇을 할지

모든 native <div> 속성이 그대로 전달되고, ref는 루트에 닿습니다.

제목에 기본값이 있는 것은 의도한 것입니다 ​

라이브러리에서 컴포넌트가 본문 크기로 지어내는 유일한 글입니다. 필수가 아니라 기본값인 이유는 하나입니다. 쓸모없는 말을 하는 버전이 결국 출시되는 버전이기 때문입니다.

Nothing here는 바닥이고, 그 위의 모든 자리 — 글리프, 문장, 동작 — 는 실제로 무엇이 없는지로 채우라고 있는 것입니다. 결과 없는 검색, 아무도 쓰지 않은 받은 편지함, 첫 파일 이전의 폴더는 서로 다른 세 가지이고, 어느 것인지는 호출자만 압니다.

tsx
import { MPEmpty } from 'material-plus-ui';

export default function EmptySlots() {
  return (
    <div style={{ display: 'grid', gap: 20, width: '100%', maxWidth: 480 }}>
      <MPEmpty variant="outlined" />

      <MPEmpty variant="outlined" icon={false} size="sm" title="Inbox zero">
        Nobody has written to you.
      </MPEmpty>

      <MPEmpty variant="outlined" icon={<span style={{ fontSize: '1em' }}>🗂</span>} title={false}>
        This folder is empty.
      </MPEmpty>
    </div>
  );
}

title={false}는 제목을 완전히 없앱니다. 글리프와 문장만 있고 그 위에 제목이 없는 상태를 위한 것입니다. 그러면 문장이 곧 상태 가 되므로 on-surface-variant로 내려가지 않고 읽는 글로 남습니다.

쟁반, 그리고 왜 쟁반인지 ​

비어 있는 이유 전부를 덮어야 하기 때문입니다. 폴더, 돋보기, 문서는 각각 하나씩을 지목합니다 — 아무것도 정리되지 않음, 아무것도 찾지 못함, 아무것도 쓰지 않음 — 그리고 이 컴포넌트는 셋 모두에 쓰입니다.

tsx
<MPEmpty />                                 // 쟁반
<MPEmpty icon={false} />                    // 없음
<MPEmpty icon={<MyIllustration />} />       // 직접

글리프는 상자가 아니라 em으로 크기가 정해집니다. 그래야 호출자가 건네는 무엇이든 주변 타입을 기준으로 재어지고, 다른 세트의 아이콘도 우리 것과 같은 무게로 내려앉습니다.

variant의 기본값은 text입니다 ​

라이브러리에서 여기만 그렇습니다. 빈 상태는 거의 언제나 이미 무언가 안에 있습니다 — 카드의 본문, 헤더 아래의 표, 패널 — 그리고 첫 사각형 안에 그린 두 번째 사각형은 사각형 하나가 더 많은 것입니다. 나머지 넷은 그렇지 않은 경우를 위한 것입니다.

어느 쪽이든 면은 중립으로 남습니다. action은 남의 버튼이고 자기 색을 가지고 도착했습니다.

color가 없습니다 ​

여기 있는 거의 모든 컴포넌트가 가진 것을 일부러 두지 않았습니다. 강조 색으로 칠해진 빈 상태는 존재하지 않는 내용에 대해 주장을 하고 있는 것입니다. "이건 문제다"라고 말하는 방법은 action 안의 color="error" 버튼입니다 — 그것이 실제로 누를 수 있는 것이기 때문입니다.

스스로를 알립니다 ​

독자 아래에서 비어 버린 목록은 그렇다고 말해야 하고, 다른 방법이 없습니다. 페이지에서 무언가 사라진 것이 아니라 무언가 더해진 것이기 때문입니다.

role="status"는 끼어들지 않고 알립니다. "결과 없음"은 방금 던진 질문에 대한 답이기 때문입니다. 도착할 때부터 페이지의 일부인 상태라면 role={undefined}로 끕니다.

render ​

가장 쓸모 있는 경우는 표 셀입니다.

tsx
<tr>
  <MPEmpty render={<td colSpan={5} />} title="아직 빌드가 없습니다" />
</tr>

MPTable의 empty prop이 이 컴포넌트를 통째로 받으므로 보통은 그쪽이 더 쉽습니다.
