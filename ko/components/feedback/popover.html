MPPopover ​

자기를 연 것 옆에 열리는 시트입니다. 툴팁과 달리 손이 닿습니다 — 닫힐 때까지 떠 있고, 안에 든 것을 누르고 입력할 수 있습니다.

ReactFlutter
tsx
import { MPPopover, MPPopoverClose, MPButton } from 'material-plus-ui';

<MPPopover trigger={<MPButton variant="outlined">이름 변경</MPButton>} title="이 뷰의 이름">
  <MPTextField label="이름" value={name} onChange={setName} fullWidth />
  <MPPopoverClose render={<MPButton>저장</MPButton>} />
</MPPopover>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPPopover(
  trigger: (BuildContext context, VoidCallback toggle) =>
      MPButton(variant: MPVariant.outlined, onPressed: toggle, child: const Text('이름 변경')),
  title: const Text('이 뷰의 이름'),
  child: Column(
    children: <Widget>[
      MPTextField(label: const Text('이름'), value: name, onChanged: setName, fullWidth: true),
      MPPopoverClose(
        builder: (BuildContext context, VoidCallback close) =>
            MPButton(onPressed: close, child: const Text('저장')),
      ),
    ],
  ),
);

trigger는 위젯이 아니라 위젯을 만드는 함수입니다. React 빌드는 받은 엘리먼트에 핸들러를 합쳐 넣지만, 위젯은 밖에서 손댈 수 없어서 팝오버가 핸들러를 건네줍니다. toggle을 컨트롤의 onPressed에 연결하세요. 여기서 만든 MPButton과 MPIconButton은 팝업이 열렸는지도 전달받고, 화면 낭독기는 이를 펼침·접힘으로 읽습니다.

셋 중 무엇이 필요한지 ​

팝오버, 툴팁, 다이얼로그는 모두 화면에 작은 시트를 올립니다. 서로 바꿔 쓸 수 없고, 차이는 읽는 사람이 그다음에 무엇을 할 수 있는가 입니다.

툴팁은 이미 거기 있는 것에 붙는 라벨입니다. 팝오버는 페이지 옆의 상세입니다. 다이얼로그는 페이지 대신 던지는 질문입니다.

표면 ​

레벨 2의 surface-container와 corner-medium입니다. MD3가 메뉴와 rich tooltip에 주는 값이고, 명세에서 이것 — 컨트롤에 붙은 작은 시트 — 에 해당하는 것이 그 둘입니다.

일부러 다이얼로그의 레벨 3 surface-container-high가 아닙니다. 팝오버는 페이지를 가져가지 않았고, 마찬가지로 가져가지 않은 메뉴들보다 위에 앉아서도 안 됩니다.

variant도 color도 없는데, 다이얼로그가 대는 이유와 같습니다. 다섯 무게는 "이 표면이 페이지에 대해 스스로를 얼마나 주장하는가"에 답하고, 요청을 받아야만 나타난 팝업은 이미 답했습니다. 그리고 물들 수 있는 팝오버는 누군가 그 안에 넣은 폼을 물들이게 됩니다.

배치 ​

ReactFlutter
tsx
import { MPButton, MPPopover } from 'material-plus-ui';
import type { MPSide } from 'material-plus-ui';

/**
 * `side` and `align`, and the one thing neither of them promises.
 *
 * Base UI flips the popup to the opposite edge when there is no room for it —
 * scroll the frame until one of these runs out of space and watch it move. That
 * is the right behaviour, and it is why `side` is a preference rather than an
 * instruction.
 */
const SIDES: MPSide[] = ['top', 'right', 'bottom', 'left'];

export default function PopoverPlacement() {
  return (
    <div style={{ display: 'flex', gap: 8, flexWrap: 'wrap' }}>
      {SIDES.map((side) => (
        <MPPopover
          key={side}
          side={side}
          arrow
          size="xs"
          trigger={<MPButton variant="outlined">{side}</MPButton>}
        >
          Anchored to the {side} edge.
        </MPPopover>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// `side` and `align`, and the one thing neither of them promises.
///
/// The popup flips to the opposite edge when there is no room for it: scroll
/// the frame until one of these runs out of space and watch it move. That is
/// the right behaviour, and it is why `side` is a preference rather than an
/// instruction.
class PopoverPlacement extends StatelessWidget {
  const PopoverPlacement({super.key});

  static const List<MPSide> _sides = <MPSide>[MPSide.top, MPSide.right, MPSide.bottom, MPSide.left];

  @override
  Widget build(BuildContext context) {
    return Wrap(
      spacing: 8,
      runSpacing: 8,
      children: <Widget>[
        for (final MPSide side in _sides)
          MPPopover(
            key: ValueKey<MPSide>(side),
            side: side,
            arrow: true,
            size: MPSize.xs,
            trigger: (BuildContext context, VoidCallback toggle) =>
                MPButton(variant: MPVariant.outlined, onPressed: toggle, child: Text(side.name)),
            child: Text('Anchored to the ${side.name} edge.'),
          ),
      ],
    );
  }
}

side는 지시가 아니라 선호입니다. 자리가 없으면 팝업이 반대편으로 뒤집히는데, 그게 옳은 동작입니다. 화면 밖으로 절반 걸친 팝업은 트리거 반대편에 놓인 팝업보다 나쁩니다.

side는 물리적(top, right, bottom, left)입니다. 팝업이 이동하는 축이기 때문입니다 — 트리거 위에 뜬 팝오버는 어느 표기 방향에서든 위에 있습니다. align은 논리적(start, center, end)입니다. 한 변을 따라가는 위치이고, 그 변은 RTL에서 반대로 흐르기 때문입니다.

arrow ​

기본은 꺼짐이고, MD3가 메뉴와 rich tooltip 양쪽에 하는 것도 그렇습니다. 자기를 연 컨트롤에서 8픽셀 떨어진 팝업은 자기가 무엇에 속하는지 따로 말할 필요가 없습니다. 트리거가 그 말이 필요할 만큼 멀 때 켜세요.

예시 ​

MPPopoverClose ​

uncontrolled 팝오버에는 Cancel 버튼이 부를 setOpen이 없고, 모든 팝오버를 controlled로 만드는 건 버튼 하나에 답하려고 팝오버마다 상태를 두는 일입니다.

tsx
<MPPopoverClose render={<MPButton variant="text">취소</MPButton>} />
dart
MPPopoverClose(
  builder: (BuildContext context, VoidCallback close) =>
      MPButton(variant: MPVariant.text, onPressed: close, child: const Text('취소')),
);

modal ​

기본은 false / MPPopoverModal.off이고, 그것이 팝오버와 다이얼로그를 가릅니다. 뒤쪽 페이지는 계속 스크롤되고 눌립니다. 페이지 옆의 상세가 페이지를 멈춰 세워서는 안 되기 때문입니다.

'trap-focus' / MPPopoverModal.trapFocus는 스크롤을 잠그지 않고 포커스만 팝업 안에 붙잡아 둡니다. 폼 컨트롤이 가득한 팝오버가 보통 원하는 것입니다.

React의 modal은 false, 'trap-focus', true 중 하나입니다. Dart에는 불리언과 문자열을 합친 타입이 없어서, 세 값을 MPPopoverModal의 세 값으로 나눴습니다.

  • off는 페이지를 그대로 둡니다. 팝업의 마지막 컨트롤에서 Tab을 누르면 트리거 다음 컨트롤로 넘어가며 팝업이 닫힙니다. 첫 컨트롤에서 Shift+Tab을 누르면 트리거로 돌아가고 팝업은 열린 채로 남습니다.
  • trapFocus는 Tab이 팝업 안에서만 돕니다.
  • on은 포커스를 붙잡는 데 더해 페이지 위에 보이지 않는 층을 깝니다. 바깥을 눌러도 페이지에는 닿지 않고, 그래서 페이지가 스크롤되지도 않습니다. 화면 낭독기도 페이지에 닿지 못합니다. 닫을 수 있는 팝업이라면 바깥 누름으로 닫히는 것은 그대로입니다.

dismissible ​

스스로 나갈 길을 가진 팝업에서만 끄세요. 다른 길이 없어집니다.

Escape, 바깥 클릭, 포커스 이탈이 모두 취소됩니다. MPPopoverClose와 코드에 의한 닫기는 그대로 동작하고, 그래서 dismissible={false}가 덫이 되지 않습니다.

바깥 누름, Escape, 시스템 뒤로 가기, Tab으로 빠져나가기를 모두 거절합니다. ×, MPPopoverClose, 트리거, controlled open으로는 계속 닫히고, 그래서 dismissible: false가 덫이 되지 않습니다.

시스템 뒤로 가기는 Android의 뒤로 버튼과 제스처, TalkBack의 뒤로, VoiceOver의 escape 스크럽을 말합니다. 닫을 수 있는 팝오버가 이를 먼저 받으므로, 다이얼로그 안에서 연 팝오버는 자기만 닫히고 다이얼로그는 남습니다.

width ​

size가 함의하는 상한을 덮어씁니다. 내용 이 너비를 정하는 팝오버 — 폼, 도움말 한 줄 — 를 위한 것입니다.

tsx
<MPPopover width={420} title="이름 변경">
  …
</MPPopover>

클래스가 아니라 인라인 스타일인 이유는, Tailwind가 소스 텍스트를 훑어 클래스를 찾기 때문에 prop으로 만든 max-w-[420px]은 아무 규칙도 만들어 내지 않기 때문입니다.

dart
MPPopover(width: 420, title: const Text('이름 변경'), child: …);

접근성 ​

  • title과 description은 aria-labelledby·aria-describedby로 연결되어, 팝업이 이름 없는 그룹으로 읽히지 않고 스스로를 알립니다.
  • 어떤 방식으로 닫혔든 포커스는 트리거로 돌아갑니다.
  • 트리거는 aria-expanded와 팝업의 id를 가집니다. 전부 Base UI의 것입니다.
  • 화면 낭독기에게 팝업은 다이얼로그이자 독립된 라우트이고, 이름은 title입니다. title은 제목으로도 읽힙니다. description은 그 아래 줄로 읽힙니다.
  • 팝업이 열리면 포커스가 그 안에서 포커스를 받는 첫 요소로 옮겨 가고, 어떤 방식으로 닫혔든 트리거로 돌아옵니다. 바깥 누름이 입력란에 떨어졌다면 포커스는 그 입력란에 남습니다.
  • trigger에서 만든 MPButton과 MPIconButton은 팝업이 펼쳐졌는지 알립니다.
  • ×는 이름이 있는 진짜 버튼이고 헤더의 처음이 아니라 마지막에 있습니다. 그래서 읽는 사람은 나가는 방법보다 팝업이 무엇에 대한 것인지를 먼저 듣습니다.
  • 팝오버는 live region이 아닙니다. 누군가 무언가를 눌러서 나타난 것이고, 그렇게 한 사람은 이미 알고 있습니다.
