MPAnimateMarquee ​

끝없이 흘러가는 내용. 똑같은 사본 두 벌을 이어 붙이고, 상자에 맞는 속도가 아니라 읽는 사람의 속도로 움직입니다.

ReactFlutter
tsx
import { MPAnimateMarquee } from 'material-plus-ui';

<MPAnimateMarquee speed={50} gap="1rem">
  {tools.map((tool) => (
    <MPChip key={tool}>{tool}</MPChip>
  ))}
</MPAnimateMarquee>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPAnimateMarquee(
  speed: 50,
  gap: 16,
  children: [for (final String tool in tools) MPChip(child: Text(tool))],
);

이음매가 없는 이유 ​

내용을 두 번 깔고, 각 사본이 정확히 자기 길이에 간격을 더한 만큼 움직입니다. 그래서 첫 사본이 떠나는 바로 그 순간 두 번째 사본이 첫 사본이 시작했던 자리에 서 있습니다. 튀지도, 이음매가 보이지도, 띠가 비는 프레임이 생기지도 않습니다.

이 중 어느 것도 측정에 기대지 않습니다. 백분율 translate는 요소 자신의 박스에 대해 계산되므로, -100%는 그것이 얼마든 사본 하나의 너비입니다.

한 바퀴에 움직일 거리는 측정합니다. 첫 사본이 배치된 뒤 그 길이를 읽고 간격을 더합니다. 첫 측정이 나오기 전까지 띠는 바로 끝나 버리는 대신 무난한 기본 속도로 움직입니다.

내용이 짧아서 뒤에 구멍을 남긴다면 copies를 올리세요. 컨테이너보다 좁은 것의 사본 둘은 두 번째가 도착하기 전에 바닥납니다.

띠는 읽기 방향의 시작 쪽으로 흐릅니다. 영어에서는 오른쪽에서 들어와 왼쪽으로 나가고, 오른쪽에서 왼쪽으로 쓰는 언어에서는 그 반대입니다. 그러지 않으면 단어가 거꾸로 도착합니다.

duration이 아니라 speed ​

duration이었다면 로고 넷짜리 띠와 마흔짜리 띠가 같은 상자를 같은 시간에 건너고, 긴 쪽은 얼룩이 됩니다. speed는 초당 픽셀이라서 둘 다 읽는 사람의 속도로 움직입니다.

여기서 측정되는 것은 그것 하나뿐이고, 띠나 컨테이너의 크기가 바뀔 때마다 다시 측정됩니다. 명시한 duration이 있으면 그쪽이 이깁니다.

위젯이 새 내용이나 설정으로 다시 빌드될 때마다 띠를 다시 측정합니다. 명시한 duration이 있으면 그쪽이 이기고, speed가 0 이하이면 띠는 그 자리에 머뭅니다.

pauseOnHover는 장식이 아닙니다 ​

포인터 앞을 지나가는 내용은 안정적으로 클릭할 수 없습니다. 멈추지 않는 마퀴 안의 링크는 아무도 따라갈 수 없는 링크이고, 읽으려는 이름은 끝내 잡히지 않는 이름입니다.

기본으로 켜져 있고, 링크나 버튼이나 읽을 만한 단어가 들어 있는 것에는 켜 둔 채로 두어야 합니다.

예제 ​

ReactFlutter
tsx
import { MPAnimateMarquee, MPBox, MPTypography } from 'material-plus-ui';

/**
 * Vertical, reversed, and slower.
 *
 * `speed` is pixels per second rather than a duration, so these two strips move
 * at the same pace even though one holds twice as much as the other — which is
 * exactly what a duration could not do.
 */
export default function AnimateMarqueeVertical() {
  const left = ['Seoul', 'Tokyo', 'Taipei', 'Osaka'];
  const right = ['Paris', 'Lisbon', 'Madrid', 'Berlin', 'Vienna', 'Oslo', 'Dublin', 'Prague'];

  return (
    <div
      style={{
        display: 'grid',
        gap: 12,
        gridTemplateColumns: 'repeat(2, minmax(0, 1fr))',
        width: '100%',
        maxWidth: 380
      }}
    >
      {[left, right].map((cities, index) => (
        <MPAnimateMarquee
          key={index}
          orientation="vertical"
          reverse={index === 1}
          speed={30}
          gap="0.5rem"
          style={{ height: 160 }}
        >
          {cities.map((city) => (
            <MPBox key={city} size="sm" style={{ width: '100%' }}>
              <MPTypography level="caption">{city}</MPTypography>
            </MPBox>
          ))}
        </MPAnimateMarquee>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// Vertical, reversed, and slower.
///
/// `speed` is pixels per second rather than a duration, so these two strips
/// move at the same pace even though one holds twice as much as the other —
/// which is exactly what a duration could not do.
class AnimateMarqueeVertical extends StatelessWidget {
  const AnimateMarqueeVertical({super.key});

  static const List<String> _left = <String>['Seoul', 'Tokyo', 'Taipei', 'Osaka'];

  static const List<String> _right = <String>[
    'Paris',
    'Lisbon',
    'Madrid',
    'Berlin',
    'Vienna',
    'Oslo',
    'Dublin',
    'Prague',
  ];

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 380),
      child: Row(
        spacing: 12,
        children: <Widget>[
          for (final (int index, List<String> cities) in <List<String>>[_left, _right].indexed)
            Expanded(
              child: SizedBox(
                height: 160,
                child: MPAnimateMarquee(
                  orientation: MPOrientation.vertical,
                  reverse: index == 1,
                  speed: 30,
                  gap: 8,
                  children: <Widget>[
                    for (final String city in cities)
                      SizedBox(
                        width: double.infinity,
                        child: MPBox(
                          size: MPSize.sm,
                          child: MPTypography(city, level: MPTypographyLevel.caption),
                        ),
                      ),
                  ],
                ),
              ),
            ),
        ],
      ),
    );
  }
}

orientation과 reverse ​

vertical은 띠를 가로가 아니라 세로로 흘립니다 — 컨테이너에 높이를 주세요. 그러지 않으면 흘릴 공간이 없습니다. reverse는 어느 축이든 반대로 돌립니다.

MPOrientation.vertical은 띠를 가로가 아니라 세로로 흘립니다 — SizedBox 같은 부모로 높이를 주세요. 그러지 않으면 흘릴 공간이 없습니다. reverse는 어느 축이든 반대로 돌립니다.

반대 방향으로 도는 두 줄은 로고 벽의 흔한 패턴이고, 두 줄이 한 줄로 읽히는 것도 막아 줍니다.

gap ​

항목 사이, 그리고 한 사본의 마지막 항목과 다음 사본의 첫 항목 사이의 간격입니다. prop에서 파싱하지 않고 계산된 스타일에서 다시 읽습니다. '2rem'은 폰트 크기가 정해진 다음에야 숫자이기 때문입니다.

항목 사이, 그리고 한 사본의 마지막 항목과 다음 사본의 첫 항목 사이의 간격이고, 단위는 논리 픽셀입니다. 기본값은 React 빌드의 2rem에 해당하는 32입니다.

접근성 ​

  • 첫 사본만 읽힙니다. 나머지는 aria-hidden을 답니다. 그러지 않으면 스크린 리더가 띠 전체를 깔린 횟수만큼 읽습니다.
  • prefers-reduced-motion에서는 느려지는 것이 아니라 멈춥니다. 흐르기를 멈춘 로고 줄도 여전히 로고 줄이고, 첫 사본은 화면 안에 온전히 들어 있습니다 — 움직이는 쪽이 어느 순간에도 보장하지 못하는 것입니다.
  • 움직이는 글자는 멈춘 글자보다 읽기 어렵고, 고정된 지점을 가로로 지나가는 글자는 그중에서도 가장 어렵습니다. 마퀴는 한눈에 훑는 묶음을 위한 것이지, 읽어야 하는 내용을 위한 것이 아닙니다.
  • 안에 있는 상호작용 요소에는 pauseOnHover가 켜져 있어야 하고, 그래도 멈춰 있는 같은 것보다 닿기 어렵습니다. 내용이 중요하다면 진짜 리스트를 쓰세요.
  • 첫 사본만 읽히고 키보드로 닿습니다. 나머지는 시맨틱스와 포커스 순서 모두에서 빠집니다. 그러지 않으면 스크린 리더가 띠 전체를 깔린 횟수만큼 읽고, 키보드는 스크린 리더가 없다고 말한 것에 멈춥니다.
  • 플랫폼이 애니메이션을 끄면(MediaQuery.disableAnimations) 느려지는 것이 아니라 멈추고, 아무것도 틱하지 않습니다. 흐르기를 멈춘 로고 줄도 여전히 로고 줄이고, 첫 사본은 시작하는 자리에서 화면 안에 온전히 들어 있습니다 — 움직이는 쪽이 어느 순간에도 보장하지 못하는 것입니다.
  • 움직이는 글자는 멈춘 글자보다 읽기 어렵고, 고정된 지점을 가로로 지나가는 글자는 그중에서도 가장 어렵습니다. 마퀴는 한눈에 훑는 묶음을 위한 것이지, 읽어야 하는 내용을 위한 것이 아닙니다.
  • 안에 있는 상호작용 요소에는 pauseOnHover가 켜져 있어야 하고, 그래도 멈춰 있는 같은 것보다 닿기 어렵습니다. 내용이 중요하다면 진짜 리스트를 쓰세요.

React 빌드와 다른 점 ​

ReactFlutter이유
children으로 넘기는 항목List<Widget>인 children사본마다 같은 목록을 다시 배치합니다.
백분율 translate, 속도를 위한 ResizeObserver배치가 끝난 뒤 첫 사본을 측정합니다상자의 백분율만큼 옮길 방법이 없으므로 거리를 측정합니다.
CSS 길이인 gap논리 픽셀 double풀어낼 rem이 없습니다.
어느 방향에서든 왼쪽으로 흐르는 띠읽기 방향의 시작 쪽으로 흐릅니다오른쪽에서 왼쪽으로 쓰는 언어에서는 그러지 않으면 단어가 거꾸로 도착합니다.
사본에 붙는 aria-hidden과 inertExcludeSemantics와 ExcludeFocus같은 답을 프레임워크의 말로 한 것입니다.
밀리초 숫자인 duration, delayDuration프레임워크에 이미 그 타입이 있습니다.
easing="linear"MPEasing.linear이름마다 MPMotion의 곡선 하나에 대응합니다.
repeat: number | 'infinite'null이면 멈추지 않는 int?인 MPAnimateRepeatDart에는 숫자와 단어의 합집합 타입이 없습니다.
IntersectionObserver로 보는 trigger="visible"위젯 위의 모든 Scrollable을 지켜봅니다옵저버가 없습니다. 위에 스크롤 영역이 없으면 바로 시작합니다.
화면 밖에서도 흐르는 띠상자가 조금도 보이지 않는 동안 쉽니다Flutter는 아무도 보지 못하는 애니메이션도 계속 그립니다.
className, style—넘겨줄 클래스 목록이나 style 속성이 없습니다. 띠의 크기는 부모로 정하세요.
