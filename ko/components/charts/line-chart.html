MPLineChart ​

순서가 있는 축 위의 수치. 어떻게 움직였고 어디로 가는지를 그립니다. 두 축과 격자, 범례, 호버 레이어까지 전부 직접 그리고 의존성은 늘리지 않습니다.

ReactFlutter
tsx
import { MPLineChart } from 'material-plus-ui';

<MPLineChart
  categories={['월', '화', '수', '목', '금']}
  series={[{ name: '가입', data: [120, 138, 131, 164, 190] }]}
/>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPLineChart(
  categories: const <String>['월', '화', '수', '목', '금'],
  series: const <MPChartSeries>[
    MPChartSeries(name: '가입', data: <num>[120, 138, 131, 164, 190]),
  ],
);

축은 0에서 시작하지 않습니다 ​

막대는 길이가 값입니다. 그래서 0 위에서 잘린 막대 차트는 비율을 속입니다. 선은 위치가 값이고, 표식 자체가 비율을 주장하지 않습니다. 눈금 범위를 좁히면 모든 점이 같은 만큼 이동할 뿐이라 그림은 그대로 살아남습니다.

3,200에서 3,400 사이를 오가는 계열에 0을 강제하면 평평한 선이 나옵니다. 실제로 일어난 변화를 아무 일도 없었다고 보고하는 셈입니다. 그래서 이 차트는 0을 넣지 않고, MPBarChart는 넣습니다.

0이 정말 기준선이라면 yAxis에 min: 0을 주십시오. 선 아래의 양이 핵심이라면 MPAreaChart를 쓰십시오. 채움은 0에서 재야 하니까요.

Dart에서는 yAxis: const MPChartAxis(min: 0)입니다.

구멍은 구멍입니다 ​

null은 아무것도 측정되지 않은 지점이고, 선은 거기서 끊깁니다. 이어 붙이지 않습니다. 아무도 가지고 있지 않은 값을 가로질러 그은 직선은 독자가 절대 의심하지 않는 종류의 조작이기 때문입니다. 나머지 선과 똑같이 생겼습니다.

smooth는 단조 보간이라 올라가던 구간이 도중에 되돌아가지 않고, 데이터의 최솟값이 화면의 최저점이 됩니다. 같은 점을 지나는 보통의 스플라인은 양쪽 다 넘어갑니다. 골짜기를 그린 차트는 골짜기가 있었다고 보고한 차트입니다.

끊는 것이 틀린 읽기인 경우가 둘 있고, gaps가 그것을 위한 prop입니다. gaps="connect"는 양쪽을 잇되 이은 구간을 점선으로 그립니다. 선은 이어지고, 그림은 어디까지가 측정한 값인지를 여전히 말합니다. gaps="zero"는 없는 값을 0으로 그리고 값 축을 0까지 넓힙니다. 빈 자리가 "하나도 일어나지 않았다"를 뜻할 때는 맞고, "아무도 세지 않았다"를 뜻할 때는 틀립니다.

Dart에서는 세 값이 MPChartGaps.gap, MPChartGaps.connect, MPChartGaps.zero입니다. break가 Dart의 예약어라 React의 'break'를 gap으로 씁니다.

바뀌는 것은 그림뿐입니다. 호버 패널과 뒤에 놓인 표는 셋 다에서 빈 값을 빈 값으로 말합니다. 독자가 숫자 자체를 필요로 할 때 받는 사본이 그 둘이기 때문입니다.

기준선은 계열이 아닙니다 ​

yAxis에 준 기준선 하나 — { value: 300, label: 'SLO', color: 'error' } — 는 300 자리에 점선을 긋고 그 끝에 이름을 씁니다. to까지 주면 선이 아니라 띠가 됩니다. 수치가 머물러야 할 범위, 무언가가 내려가 있던 구간 같은 것입니다. 양쪽 가장자리를 다 긋고 그 사이를 채웁니다.

Dart에서 기준선은 축의 references 목록에 넣는 MPChartReference입니다.

dart
yAxis: const MPChartAxis(
  references: <MPChartReference>[
    MPChartReference(value: 300, label: 'SLO', color: MPColor.error),
    MPChartReference(value: 280, to: 320, label: '목표'),
  ],
),

데이터가 아닙니다. 기준선은 독자가 들고 온 사실이라 팔레트 슬롯이 아니라 크롬의 잉크를 입고, 격자선과 헷갈리지 않도록 점선으로 그리며, 차트가 스스로 만들어 내는 일은 없습니다. color는 가질 값어치가 있는 한 경우를 위해 역할을 받습니다. 누군가 지켜보는 임계값이야말로 error가 있는 이유입니다.

눈금이 열려서 기준선을 담습니다. 그러지 않으면 측정한 모든 값보다 높은 목표치가 그림 밖으로 잘려 나가는데, 목표치가 절대 되어서는 안 되는 것이 그것입니다. 원치 않으면 min이나 max를 고정하십시오.

띠는 표식 아래에, 선은 표식 위에 그립니다. 막대 위에 덮인 채움은 독자가 뚫고 봐야 하는 막대이고, 그 선을 넘은 계열 뒤에 숨은 목표치는 아무도 읽을 수 없는 목표치입니다.

기준선은 자기 value가 놓인 눈금을 가진 축에 속하고, 그 축과 직각으로 그려집니다. 그래서 같은 기준선이 세워 둔 차트에서는 가로선이고 눕힌 차트에서는 세로선입니다. 이름만 늘어선 축에는 두 항목 사이에 선이 있을 자리가 없으므로, 눈금을 가진 축만 이 값을 읽습니다. 값 축은 언제나, 항목 축은 MPScatterChart처럼 숫자로 돌아갈 때만입니다. 날짜 축에서는 value에 Date를 줄 수 있습니다.

이름을 가진 기준선은 표 옆에서 차트와 함께 읽힙니다. 표에는 그것을 담을 열이 없기 때문입니다.

이름을 가진 기준선은 플롯의 의미 값에서 표 뒤에 이어 읽힙니다. 표에는 그것을 담을 열이 없기 때문입니다.

호버 레이어는 기본값입니다 ​

브라우저에 그려진 차트는 독자가 캐묻는 대상입니다. 선 차트가 받는 질문은 "3월에 무슨 일이 있었나"이고, 격자선에 대고 재보라고 답하는 건 잘못 답하는 겁니다. 그래서 십자선과 패널은 요청하지 않아도 나옵니다.

tooltip에 준 sort: 'value'는 가장 큰 행을 맨 위에 둡니다. 계열이 여덟 개인 차트가 원하는 것이 그것입니다. 독자가 찾는 행은 대개 큰 쪽이고, 고정된 순서의 목록에서 그것을 뒤지는 일이야말로 패널이 덜어 주려던 일입니다. 기본값은 계열을 넘긴 순서입니다. 범례를 익힌 독자는 읽지 않고도 행을 찾습니다. 어느 쪽이든 값이 같으면 계열 순서를 지킵니다.

쌓기에는 그 열이 얼마가 되는지를 말하는 행이 하나 더 붙습니다. 부분들과 선으로 나뉘고 견본은 달지 않습니다. 그 열의 높이가 이 모양의 전부인데, 부분만 늘어놓은 패널은 독자에게 덧셈을 시키기 때문입니다. 쌓지 않은 차트에는 붙지 않습니다. 그 계열들은 무언가의 부분이 아니고, 더하는 것은 패널이 없던 양을 만들어 내는 일입니다. percent 쌓기에도 붙지 않습니다. 답이 모든 항목에서 100%이니까요. tooltip의 total에 false나 true를 주면 둘 다 뒤집힙니다.

긴 축에서 구간을 끌어내기 ​

이 차트가 그리는 건 카드가 아니라 도형입니다. 표면이 필요하면 MPBox나 MPCard로 감싸십시오. 대시보드의 패널을 호출자의 결정으로 남겨 두는 편이, 여덟 개 컴포넌트가 각자 여백에 관해 의견을 갖는 것보다 낫습니다.

React 빌드와 다른 점 ​

ReactFlutter이유
data: [120, null, { y: 3 }]List<MPChartDatum>: 각각 num, null, MPChartPoint 중 하나Dart에는 유니언 타입이 없습니다. MPChartDatum, MPChartCategory, MPChartColor는 Object의 별칭이라 계열은 여전히 <num?>[120, 138, null]로 씁니다. 숫자가 아닌 값은 빈 값으로 읽습니다.
color: 'primary' 또는 CSS 색MPColor 또는 Color같은 선택을 Dart의 두 타입으로 씁니다.
Intl.NumberFormatOptions인 formatString Function(double value)인 format프레임워크에 Intl이 없습니다. format이 없으면 어느 언어에서든 숫자를 영어식으로 자릿수 구분하고 만 단위부터 축약합니다.
locale로 쓰는 날짜dateNames달 이름을 물어볼 Intl이 없습니다. 날짜 선택기처럼 로케일에 맞는 라이브러리 내장 표를 쓰고, dateNames로 직접 만든 MPDateNames를 넘기면 그것으로 바뀝니다.
legend={true}, legend={false}MPChartLegend(visible: true), MPChartLegend(visible: false)매개변수 하나에 타입 하나입니다.
