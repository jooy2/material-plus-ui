MPGaugeChart ​

계기판 위의 값 하나, 위험 구간은 문자판에 그려 둡니다. 논쟁할 값어치가 있는 차트 형태이고, 그 논쟁이 이 페이지에 있습니다.

ReactFlutter
tsx
import { MPGaugeChart } from 'material-plus-ui';

<MPGaugeChart value={72} label="CPU" thresholds={[{ from: 80, color: 'error' }]} />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPGaugeChart(
  value: 72,
  label: const Text('CPU'),
  thresholds: const <MPThreshold>[MPThreshold(from: 80, color: MPColor.error)],
);

안 쓰는 쪽을 먼저 생각하십시오 ​

계기판은 숫자 하나에 패널 하나를 씁니다. 그리고 호가 더해 주는 것은 숫자 자체에서 얻을 수 없는 것이 아닙니다. 각도는 길이보다 부정확하게 읽히고, 계기판의 양 끝은 눈이 가장 못 보는 자리입니다. MPStatistic 아래에 MPMeter를 두면 같은 말을 3분의 1의 공간에서 더 잘 읽히게 합니다.

계기판이 정말 잘하는 것은 누군가 지켜보는 임계값 있는 수치입니다. 문자판에 주의 구간이 칠해져 있으면 "이게 위험에 얼마나 가까운가"를 계산이 아니라 바늘이 멈춘 자리로 답하게 됩니다. bands가 그것이고, 이 모양을 고를 값어치가 있는 유일한 경우입니다.

임계값 없는 계기판은 장식을 두른 통계 숫자입니다.

마크업에서는 meter입니다 ​

값과 최솟값, 최댓값을 실은 role="meter"입니다. MPMeter와 같은 의미론이고, 둘은 같은 양의 두 가지 모양이기 때문입니다. 계기판을 볼 수 없는 독자도 그림을 설명받지 않고 숫자와 범위를 얻습니다.

이름과 숫자를 실은 의미 노드 하나입니다. 계기판 아래의 레이블이 이름이고, 수치가 그 값입니다. Flutter에는 meter 역할이 없어 범위를 따로 읽어 주지 않으니, 독자에게 범위가 필요하면 레이블에 넣으십시오.

뒤에 표가 없고 호버 레이어도 없는 이유가 그것입니다. 숫자 하나짜리 차트에는 가운데 숫자가 이미 말하지 않는, 독자가 캐낼 것이 없습니다.

임계값은 역할을 지목하고, 두 모양이 같은 해석기를 씁니다 ​

{ from: 80, color: 'error' }이지 절대 색상값이 아닙니다. 그래서 한 페이지의 계기판과 막대가 주의 구간이 어디서 시작하는지를 두고 어긋날 수 없습니다. 수치가 지나온 마지막 임계값이 이기므로 작은 것부터 나열하십시오.

Dart에서 임계값은 MPThreshold(from: 80, color: MPColor.error)입니다. MPMeter가 받는 것과 같은 타입이고, 둘은 같은 해석기를 씁니다.

머터리얼에는 warning 역할이 없어서, 주의 구간은 페이지가 어떤 시드 색으로 테마를 잡았든 tertiary입니다. 한계가 아니라 정직한 답입니다. 임계값이 역할을 지목하니 테마가 그것을 옮길 수 있습니다.

bands는 그 임계값을 수치뿐 아니라 트랙에도 칠합니다. 없으면 트랙은 중립적인 홈이고 수치만 색을 가집니다. 한계를 지켜보는 사람이 없는 계기판에는 그쪽이 맞습니다.

열린 각도, 그리고 계기판이 놓이는 자리 ​

sweep은 계기판이 도는 각도이고, 12시 방향을 중심으로 잰 도 단위입니다. 180은 밑변으로 선 반원, 240은 아래가 열린 전형적인 계기판입니다. 300도를 넘으면 양 끝이 만나서 독자가 시작과 끝을 구별할 수 없게 되므로 거기서 멈춥니다.

호가 중심 아래로 얼마나 내려오는지는 어림하지 않고 각도에서 계산합니다. 240도 계기판이 상자 안에서 뜨거나 300도 계기판이 잘리지 않는 이유입니다.

양 끝에 표시가 있습니다 ​

시작과 끝에 눈금 하나씩. 그래서 비어 있거나 가득 찬 계기판도 자기 눈금이 어디서 어디까지인지를 보여 줍니다. 이것이 없으면 가득 찬 계기판과 눈금 없는 계기판이 똑같아 보입니다.

React 빌드와 다른 점 ​

ReactFlutter이유
아무 노드나 되는 label위젯인 label, 보통 TextText 레이블은 화면 낭독기가 읽는 계기판의 이름도 됩니다. 레이블이 다른 위젯이면 semanticLabel로 이름을 줍니다.
범위를 실은 role="meter"레이블과 숫자를 실은 노드Flutter에는 meter 역할이 없습니다.
Intl.NumberFormatOptions인 formatString Function(double value)인 format프레임워크에 Intl이 없습니다.
CSS 길이인 height픽셀인 height해석할 CSS 길이가 없습니다.
className, style—넘길 클래스 목록도 style 속성도 없습니다.
