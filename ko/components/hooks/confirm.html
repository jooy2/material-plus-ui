useMPConfirm ​

"정말 하시겠어요?"를 promise로. 클릭 핸들러가 묻고 boolean을 돌려받습니다.

ReactFlutter
tsx
import { useState } from 'react';
import {
  ICONS,
  MPButton,
  MPConfirmProvider,
  MPIcon,
  MPTypography,
  useMPConfirm
} from 'material-plus-ui';

/**
 * A click handler, a question, and a boolean.
 *
 * What a caller has at the moment a confirmation is warranted is a handler, not
 * a place in the tree — so the dialog lives in the provider and the call site
 * gets a promise. Everything that is not the confirm button resolves `false`:
 * cancel, Escape, a press outside.
 */
function Row() {
  const { confirm, alert } = useMPConfirm();
  const [log, setLog] = useState<string[]>([]);

  const say = (line: string) => setLog((all) => [line, ...all].slice(0, 4));

  return (
    <div style={{ display: 'grid', gap: 16, justifyItems: 'start' }}>
      <div style={{ display: 'flex', gap: 12, flexWrap: 'wrap' }}>
        <MPButton
          color="error"
          startIcon={<MPIcon icon={ICONS.close} />}
          onClick={async () => {
            const sure = await confirm({
              title: 'Delete this project?',
              description: 'Everything in it goes too, and it cannot be undone.',
              confirmLabel: 'Delete',
              color: 'error'
            });

            say(sure ? 'Deleted.' : 'Kept.');
          }}
        >
          Delete project
        </MPButton>

        <MPButton
          variant="outlined"
          onClick={async () => {
            await alert({
              title: 'Saved',
              description: 'Your changes are on the server.'
            });

            say('Acknowledged.');
          }}
        >
          Save
        </MPButton>
      </div>

      <MPTypography level="caption">
        {log.length === 0 ? 'Nothing yet.' : log.join(' · ')}
      </MPTypography>
    </div>
  );
}

export default function ConfirmHero() {
  return (
    <MPConfirmProvider>
      <Row />
    </MPConfirmProvider>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

import 'package:material_plus_ui_example/demos/glyphs_confirm.dart';

/// A callback, a question, and a boolean.
///
/// What a caller has at the moment a confirmation is warranted is a callback,
/// not a place in the tree, so the dialog lives in the provider and the call
/// site gets a future. Everything that is not the confirm button completes
/// with `false`: cancel, Escape, a press outside.
class ConfirmHero extends StatelessWidget {
  const ConfirmHero({super.key});

  @override
  Widget build(BuildContext context) {
    return const MPConfirmProvider(child: _Row());
  }
}

class _Row extends StatefulWidget {
  const _Row();

  @override
  State<_Row> createState() => _RowState();
}

class _RowState extends State<_Row> {
  final List<String> _log = <String>[];

  void _say(String line) {
    setState(() {
      _log.insert(0, line);

      if (_log.length > 4) {
        _log.removeLast();
      }
    });
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: <Widget>[
        Wrap(
          spacing: 12,
          runSpacing: 12,
          children: <Widget>[
            MPButton(
              color: MPColor.error,
              startIcon: const MPIcon(icon: CloseGlyph()),
              onPressed: () async {
                final bool sure = await MPConfirmProvider.of(context).confirm(
                  const MPConfirmOptions(
                    title: Text('Delete this project?'),
                    description: Text('Everything in it goes too, and it cannot be undone.'),
                    confirmLabel: Text('Delete'),
                    color: MPColor.error,
                  ),
                );

                _say(sure ? 'Deleted.' : 'Kept.');
              },
              child: const Text('Delete project'),
            ),
            MPButton(
              variant: MPVariant.outlined,
              onPressed: () async {
                await MPConfirmProvider.of(context).alert(
                  const MPConfirmOptions(
                    title: Text('Saved'),
                    description: Text('Your changes are on the server.'),
                  ),
                );

                _say('Acknowledged.');
              },
              child: const Text('Save'),
            ),
          ],
        ),
        MPTypography(
          _log.isEmpty ? 'Nothing yet.' : _log.join(' · '),
          level: MPTypographyLevel.caption,
        ),
      ],
    );
  }
}

// 애플리케이션을 한 번 감싸고
<MPConfirmProvider>

// 그 아래 어디서든

  if (sure) {

dart
import 'package:material_plus_ui/material_plus_ui.dart';

// 애플리케이션 안에서 한 번, 자기만의 Overlay 아래에
WidgetsApp(
  // …
  builder: (BuildContext context, Widget? child) =>
      Overlay.wrap(child: MPConfirmProvider(child: child!)),
);

// 그 아래 어디서든
Future<void> remove(BuildContext context) async {
  final bool sure = await MPConfirmProvider.of(context).confirm(
    const MPConfirmOptions(
      title: Text('Delete this project?'),
      description: Text('Everything in it goes too, and it cannot be undone.'),
      confirmLabel: Text('Delete'),
      color: MPColor.error,
    ),
  );

  if (sure) {
    await api.delete(id);
  }
}

Flutter에는 훅이 없으므로 MPConfirmProvider.of(context)로 찾습니다. 돌려받는 것은 같은 두 메서드 confirm과 alert입니다. 콜백 안에서 쓰라고 만든 것이고, 불러도 프로바이더가 다시 그려질 때 위젯이 따라 다시 그려지지 않습니다.

프로바이더는 앱을 감싸지 않고 앱 안에 둡니다. 앱 바깥에는 아직 Directionality가 없기 때문입니다. builder 안에서는 내비게이터와 그 Overlay보다 위에 놓이므로 자기만의 Overlay가 있어야 합니다. 없으면 첫 질문이 "No Overlay widget found"로 실패합니다.

왜 직접 만든 다이얼로그가 아닌가 ​

다이얼로그가 어려운 부분이 아니기 때문입니다. "정말 하시겠어요"에는 열림 상태 하나, 무엇을 확인하는지에 대한 상태 하나, 핸들러 둘, 그리고 있어야 할 자리가 아닌 곳에 마운트해 둔 MPDialog가 필요합니다 — 호출 지점마다. 그 순간 호출자가 실제로 가진 것은 클릭 핸들러이고, 돌려받고 싶은 것은 boolean입니다.

useMPSnackbar가 하는 거래를 반대 방향으로 돌린 것입니다. 스낵바는 할 말이고, 이건 물을 것입니다.

나머지 전부가 false입니다 ​

읽는 사람이 한 것무엇으로 resolve되는가
확인 버튼을 누름true
취소를 누름false
Escapefalse
다이얼로그 바깥을 누름false

세 번째 결과가 없고 promise는 절대 reject하지 않습니다. 그래서 호출자는 try와 기본값이 아니라 if 하나를 씁니다. 모양이 boolean인 이유가 그것입니다 — 던지기도 하는 confirm은 모든 호출 지점이 두 번 처리해야 하는 confirm입니다.

시스템 뒤로 가기도 false로 답합니다. future가 오류로 끝나는 일은 없습니다.

alert은 버튼 하나짜리입니다 ​

tsx
const { alert } = useMPConfirm();

await alert({ title: 'Saved', description: 'Your changes are on the server.' });
dart
await MPConfirmProvider.of(context).alert(
  const MPConfirmOptions(
    title: Text('Saved'),
    description: Text('Your changes are on the server.'),
  ),
);

확인되면 void로 / Future<void>로 resolve합니다. 승인에는 거절할 것이 없고, 아무도 바꿀 수 없는 boolean은 호출자가 무시하는 법을 배워야 하는 값입니다. 같은 이유로 Escape도 resolve합니다.

애플리케이션 전체의 기본값 ​

tsx
<MPConfirmProvider defaults={{ size: 'sm', cancelLabel: 'Not now' }}>
  <App />
</MPConfirmProvider>
dart
MPConfirmProvider(
  defaults: const MPConfirmOptions(size: MPSize.sm, cancelLabel: Text('Not now')),
  child: child!,
);

defaults도 MPConfirmOptions입니다. 그 안의 title, description, child, semanticLabel은 쓰이지 않습니다. 질문은 한 가지를 묻고, 프로바이더는 그것이 무엇인지 모르기 때문입니다.

각 호출은 필요한 것을 여전히 말하고, 그쪽이 이깁니다.

색은 기본값이 아니라 결정입니다 ​

color는 확인 버튼을 칠하고, 'error' / MPColor.error는 파괴적인 확인이 원하는 것입니다. 일부러 기본값이 아닙니다 — 대부분의 확인은 파괴적이지 않고, 전부에 빨간 버튼을 달면 그건 더 이상 경고가 아닙니다.

라벨도 같습니다. Confirm과 Cancel은 아무도 다르게 말하지 않을 때 그려지는 것이고 열여덟 개 언어로 번역돼 있습니다 — 다만 Delete라고 적힌 버튼은 읽는 사람에게 지금 무엇을 하려는지 말해 주고, Confirm이라고 적힌 버튼은 기억해 내라고 요구합니다.

날카로운 모서리 ​

  • 위에 MPConfirmProvider가 필요합니다. 없으면 훅이 / MPConfirmProvider.of가 FlutterError를 throw합니다. 조용히 영원히 resolve되지 않는 함수를 돌려주지 않습니다. 끝내 정착하지 않는 promise는 프로바이더가 빠졌다는 사실을 알리는 가장 어려운 방법입니다.
  • 한 번에 하나입니다. 하나가 열려 있는 동안 올린 두 번째 confirm() / confirm은 그것을 대체하고, 첫 번째 promise는 false로 resolve합니다. 일부러 큐가 아닙니다 — 큐는 읽는 사람이 이미 지나간 것에 대해 묻게 되고, 철 지난 질문의 답은 정보가 아닙니다.
  • dismissible: false는 나가는 길이 둘뿐인 다이얼로그를 만들고, 둘 다 당신의 버튼입니다. 그 질문이 정말로 답해져야만 하는지 확인하세요.
  • 렌더 / build 중에 await하지 마세요. 클릭 핸들러의 도구입니다.

접근성 ​

  • 화면 낭독기는 질문을 경고 대화상자(SemanticsRole.alertDialog)로 알립니다. WAI-ARIA에서 읽는 사람이 하던 일에 끼어들어 답을 기다리는 대화상자를 부르는 이름입니다. 이름은 제목이 정하고, 제목이 평범한 Text가 아니면 질문에 semanticLabel을 주세요.
  • 대화상자가 열리면 취소 버튼이 포커스를 잡습니다. 습관처럼 누른 Enter는 아니오로 답합니다. alert은 하나뿐인 버튼에 포커스를 둡니다. 열린 질문을 대체한 질문도 포커스를 다시 놓습니다.
  • 포커스는 대화상자 안에 머물고, 질문에 답하면 열리기 전에 있던 곳으로 돌아갑니다.

React 빌드와 다른 점 ​

  • useMPConfirm() 대신 MPConfirmProvider.of(context)입니다. Flutter에는 훅이 없습니다. 찾으면 같은 confirm과 alert을 가진 MPConfirmResult가 돌아옵니다.
  • 질문은 경고 대화상자입니다. React 빌드는 평범한 role="dialog"입니다. 여기서는 답을 기다리는 질문에 맞게 층을 SemanticsRole.alertDialog로 알립니다.
  • 첫 포커스는 언제나 취소 버튼입니다. Base UI는 시트 안에서 포커스를 받을 수 있는 첫 요소에 포커스를 두므로, 질문의 children에 필드가 있으면 그 필드가 받습니다.
  • 트리에서 빠지는 프로바이더는 열린 질문에 false로 답합니다. React에서는 promise가 대기 상태로 남습니다. Flutter에서 끝나지 않는 future를 기다리는 콜백은 finally를 영영 실행하지 않으므로, 경로가 바뀌면 버튼이 계속 돌고 있게 됩니다.
  • semanticLabel이 추가됐습니다. Flutter의 제목은 위젯이라서 평범한 Text가 아니면 넘겨줄 글자가 없습니다. 그럴 때 이것이 대화상자의 이름이 됩니다.
