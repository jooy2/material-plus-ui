이 페이지 콘텐츠

MPAnchor ​

읽고 있는 페이지의 제목 목록입니다. 페이지가 스크롤되는 동안 독자가 지금 있는 항목을 표시합니다. 행은 스스로 제목까지 가고, 스크롤 추적은 그것을 떠받치는 것이 아니라 그 위에 얹힌 것입니다.

ReactFlutter
tsx
import { MPAnchor } from 'material-plus-ui';

<MPAnchor
  items={[
    { href: '#install', label: 'Install' },
    { href: '#usage', label: 'Usage' },
    { href: '#options', label: 'Options', depth: 1 }
  ]}
/>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPAnchor(
  items: <MPAnchorItem>[
    MPAnchorItem(target: _install, label: const Text('Install')),
    MPAnchorItem(target: _usage, label: const Text('Usage')),
    MPAnchorItem(target: _options, label: const Text('Options'), depth: 1),
  ],
)

target은 행이 가리키는 제목 위젯에 단 GlobalKey입니다.

Props ​

Prop타입기본값설명
items * MPAnchorItem[]—제목들. 페이지에 나타나는 순서대로 `{ href, label, depth? }` 배열입니다. `href`는 `id`를 가리키고, `id`가 없는 제목은 추적할 수 없습니다
activeHrefstring | null—표시할 행을 `href`로 지정합니다. 주면 목록은 스크롤을 지켜보지 않고 시키는 대로만 말합니다. `null`은 아무것도 표시하지 않습니다
onActiveChange(href: string | null) => void—독자가 있는 행이 바뀔 때마다 호출됩니다
offsetnumber0스크롤포트 위쪽에서 얼마나 내려가야 제목에 닿은 것으로 칠지, 픽셀. 고정 헤더의 높이를 넣으세요 — 그러지 않으면 바 뒤에 가려진 제목이 표시되는 일이 없습니다
containerRefObject<HTMLElement | null>—문서가 아닌 다른 것이 스크롤될 때 그 엘리먼트. `scroll="content"`인 `MPPageLayout`이 페이지를 넣는 상자 같은 것입니다
railbooleantrue앞 가장자리를 따라 레일을 그리고, 독자가 있는 행에 불을 켭니다. 표식이 아니라 행 자신의 테두리라서 아무것도 미끄러지지 않습니다
labelstring'On this page'`<nav>` 랜드마크의 접근성 이름. 메뉴와 목차가 함께 있는 페이지는 랜드마크가 둘이고, 둘 다 "navigation"으로 읽히면 아무것도 알려 주지 못합니다
localestring—그 이름을 쓰는 언어를 정하는 BCP 47 태그. 생략하면 가장 가까운 `MPLocaleProvider`, 그다음 영어입니다
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'행 글자의 크기, 그리고 제목 한 단계가 들어가는 정도
color'primary' | 'secondary' | 'tertiary' | 'error''primary'표시된 행이 읽는 강조 색 계열. 나머지 행은 중립으로 남습니다
density0 | -1 | -2 | -30행만 좁힙니다. 글자 크기는 움직이지 않습니다
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다

semanticLabelString?'On this page'화면 낭독기가 목록을 부르는 이름. 메뉴와 목차가 한 화면에 있으면 둘을 구분하는 것이 이 이름입니다

MPAnchorItem ​

React 패키지에는 아직 없는 컴포넌트입니다.

Prop타입기본값설명
target * GlobalKey—이 항목이 가리키는 제목 위젯에 단 키. React의 `href` 자리입니다
label * Widget—행에 쓰이는 내용
depthint0제목의 깊이, `0`부터. 들여쓰기만 바뀌고 목록은 평평하게 남습니다

링크는 추적이 돌기 전부터 동작합니다 ​

행은 <nav> 안의 <a href="#…">입니다. 그래서 자바스크립트를 꺼도 제목으로 뛰고, 스크린 리더가 불러내는 링크 목록에 들어가며, 가운데 클릭으로 새 탭에 열립니다. 스크롤을 지켜보는 쪽이 그 위에 얹은 것입니다.

표시된 행은 aria-current="true"가 아니라 "location"을 답니다. 그 값은 "링크 묶음 안에서 독자가 있는 자리"를 뜻하고, 목차가 보고하는 것이 정확히 그것입니다. "true"는 현재 페이지를 뜻하고, 그건 내비게이션 메뉴의 자기 항목이 하는 말입니다.

라우터가 클릭을 가져가지 않는다면 ​

VitePress, Docusaurus, Astro, Nuxt는 모두 같은 페이지 안의 해시 클릭을 가로채 취소하고, 자기가 생각하는 목표 위치로 창을 스크롤합니다. container를 주면 창은 그들이 뜻할 수 없는 단 하나의 스크롤 영역입니다. 그래서 페이지가 튀고 패널은 그대로 남습니다.

그래서 행에 도달했을 때 이미 취소된 누름은 행이 직접 답합니다. offset까지 반영해 container를 제목까지 스크롤합니다. 아무도 취소하지 않은 누름은 그대로 둡니다. 스크롤도 해시도 히스토리 항목도 브라우저가 이미 다 하기 때문입니다. container가 없으면 아무것도 걸지 않습니다.

행을 누르면 제목이 선까지 옵니다 ​

행을 누르거나 행에서 Enter를 누르면, 제목이 든 스크롤 뷰가 움직여 제목이 위쪽에서 offset만큼 내려온 자리에 놓입니다. 추적이 읽는 선과 같은 자리입니다. React 빌드에서 fragment 링크가 그러듯 애니메이션 없이 바로 옮겨 갑니다.

화면에는 fragment를 적을 URL이 없고 링크를 긁어 가는 크롤러도 없으므로, 기댈 링크 엘리먼트가 없습니다. 각 행은 semantics 트리에서 링크이고 자기 포커스 자리를 가지며, 표시된 행은 선택된 것으로 읽힙니다. 프레임워크에서 aria-current="location"에 가장 가까운 표현입니다.

제목은 긁어 오는 게 아니라 건네받습니다 ​

items는 호출부가 이미 가지고 있는 목록입니다. 페이지를 만든 것이 무엇이든 — MDX 파이프라인이든, CMS든, 라우트의 frontmatter든 — 자기 제목과 거기 써 넣은 id를 압니다. 문서에서 <h2>를 찾아다니는 컴포넌트는 그중 무엇이 본문이고 무엇이 크롬인지를 추측하게 되고, 사이드바에 있는 것까지 집어 옵니다.

href는 id를 가리키고, id가 없는 제목은 추적할 수 없습니다. 호출부가 맞춰 줘야 하는 것은 그 하나입니다.

items는 호출부가 이미 가지고 있는 목록입니다. 화면을 만든 쪽은 자기 제목을 알고, 위젯 트리에서 제목을 찾아다니는 컴포넌트는 무엇이 본문이고 무엇이 크롬인지 추측할 수밖에 없습니다.

target은 제목 위젯에 단 GlobalKey이고, 그 키가 어디에도 달려 있지 않은 제목은 추적할 수 없습니다. 호출부가 맞춰 줘야 하는 것은 그 하나입니다.

엉뚱한 행에 불이 들어오게 만드는 두 가지 ​

고정 헤더. 페이지 위쪽을 지나간 제목도 아직 바 뒤에 가려져 있으므로, 독자가 보고 있는 것은 그 앞 섹션입니다. offset이 그 바의 높이입니다.

tsx
<MPAnchor items={items} offset={64} />
dart
MPAnchor(items: items, offset: 64)

문서가 아닌 스크롤러. scroll="content"인 MPPageLayout은 페이지를 자기 엘리먼트 안에 넣고, 창은 아예 스크롤되지 않습니다. container가 대신 볼 곳입니다.

tsx
const page = React.useRef<HTMLDivElement>(null);

<MPAnchor items={items} container={page} />;

엉뚱한 스크롤 뷰. 목록은 첫 제목이 든 스크롤 뷰를 따라가므로, 따로 스크롤되는 패널이라도 더 할 일이 없습니다. 제목이 여러 스크롤 뷰에 흩어져 있거나 따라갈 뷰가 더 바깥에 있으면 controller로 지정합니다.

dart
MPAnchor(items: items, controller: _page)

무엇을 표시하고, 언제 아무것도 표시하지 않는지 ​

규칙은 "선을 지나간 제목 중 마지막 것"입니다. 내려갈 때뿐 아니라 올라갈 때도 옳게 읽히는 유일한 규칙입니다.

거기서 두 가지가 따라 나오고, 둘 다 의도한 것입니다. 페이지 맨 위에서는 아무것도 표시되지 않습니다. 독자가 아직 첫 제목에 닿지 않았기 때문이고, 그런데도 첫 항목에 불을 켜면 가 보지 않은 섹션에 있다고 말하는 셈입니다. 그리고 맨 아래에서는 측정이 무엇이라고 하든 마지막 제목을 표시합니다. 마지막 섹션은 대개 뷰포트보다 짧은 내용을 달고 있어서 그 위쪽이 선에 닿지 못하고, 이 예외가 없으면 아무리 스크롤해도 결코 표시될 수 없는 유일한 제목이 됩니다.

직접 정하려면 activeHref를 넘기세요. 그러면 목록은 스크롤을 아예 지켜보지 않고 시키는 대로만 말합니다. null은 아무것도 표시하지 않는다는 뜻입니다.

직접 정하려면 activeTarget을 넘기세요. 그러면 목록은 스크롤을 아예 지켜보지 않고 시키는 대로만 말합니다. null을 넘기면 표시를 다시 스크롤에 맡깁니다.

아무것도 미끄러지지 않습니다 ​

레일에 켜지는 구간은 행 사이를 옮겨 다니는 표식이 아니라 행 자신의 테두리입니다. 이미 움직이고 있는 독자 밑에서 무언가가 움직이는 것은 목차가 가져서는 안 될 유일한 애니메이션이고, 동시에 제대로 만들 수 없는 종류이기도 합니다. 표식과 스크롤이 같은 동작에 서로 다른 속도로 답하기 때문입니다. 색은 전이하고, 위치는 그렇지 않습니다.

depth는 들여쓸 뿐입니다 ​

제목이 아무리 깊어져도 목록은 평평합니다. 목차 안에 목록을 겹치면 목록 안의 목록으로 읽히고, 방금 제목이 열두 개라고 들은 독자에게 필요 없는 말입니다.

React 빌드와 다른 점 ​

ReactFlutter이유
항목의 hreftarget, GlobalKey화면에는 가리킬 fragment가 없습니다. 목록이 재는 것은 위젯의 위치이고, 키가 그 위치를 잡는 손잡이입니다.
container, refcontroller, 생략 가능없으면 목록이 제목이 든 스크롤 뷰를 스스로 찾습니다. React에서 기본값이 문서인 것과 같은 자리입니다.
activeHref={null}로 아무것도 표시하지 않기—activeTarget: null은 "스크롤을 따라가라"는 뜻입니다. 제어하는 목록은 언제나 한 행을 표시합니다.
labelsemanticLabelReact의 aria-label처럼 화면 낭독기만 듣는 이름입니다.
진짜 <a> 링크와 라우터 대비 처리스크롤 뷰를 바로 옮기는 누름URL도, 가운데 클릭도, 크롤러도 없습니다. 브라우저가 fragment 링크에 하는 일을 누름이 대신합니다.
className, style—넘길 클래스 목록도 style 속성도 없습니다.
