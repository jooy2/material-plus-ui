MPShortcut ​

키보드의 키, 또는 그 조합입니다. 이것을 그냥 꾸민 상자 이상으로 만드는 두 가지는 모두 상자가 아니라 라벨에 관한 것입니다.

ReactFlutter
tsx
import { MPShortcut } from 'material-plus-ui';

<MPShortcut keys="Mod+K" />
<MPShortcut keys="Mod+Shift+P" os="windows" />
<MPShortcut keys={['Ctrl', '+']} />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

const MPShortcut(keys: 'Mod+K');
const MPShortcut(keys: 'Mod+Shift+P', os: MPShortcutOS.windows);
const MPShortcut(keys: <String>['Ctrl', '+']);

Props ​

Prop타입기본값설명
keys * string | string[]—키들. 문자열은 `+`로 나뉩니다 — `Mod+Shift+P`. 키 자체가 `+`이면 배열로 주세요
os'auto' | 'mac' | 'windows' | 'linux''auto'어느 키보드 기준으로 이름 붙일지. `auto`는 브라우저에 물어봅니다
separatorReactNode—키 사이에 들어갈 것. 생략하면 플랫폼 관례 — 윈도우·리눅스는 `+`, 맥은 아무것도 없음
variant'filled' | 'tonal' | 'elevated' | 'outlined' | 'text''outlined'키 캡이 칠하는 면의 양
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
color'primary' | 'secondary' | 'tertiary' | 'error''secondary'어떤 강조 색 계열을 읽을지. 임의의 색상값은 받지 않습니다 — `primary`가 무엇인지 바꾸려면 토큰을 설정하세요
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다
Prop타입기본값설명
keys * String | List<String>—키들. 문자열은 `+`로 나누고, 키 자체가 `+`인 단축키는 목록으로 넘깁니다. 유니언 타입이 없어 `Object`로 받습니다
osMPShortcutOSMPShortcutOS.auto어느 키보드 기준으로 이름 붙일지. `auto`는 브라우저에 물어봅니다
separatorWidget?—키 사이에 들어갈 것. 생략하면 플랫폼 관례 — 윈도우·리눅스는 `+`, 맥은 아무것도 없음
variantMPVariantMPVariant.outlined키 캡이 칠하는 면의 양
sizeMPSize?MPSize.md컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
colorMPColorMPColor.secondary`filled`와 `tonal` 키캡이 쓰는 강조 계열

모든 native <span> 속성이 그대로 전달되고, ref는 루트에 닿습니다.

Dart에는 유니언 타입이 없어 keys는 Object로 받습니다. String이나 List<String>이어야 하며 디버그에서 확인합니다. 이 컴포넌트는 키를 그리기만 합니다. 키에 반응하는 일은 앱의 Shortcuts나 CallbackShortcuts가 맡습니다.

Mod이 이것이 존재하는 이유입니다 ​

Ctrl+K로 적은 단축키는 모든 맥 사용자에게 틀렸고, ⌘K로 적은 것은 나머지 모두에게 틀렸습니다. Mod은 "단축키가 기반하는 수정 키"를 뜻하는 토큰이고 — 맥에서는 Command, 나머지에서는 Control — 플랫폼에 따라 결정됩니다.

ReactFlutter
tsx
import { MPShortcut } from 'material-plus-ui';
import type { MPShortcutOS } from 'material-plus-ui';

const PLATFORMS: MPShortcutOS[] = ['auto', 'mac', 'windows', 'linux'];

export default function ShortcutPlatforms() {
  return (
    <div style={{ display: 'grid', gap: 12 }}>
      {PLATFORMS.map((os) => (
        <div key={os} style={{ display: 'flex', alignItems: 'center', gap: 14 }}>
          <code style={{ width: 72, flexShrink: 0, fontSize: 12, opacity: 0.7 }}>{os}</code>
          <MPShortcut keys="Mod+Shift+P" os={os} size="sm" />
        </div>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class ShortcutPlatforms extends StatelessWidget {
  const ShortcutPlatforms({super.key});

  @override
  Widget build(BuildContext context) {
    final MPThemeData theme = MPTheme.of(context);
    final TextStyle code = TextStyle(
      fontFamily: 'monospace',
      fontSize: 12,
      color: theme.colors.onSurface.withValues(alpha: 0.7),
    );

    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      mainAxisSize: MainAxisSize.min,
      spacing: 12,
      children: <Widget>[
        for (final MPShortcutOS os in MPShortcutOS.values)
          Row(
            mainAxisSize: MainAxisSize.min,
            spacing: 14,
            children: <Widget>[
              SizedBox(width: 72, child: Text(os.name, style: code)),
              MPShortcut(keys: 'Mod+Shift+P', os: os, size: MPSize.sm),
            ],
          ),
      ],
    );
  }
}

auto는 React에서는 브라우저에, Flutter에서는 defaultTargetPlatform에 물어봅니다. 사용자가 지금 누르려는 단축키라면 그것이 맞습니다. 나머지 세 값은 사용자의 플랫폼이 아니라 특정 플랫폼을 명시해야 하는 문서를 위한 것입니다 — 윈도우 빌드를 설명하는 지원 페이지, 둘을 비교하는 표.

서버 렌더링

플랫폼은 렌더 중이 아니라 useSyncExternalStore로 읽습니다. 서버의 답과 브라우저의 답이 달라야 한다 고 React에 말해주는 유일한 API입니다. Ctrl로 하이드레이션하고 ⌘로 다시 렌더링하는데, 맥 사용자가 실제로 보는 순서가 그것입니다. 렌더 중에 navigator를 읽는 것은 하이드레이션 불일치입니다.

⌘는 단어가 아닙니다 ​

스크린 리더는 그것을 "place of interest sign"으로 읽습니다. 아무의 키보드에도 없는 키입니다.

그래서 글리프로 그려지는 모든 키는 잘려 있는 상자 안에 자기 이름을 함께 지니고, 읽히는 것은 "Command K" — 이 단축키의 실제 이름 — 입니다.

이음쇠가 aria-hidden인 것도 같은 이유입니다. "Ctrl 더하기 K"는 구두점을 읽는 것입니다.

그래서 조합 전체가 의미 노드 하나이고, 각 키를 부르는 이름으로 이름이 붙습니다. 읽히는 것은 정류장 세 개, 그것도 첫 번째가 기호인 정류장이 아니라 "Command Shift P", 이 단축키의 실제 이름입니다.

이음쇠를 그 이름에서 빼는 것도 같은 이유입니다. "Ctrl 더하기 K"는 구두점을 읽는 것입니다.

별칭은 인심이 아니라 의도입니다. Cmd, Command, Meta는 하나의 키가 이미 가진 세 이름이고, 그중 하나만 받는 컴포넌트는 호출자가 매번 찾아봐야 하는 컴포넌트입니다.

화살표는 맥에서만이 아니라 어디서나 화살표로 그려집니다. 화살표는 맥의 관례가 아니라 키에 인쇄되어 있는 것입니다.

표에 없는 것은 쓴 그대로 인쇄됩니다. 한 글자는 대문자로 바꾸는 배려 하나만 있습니다. keys="mod+k"는 K를 그립니다. 키에 그렇게 적혀 있으니까요.

separator ​

생략하면 플랫폼의 관례를 따릅니다. 윈도우와 리눅스는 +, macOS는 아무것도 없습니다 — 맥에서 단축키는 기호의 나열로 적힙니다. ⇧⌘P이지 ⇧+⌘+P가 아닙니다.

키는 진짜 <kbd> 엘리먼트입니다 ​

감싸는 것은 <span>입니다. <kbd> 안에 <kbd>를 넣는 것도 허용되고 그것대로 옹호할 만하지만, kbd 래퍼는 호스트 스타일시트가 손을 뻗을 상자가 하나 더 생기는 것뿐입니다 — 의미는 어느 쪽이든 키 자신이 나릅니다.

캡은 corner-extra-small이고, 모양 스케일에서 corner-full로부터 가장 먼 곳입니다. 여기에는 누를 수 있는 것이 없습니다.

React 빌드와 다른 점 ​

ReactFlutter이유
string | string[]인 keysObjectDart에는 유니언 타입이 없습니다. String이나 List<String>이며 디버그에서 확인합니다.
브라우저를 읽는 autodefaultTargetPlatformmacOS와 iOS는 mac, Windows는 windows, 나머지는 linux입니다.
잘린 이름을 품은 <kbd>조합 전체에 노드 하나이름을 실을 엘리먼트가 없습니다. 조합에 이름 하나를 붙이면 단축키의 이름으로 읽힙니다.
이음쇠를 없애는 separator={null}SizedBox.shrink()Dart에서는 null이 이미 "플랫폼의 관례"를 뜻합니다.
font-monofontFamily: 'monospace'브라우저는 이 일반 글꼴군을 풀어 주고, 다른 플랫폼에서는 엔진의 기본 글꼴로 돌아갑니다.
className, style, ref—넘길 클래스 목록, style 속성, 엘리먼트가 없습니다.
