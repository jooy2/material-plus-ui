MPBadge ​

다른 것의 모서리에 붙는 작은 표시입니다. 받은 편지함 아이콘 위의 안 읽은 메일, 아바타 위의 상태 점, 탭 위의 개수. 자식이 없으면 인라인으로 놓여서 독립된 상태 표시가 됩니다.

ReactFlutter
tsx
import { MPBadge } from 'material-plus-ui';

<MPBadge content={3} label="안 읽은 메시지 3개">
  <MPButton>받은 편지함</MPButton>
</MPBadge>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPBadge(
  content: 3,
  label: '안 읽은 메시지 3개',
  child: MPButton(onPressed: openInbox, child: const Text('받은 편지함')),
);

모든 native <span> 속성이 그대로 전달되고, ref는 표시에 닿습니다.

Dart에는 유니언 타입이 없어 content는 Object?로 받습니다. int나 double은 max와 showZero가 적용되는 개수이고, String은 낱말, 위젯은 그대로 그립니다. 그 밖의 값은 디버그에서 assert로 막습니다.

color의 기본값은 error입니다 ​

라이브러리에서 유일하게 그런 컴포넌트이고, 취향의 문제가 아닙니다. MD3는 배지에 정확히 한 쌍의 색만 줍니다 — on-error 아래의 error — 배지는 눈에 띄기 위해 존재하고, error 팔레트는 소스 색이 무엇이든 시끄러움이 보장되는 유일한 팔레트이기 때문입니다. 브랜드 색 앱 바 위의 브랜드 색 숫자는 아무도 못 보는 숫자입니다.

점과 숫자가 머터리얼의 두 배지입니다 ​

MD3에는 작은 배지(6dp 점)와 큰 배지(라벨이 있는 16dp)가 있고, 그게 전부입니다. dot을 주면 앞의 것이고, content를 주면 뒤의 것입니다. 둘 다 없으면 숫자 0일 때처럼 배지가 숨습니다.

dot과 content를 함께 주는 것은 새로운 모양이 아니라 그 중간입니다. 표시는 점으로 그려지고 내용은 스크린 리더용으로만 남습니다. 조용한 모서리가 침묵하는 모서리는 아닙니다.

ReactFlutter
tsx
import { useState } from 'react';
import { MPBadge, MPButton } from 'material-plus-ui';

export default function BadgeCounts() {
  const [count, setCount] = useState(0);

  return (
    <div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 20 }}>
      <MPBadge content={count} label={`${count} unread`}>
        <MPButton variant="outlined" size="sm">
          Inbox
        </MPButton>
      </MPBadge>

      <MPButton size="sm" variant="text" onClick={() => setCount((value) => value + 1)}>
        One more
      </MPButton>
      <MPButton size="sm" variant="text" onClick={() => setCount(0)}>
        Mark all read
      </MPButton>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class BadgeCounts extends StatefulWidget {
  const BadgeCounts({super.key});

  @override
  State<BadgeCounts> createState() => _BadgeCountsState();
}

class _BadgeCountsState extends State<BadgeCounts> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Wrap(
      spacing: 20,
      runSpacing: 20,
      crossAxisAlignment: WrapCrossAlignment.center,
      children: <Widget>[
        MPBadge(
          content: _count,
          label: '$_count unread',
          child: MPButton(
            variant: MPVariant.outlined,
            size: MPSize.sm,
            onPressed: () {},
            child: const Text('Inbox'),
          ),
        ),
        MPButton(
          size: MPSize.sm,
          variant: MPVariant.text,
          onPressed: () => setState(() => _count += 1),
          child: const Text('One more'),
        ),
        MPButton(
          size: MPSize.sm,
          variant: MPVariant.text,
          onPressed: () => setState(() => _count = 0),
          child: const Text('Mark all read'),
        ),
      ],
    );
  }
}

0은 소식이 아닙니다 ​

content가 0이면 배지가 숨습니다. 사라지지 않는 배지는 아무 뜻도 갖지 못하기 때문입니다. 정말 0을 읽어야 하는 계수기를 위해 showZero가 있습니다.

invisible은 숨기는 다른 방법이고 성질이 다릅니다. 표시가 자기 상자를 유지하므로 다시 보여줄 때 아래가 밀리지 않습니다.

그리고 자라 들어오고 줄어들어 나갑니다. MD3가 배지에 정한 등장 방식이고, 그냥 나타나는 숫자는 아무도 바뀌는 것을 보지 못한 숫자입니다.

숨기는 일은 여전히 visibility가 합니다. 배율에 밀려난 것이 아니라 함께 쓰이는데, opacity가 할 수 없는 두 가지를 하기 때문입니다. opacity: 0으로 세워 둔 배지는 페이지 내 찾기에는 여전히 보이고, 아무 말도 하지 않는 표시가 "3" 검색에 걸려서는 안 됩니다. 또 visibility는 정확히 필요한 모양으로 보간됩니다. 들어올 때는 첫 프레임에서 보이게 되고, 나갈 때는 마지막 프레임까지 보인 채로 있습니다. 그래서 표시는 두 애니메이션 내내 그려지고, 어느 쪽에서도 사라져 있지 않습니다.

invisible 배지가 숫자를 DOM에 그대로 두는 이유가 그것입니다. 안이 빈 요소에는 줄어들 크기가 없어서, 한 프레임 만에 빈 알약으로 무너진 뒤 그것을 애니메이션하게 됩니다. 숨어 있는 동안에는 페이지 검색에도, 접근성 트리에도 잡히지 않습니다. 할 말이 전혀 없는 배지는 아무것도 담지 않습니다 — 그건 숨겨진 배지가 아니라 애초에 없던 배지입니다.

배율과 페이드는 둘 다 short4 동안 움직이고, MediaQuery.disableAnimations가 켜져 있으면 움직이지 않습니다. 숨은 배지는 의미 트리에서 빠지고, 배지는 탭을 받지 않습니다. 배지 위의 탭은 배지가 붙은 대상의 것입니다. invisible 배지는 숫자를 그대로 들고 있어서 줄어들 크기와 다시 자라날 크기가 있습니다.

label이 문장입니다 ​

종 아이콘 옆의 content가 3이면 "3"으로 읽히고, 그것은 아무 뜻이 없습니다. label이 스크린 리더가 대신 듣는 문장이고, 눈에 보이는 숫자는 접근성 트리에서 감춰집니다. 둘이 연달아 읽히지 않게 하기 위해서입니다.

tsx
<MPBadge content={3} label="안 읽은 알림 3개">
  <BellIcon />
</MPBadge>
dart
const MPBadge(content: 3, label: '안 읽은 알림 3개', child: BellGlyph())

버튼이 아니면서 알약인 유일한 것 ​

모든 크기에서 corner-full입니다. MD3가 배지를 완전한 원이나 스타디움으로 두는 이유는 그것이 자기 면이 아니라 면 위에 얹힌 표시이기 때문이고, 표시에는 깎을 가장자리가 없습니다. 이웃과 겹치는 유일한 컴포넌트인 것도 같은 이유입니다.

overlap은 얼마나 안쪽으로 파고들지입니다. 원의 모서리는 배지가 기준으로 삼는 경계 상자 안쪽으로 지름의 약 15% 들어와 있어서, 이것이 없으면 아바타에서 알맞아 보이던 배지가 아이콘 버튼에서는 붕 뜹니다.

아래에 프리미티브가 없습니다 ​

배지에는 상호작용도, 상태도, 키보드 계약도 없습니다. 표시입니다. 위젯 프리미티브에 연결하면 장식용 점 하나하나에 지킬 수 없는 역할을 쥐여주는 셈입니다.

React 빌드와 다른 점 ​

ReactFlutter이유
ReactNode인 contentObject?Dart에는 유니언 타입이 없어 숫자, String, 위젯을 한 인자로 받고 디버그에서 확인합니다.
숨을 때의 visibilityExcludeSemantics숨은 숫자를 감출 페이지 내 찾기가 없습니다. 숫자를 빼 두는 곳은 의미 트리입니다.
childrenchildFlutter의 이름입니다.
className, style, ref—넘길 클래스 목록, style 속성, 엘리먼트가 없습니다.
