MPBadge ​

다른 것의 모서리에 붙는 작은 표시입니다. 받은 편지함 아이콘 위의 안 읽은 메일, 아바타 위의 상태 점, 탭 위의 개수. 자식이 없으면 인라인으로 놓여서 독립된 상태 표시가 됩니다.

tsx
import { MPBadge } from 'material-plus-ui';

<MPBadge content={3} label="안 읽은 메시지 3개">
  <MPButton>받은 편지함</MPButton>
</MPBadge>;

Props ​

Prop타입기본값설명
contentReactNode—배지가 말하는 것. 생략하면 점을 그립니다
maxnumber99숫자 `content`의 상한. 넘으면 `+`가 붙습니다
dotbooleanfalse내용이 있어도 점으로 그립니다. 내용은 스크린 리더용으로 남습니다
showZerobooleanfalse`content`가 `0`일 때도 보여줍니다
invisiblebooleanfalse자리는 그대로 두고 표시만 감춥니다
placement'top-start' | 'top-end' | 'bottom-start' | 'bottom-end''top-end'붙는 모서리
overlap'square' | 'circle''square'밑에 깔린 것의 모양. 얼마나 안쪽으로 파고들지를 정합니다
variant'filled' | 'tonal' | 'elevated' | 'outlined' | 'text''filled'표시가 칠하는 면의 양
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
color'primary' | 'secondary' | 'tertiary' | 'error''error'읽어들일 강조 색 계열. 라이브러리에서 유일하게 `error`가 기본값입니다 — MD3의 배지가 그렇습니다
labelstring—스크린 리더가 숫자 대신 듣는 문장
childrenReactNode—배지가 붙는 대상. 없으면 인라인으로 놓이는 독립 표시가 됩니다
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다

모든 native <span> 속성이 그대로 전달되고, ref는 표시에 닿습니다.

color의 기본값은 error입니다 ​

라이브러리에서 유일하게 그런 컴포넌트이고, 취향의 문제가 아닙니다. MD3는 배지에 정확히 한 쌍의 색만 줍니다 — on-error 아래의 error — 배지는 눈에 띄기 위해 존재하고, error 팔레트는 소스 색이 무엇이든 시끄러움이 보장되는 유일한 팔레트이기 때문입니다. 브랜드 색 앱 바 위의 브랜드 색 숫자는 아무도 못 보는 숫자입니다.

점과 숫자가 머터리얼의 두 배지입니다 ​

MD3에는 작은 배지(6dp 점)와 큰 배지(라벨이 있는 16dp)가 있고, 그게 전부입니다. content를 생략하면 앞의 것이고, 주면 뒤의 것입니다.

dot이 세 번째 경우인데, 새로운 모양이 아니라 그 중간입니다. 표시는 점으로 그려지고 내용은 스크린 리더용으로만 남습니다. 조용한 모서리가 침묵하는 모서리는 아닙니다.

tsx
import { useState } from 'react';
import { MPBadge, MPButton } from 'material-plus-ui';

export default function BadgeCounts() {
  const [count, setCount] = useState(0);

  return (
    <div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 20 }}>
      <MPBadge content={count} label={`${count} unread`}>
        <MPButton variant="outlined" size="sm">
          Inbox
        </MPButton>
      </MPBadge>

      <MPButton size="sm" variant="text" onClick={() => setCount((value) => value + 1)}>
        One more
      </MPButton>
      <MPButton size="sm" variant="text" onClick={() => setCount(0)}>
        Mark all read
      </MPButton>
    </div>
  );
}

0은 소식이 아닙니다 ​

content={0}이면 배지가 숨습니다. 사라지지 않는 배지는 아무 뜻도 갖지 못하기 때문입니다. 정말 0을 읽어야 하는 계수기를 위해 showZero가 있습니다.

invisible은 숨기는 다른 방법이고 성질이 다릅니다. 표시가 자기 상자를 유지하므로 다시 보여줄 때 아래가 밀리지 않습니다.

그리고 자라 들어오고 줄어들어 나갑니다. MD3가 배지에 정한 등장 방식이고, 그냥 나타나는 숫자는 아무도 바뀌는 것을 보지 못한 숫자입니다.

숨기는 일은 여전히 visibility가 합니다. 배율에 밀려난 것이 아니라 함께 쓰이는데, opacity가 할 수 없는 두 가지를 하기 때문입니다. opacity: 0으로 세워 둔 배지는 페이지 내 찾기에는 여전히 보이고, 아무 말도 하지 않는 표시가 "3" 검색에 걸려서는 안 됩니다. 또 visibility는 정확히 필요한 모양으로 보간됩니다. 들어올 때는 첫 프레임에서 보이게 되고, 나갈 때는 마지막 프레임까지 보인 채로 있습니다. 그래서 표시는 두 애니메이션 내내 그려지고, 어느 쪽에서도 사라져 있지 않습니다.

invisible 배지가 숫자를 DOM에 그대로 두는 이유가 그것입니다. 안이 빈 요소에는 줄어들 크기가 없어서, 한 프레임 만에 빈 알약으로 무너진 뒤 그것을 애니메이션하게 됩니다. 숨어 있는 동안에는 페이지 검색에도, 접근성 트리에도 잡히지 않습니다. 할 말이 전혀 없는 배지는 아무것도 담지 않습니다 — 그건 숨겨진 배지가 아니라 애초에 없던 배지입니다.

숨은 배지는 글자를 전혀 갖고 있지 않습니다. 잘려 있는 상자에 남은 글자는 페이지 내 검색이 여전히 찾아내는 글자입니다.

label이 문장입니다 ​

종 아이콘 옆의 content={3}은 "3"으로 읽히고, 그것은 아무 뜻이 없습니다. label이 스크린 리더가 대신 듣는 문장이고, 눈에 보이는 숫자는 접근성 트리에서 감춰집니다. 둘이 연달아 읽히지 않게 하기 위해서입니다.

tsx
<MPBadge content={3} label="안 읽은 알림 3개">
  <BellIcon />
</MPBadge>

버튼이 아니면서 알약인 유일한 것 ​

모든 크기에서 corner-full입니다. MD3가 배지를 완전한 원이나 스타디움으로 두는 이유는 그것이 자기 면이 아니라 면 위에 얹힌 표시이기 때문이고, 표시에는 깎을 가장자리가 없습니다. 이웃과 겹치는 유일한 컴포넌트인 것도 같은 이유입니다.

overlap은 얼마나 안쪽으로 파고들지입니다. 원의 모서리는 배지가 기준으로 삼는 경계 상자 안쪽으로 지름의 약 15% 들어와 있어서, 이것이 없으면 아바타에서 알맞아 보이던 배지가 아이콘 버튼에서는 붕 뜹니다.

아래에 프리미티브가 없습니다 ​

배지에는 상호작용도, 상태도, 키보드 계약도 없습니다. 표시입니다. 위젯 프리미티브에 연결하면 장식용 점 하나하나에 지킬 수 없는 역할을 쥐여주는 셈입니다.
