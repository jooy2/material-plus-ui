MPAnimateLighting ​

무언가의 바깥을 도는 빛. 아무것도 움직이지 않고 "지금 이것"이라고 말하는 방법입니다 — 처리 중인 행, 검사 중인 필드, 추천되는 요금제.

tsx
import { MPAnimateLighting } from 'material-plus-ui';

<MPAnimateLighting size="md">
  <MPCard title="Recommended" />
</MPAnimateLighting>;

Props ​

Prop타입기본값설명
color'primary' | 'secondary' | 'tertiary' | 'error''primary'빛이 어떤 계열로 그려지는지. 임의의 색상값은 받지 않습니다 — `primary`가 무엇인지 바꾸려면 토큰을 설정하세요
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'빛이 따라 도는 반경. 안에 있는 것과 맞아야 합니다 — 그러지 않으면 내용이 이미 깎아 낸 모서리를 빛이 가로지릅니다
spreadnumber3빛이 내용 바깥으로 얼마나 나가는지(px)
arcnumber50한 번에 얼마만큼의 윤곽이 켜지는지(도). 작으면 지나가는 불꽃, 크면 쓸고 지나가는 빛입니다
blurnumber4빛이 얼마나 부드러운지(px). `0`이면 빛이 아니라 그래픽으로 읽히는 쐐기가 됩니다
reversebooleanfalse빛을 반대 방향으로 돌립니다
durationnumber—한 번 도는 데 걸리는 시간(ms). 비워 두면 그 효과의 머터리얼 duration 토큰을 따르므로, 페이지가 모션 토큰을 바꾸면 같이 움직입니다
delaynumber0시작하기 전 기다리는 시간(ms)
repeatnumber | 'infinite'1몇 번 도는지. `Infinity`가 아니라 `'infinite'`입니다 — CSS에 그 단어로 쓰이기 때문입니다
alternatebooleanfalse한 번 걸러 거꾸로 돌립니다. 반복이 처음으로 튀지 않고 되돌아옵니다
pausedbooleanfalse애니메이션을 그 자리에 붙들어 둡니다. 되감지 않습니다
trigger'mount' | 'visible' | 'hover' | 'manual''mount'무엇이 시작시키는지 — 화면에 올라올 때, 스크롤로 보일 때, 포인터가 올라올 때, 또는 `play`로만
playboolean—`trigger="manual"`일 때 이것이 돌립니다. `false` → `true`마다 처음부터 다시 시작합니다
oncebooleantrue`trigger="visible"`일 때 처음 한 번만 돌릴지. 끄면 다시 보일 때마다 돕니다
thresholdnumber0.2`trigger="visible"`일 때 얼마나 보여야 보인 것으로 칠지, `0`부터 `1`까지
renderRenderProp—`<div>` 아닌 것으로 렌더링합니다
childrenReactNode—빛이 두를 것
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다

빛은 내용 뒤에 있습니다 ​

위가 아니라요. 격리된 쌓임 맥락 안에서 의사 요소가 z-index: -1에 놓이므로, 읽는 사람이 보는 것은 가장자리를 두른 테두리가 아니라 가장자리 밑에서 새어 나오는 빛입니다.

그래서 카드, 버튼, 폼 구획 전체를 감싸면서도 그것들이 그려지는 방식을 전혀 건드리지 않습니다. 안의 것에 무엇도 겹쳐지지 않고 무엇도 물들지 않으며, 내용은 정확히 이전만큼 읽힙니다 — 색을 바꾸거나 맥동시키는 대신 이것을 집는 이유 전부입니다.

내용은 자기 면을 칠해야 합니다 ​

"뒤"는 앞에 불투명한 것이 있을 때만 뒤로 읽힙니다. 배경을 전혀 칠하지 않는 outlined 카드나 text 버튼을 감싸면, 호는 내용 아래가 아니라 내용을 통과해 지나갑니다.

투명한 상자 뒤의 빛을 그리면 정확히 그렇게 됩니다. 다만 아무도 원한 효과가 아닐 뿐입니다. 내용에 면을 주세요 — variant="filled" 또는 variant="elevated".

size는 안의 것과 맞아야 합니다 ​

빛은 border-radius: inherit을 통해 래퍼 자신의 모서리를 따릅니다. 그러니 md Lighting 안의 xl 카드는, 카드가 이미 둥글게 깎아 낸 네 모서리에서 빛이 삐져나옵니다.

중요도가 아니라 내용의 반경에 맞춰 단계를 정하세요.

호가 왜 conic gradient인가 ​

실제로 움직이는 것은 그라디언트의 from 각도이고, 각도가 타입을 가진 등록된 커스텀 프로퍼티 — @property --mp-glow-angle { syntax: '<angle>' } — 이기 때문에만 애니메이션이 가능합니다.

떠오르는 대안인 의사 요소 자체를 회전시키는 방법은, 4분의 1 바퀴마다 모서리를 요소 밖으로 휘두릅니다. 중심을 축으로 돌아간 직사각형은 원래 직사각형보다 넓기 때문입니다. 그라디언트는 제자리에 있고 빛만 움직입니다.

easing이 없습니다 ​

한 바퀴에는 감속해 들어갈 시작점이 없습니다. 이징이 걸린 회전은 임의의 점이 없는 원 위 임의의 점에서 빛이 머뭇거리는 것으로 읽히므로, 곡선은 linear이고 그것을 잘못 줄 prop 자체가 없습니다.

예제 ​

tsx
import { MPAnimateLighting, MPBox, MPTypography } from 'material-plus-ui';

/**
 * Three dials, and they are the whole of the look.
 *
 * `arc` is how much of the outline is lit at once — small is a travelling
 * spark, large is a sweep. `blur` is how soft the light is; at `0` it is a
 * hard-edged wedge, which reads as a graphic rather than as light. `spread` is
 * how far past the content it reaches.
 */
export default function AnimateLightingShape() {
  const looks = [
    { label: 'A spark', arc: 18, blur: 6, spread: 3, color: 'primary' as const },
    { label: 'A sweep', arc: 140, blur: 10, spread: 5, color: 'tertiary' as const },
    { label: 'A wedge', arc: 60, blur: 0, spread: 2, color: 'secondary' as const },
    { label: 'A halo', arc: 200, blur: 14, spread: 8, color: 'error' as const }
  ];

  return (
    <div
      style={{
        display: 'grid',
        gap: 20,
        gridTemplateColumns: 'repeat(2, minmax(0, 1fr))',
        width: '100%',
        maxWidth: 460
      }}
    >
      {looks.map((look) => (
        <MPAnimateLighting
          key={look.label}
          size="sm"
          color={look.color}
          arc={look.arc}
          blur={look.blur}
          spread={look.spread}
          duration={4000}
        >
          <MPBox size="sm" variant="filled">
            <MPTypography level="caption">{look.label}</MPTypography>
          </MPBox>
        </MPAnimateLighting>
      ))}
    </div>
  );
}

arc ​

한 번에 얼마만큼의 윤곽이 켜지는지, 도 단위입니다. 작으면 — 대략 30 아래 — 지나가는 불꽃입니다. 크면 쓸고 지나가는 빛이고, 180쯤을 넘으면 이동이 아니라 숨 쉬는 후광으로 읽힙니다.

blur ​

빛이 얼마나 부드러운지. 0이면 가장자리가 딱 떨어지는 쐐기가 되고, 빛이 아니라 그래픽으로 읽힙니다. 기본값 4px는 빛으로 읽히는 가장 작은 값입니다.

color ​

MD3의 네 강조 계열 중 하나이고, 임의의 색상값은 아닙니다 — 이 라이브러리의 어떤 것도 그것을 받지 않는 이유와 같습니다. primary가 무엇인지 바꾸려면 토큰을 설정하세요.

접근성 ​

  • prefers-reduced-motion에서는 호가 이동을 멈추고 고른 빛이 됩니다. MPSkeleton이 하는 것과 같은 거래입니다. 장식은 살아남고 움직임은 사라지며, 살아 있는 행을 표시하던 빛은 멈춘 채로도 여전히 그것을 표시합니다.
  • 이 표시는 장식이고 접근성 트리에는 전혀 닿지 않습니다. 그것이 가리키던 것 — "추천", "처리 중", "확인 중" — 은 내용에서도 말해져야 합니다.
  • 래퍼 안의 것은 아무것도 달라지지 않으므로, 명암비와 포커스 링과 클릭 영역은 이것이 없을 때와 똑같습니다.
  • 기본으로 영원히 돕니다. 살아 있는 영역이 여럿인 페이지에서는 여러 개가 동시에 움직이는 것이 됩니다. 하나만 표시하세요.

함께 보기 ​

  • MPOverlay — 어떤 일이 영역에게 일어나고 있어서 그것을 덮어야 할 때.
  • MPProgressLinear — 보고할 실제 진행량이 있을 때.
