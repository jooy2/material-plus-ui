MPGrid ​

머터리얼의 레이아웃 그리드입니다. 한 행을 열로 나누고, 아이템이 그중 몇 개를 가져갑니다. 열 개수는 이 라이브러리가 임의로 정한 브레이크포인트가 아니라 명세가 정의한 윈도우 크기 클래스를 따라 바뀝니다 — 휴대폰에서 4열, 600dp부터 12열입니다.

ReactFlutter
tsx
import { MPGrid, MPGridItem } from 'material-plus-ui';

<MPGrid>
  <MPGridItem span={6}>절반</MPGridItem>
  <MPGridItem span={3}>4분의 1</MPGridItem>
  <MPGridItem span={3}>그리고 4분의 1</MPGridItem>
</MPGrid>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

const MPGrid(
  children: <Widget>[
    MPGridItem(span: MPResponsive<MPGridSpan>(MPGridSpan(6)), child: Text('절반')),
    MPGridItem(span: MPResponsive<MPGridSpan>(MPGridSpan(3)), child: Text('4분의 1')),
    MPGridItem(span: MPResponsive<MPGridSpan>(MPGridSpan(3)), child: Text('그리고 4분의 1')),
  ],
);

Props ​

Prop타입기본값설명
columnsMPResponsive<number>12한 행을 몇 개의 열로 나눌지. 안쪽의 모든 `span`과 `offset`이 이 숫자를 기준으로 읽히므로 `columns={24}`에서는 `span={12}`가 절반입니다. MD3 자신의 그리드는 `{ compact: 4, medium: 12 }`입니다
spacingMPResponsive<number>4아이템 사이 간격. Tailwind의 spacing 스케일이라 `4`는 `gap-4`와 같은 `1rem`입니다. 소수도 됩니다. MD3 자신의 간격은 `{ compact: 4, medium: 6 }` — 휴대폰에서 16dp, medium부터 24dp입니다
rowSpacingMPResponsive<number>—행 사이 간격만. 없으면 `spacing`을 따릅니다
columnSpacingMPResponsive<number>—열 사이 간격만. 없으면 `spacing`을 따릅니다
justifyContent'start' | 'center' | 'end' | 'space-between' | 'space-around' | 'space-evenly'—아이템이 쓰지 않은 폭을 행이 어떻게 나눌지
alignItems'start' | 'center' | 'end' | 'stretch' | 'baseline''stretch'아이템들이 행을 가로질러 서로 어떻게 놓일지
alignContent'start' | 'center' | 'end' | 'space-between' | 'space-around' | 'space-evenly' | 'stretch'—그리드가 자기를 담은 상자보다 짧을 때 행들이 어디에 놓일지. 높이를 가진 그리드에서만 보입니다
wrapbooleantrue열이 모자란 행이 다음 줄로 이어질지. 끄면 넘치는 한 줄이 되며, 가로로 스크롤되는 띠가 원하는 동작입니다
renderRenderProp—`<div>` 대신 다른 엘리먼트로 렌더링합니다 — `render={<section />}`, `render={<ul />}`. Base UI 자신의 탈출구입니다
childrenReactNode—`MPGridItem`들
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다
Prop타입기본값설명
children * List<Widget>—아이템들. `MPGridItem`은 자기가 차지할 열을 말하고, 그 밖의 위젯은 행 전체를 채웁니다. `MPGridItem`은 `Expanded`처럼 그리드의 직접 자식이어야 합니다
columnsMPResponsive<int>?12한 행을 몇 열로 나눌지. 안의 span과 offset은 모두 이 숫자를 기준으로 읽습니다. MD3 자신의 그리드는 `MPResponsive<int>(4, medium: 12)`입니다. `MPResponsive(값, medium: …)`은 기본값에 창 크기 클래스별 덮어쓸 값을 더한 것이고, `MPResponsive.from(expanded: …)`은 바꾸는 클래스만 적어 그 아래는 기본값을 남깁니다
spacingMPResponsive<double>?4아이템 사이 간격. Tailwind 간격 척도이므로 `4`는 16px이고 `1.5`는 6px입니다. MD3 자신의 간격은 `MPResponsive<double>(4, medium: 6)`입니다
rowSpacingMPResponsive<double>?—행 사이 간격만. 없으면 `spacing`을 따릅니다
columnSpacingMPResponsive<double>?—열 사이 간격만. 없으면 `spacing`을 따릅니다
justifyContentMPGridJustify?MPGridJustify.start아이템이 쓰지 않은 폭을 행이 어떻게 나눌지
alignItemsMPGridAlignMPGridAlign.stretch아이템들이 행을 가로질러 서로 어떻게 놓일지
alignContentMPGridAlignContent?—그리드가 자기를 담은 상자보다 짧을 때 행들이 어디에 놓일지. 높이를 가진 그리드에서만 보입니다
wrapbooltrue열이 모자란 행을 다음 줄로 이어 갈지. 끄면 한 행이 되고, 그 행은 가로로 스크롤됩니다. 폭은 여전히 보이는 상자를 기준으로 계산합니다

MPGridItem ​

Prop타입기본값설명
spanMPResponsive<number | 'grow' | 'auto'>—그리드의 열 중 몇 개를 가져갈지. 그리드의 `columns` 기준이라 기본 12열에서 `span={6}`은 절반입니다. `{ compact: 12, medium: 6 }`처럼 윈도우 크기 클래스별로 줄 수 있고, 행보다 넓으면 넘치는 대신 행에 맞춰 잘립니다. 열의 개수가 아닌 값이 둘 있습니다. `'grow'`는 **행에 남은 폭**이라 썸네일 옆 본문이 원하는 값이고, `'auto'`는 **안에 든 것의 폭**이라 개수가 그때그때 달라지는 버튼 묶음이 원하는 값입니다. 기본값은 행 전체입니다
offsetMPResponsive<number>0아이템 **앞에** 비워 두는 열. 행 안의 절대 위치가 아니라 앞으로 밀어 넣는 공간입니다 — 12열 행의 첫 번째에서 `offset={4}`에 `span={4}`면 가운데 3분의 1입니다
alignSelf'auto' | 'start' | 'center' | 'end' | 'stretch' | 'baseline'—이 아이템 하나에 대해 행의 `alignItems`를 덮어씁니다
renderRenderProp—`<div>` 대신 다른 엘리먼트로 렌더링합니다 — `render={<li />}`, `render={<article />}`
childrenReactNode—셀 안의 내용

Prop타입기본값설명
spanMPResponsive<MPGridSpan>?—그리드의 열 중 몇 열을 차지할지. `MPGridSpan(6)`은 기본 12열의 절반이고, `MPGridSpan.grow`는 행에 남은 폭, `MPGridSpan.auto`는 안에 든 것의 폭입니다. 행보다 넓으면 행에 맞춰 잘립니다. 지정하지 않으면 행 전체를 채웁니다

브레이크포인트가 아니라 윈도우 크기 클래스 ​

span, offset, columns, 그리고 간격 관련 세 prop은 값 하나를 받거나, 윈도우 크기 클래스를 키로 하는 맵을 받습니다.

클래스시작MD3 열 개수
compact04
medium600dp12
expanded840dp12
large1200dp12
extra-large1600dp12

각 항목은 자기 클래스부터 위로 적용됩니다. 그래서 레이아웃 하나는 보통 다섯 개가 아니라 두 개면 끝나고, 적지 않은 클래스는 그 아래 클래스가 말한 값을 그대로 유지합니다.

tsx
<MPGridItem span={{ compact: 12, medium: 6, expanded: 4 }} />
dart
MPGridItem(
  span: const MPResponsive<MPGridSpan>(
    MPGridSpan(12),
    medium: MPGridSpan(6),
    expanded: MPGridSpan(4),
  ),
  child: card,
)

휴대폰에서는 전체 폭, 600dp부터 절반, 840dp부터 3분의 1입니다.

이건 일부러 Tailwind의 브레이크포인트가 아닙니다. 그리고 직접 쓰는 유틸리티도 경쟁하는 대신 같은 사다리에 올라탈 수 있습니다 — mp-medium:flex, mp-below-expanded:hidden. 왜 이 사다리인지, 또 무엇이 이 사다리를 읽는지, 그리고 옮기는 방법은 브레이크포인트에 전부 있습니다.

Dart에서 반응형 값은 MPResponsive입니다. MPResponsive<int>(4, medium: 12)는 4열에 medium부터 12열이고, MPResponsive<double>.from(expanded: 8)은 바꾸는 클래스만 적으며 그 아래 클래스는 매개변수의 기본값을 따릅니다. span은 MPGridSpan입니다. MPGridSpan(6), MPGridSpan.grow, MPGridSpan.auto처럼 씁니다. 클래스는 MediaQuery로 읽은 창의 것입니다.

머터리얼 자신의 그리드 ​

compact 윈도우에서 4열에 16dp 간격, medium부터 12열에 24dp. 한 줄이면 되고, 그것이 명세가 그리는 레이아웃입니다.

ReactFlutter
tsx
import { MPBox, MPGrid, MPGridItem, MPTypography } from 'material-plus-ui';

/**
 * Material's own layout grid: four columns in a compact window, twelve from
 * medium up, with the gutter widening from 16dp to 24dp at the same moment.
 *
 * Narrow the window — or drag the preview's edge — and the cards go from one a
 * row to two and then to four. Nothing re-renders while that happens: the column
 * count is an inherited custom property, so the media query changes it and the
 * browser reflows on its own.
 */
const ARTICLES = [
  { title: 'Window size classes', meta: 'compact · medium · expanded' },
  { title: 'Columns', meta: '4 · 12 · 12' },
  { title: 'Gutters', meta: '16dp · 24dp · 24dp' },
  { title: 'Margins', meta: '16dp · 24dp · 24dp' }
];

export default function GridResponsive() {
  return (
    <MPGrid
      columns={{ compact: 4, medium: 12 }}
      spacing={{ compact: 4, medium: 6 }}
      style={{ width: '100%' }}
    >
      {ARTICLES.map((article) => (
        <MPGridItem key={article.title} span={{ compact: 4, medium: 6, expanded: 3 }}>
          <MPBox variant="elevated" style={{ height: '100%' }}>
            <MPTypography level="h6" gutter>
              {article.title}
            </MPTypography>
            <MPTypography level="caption">{article.meta}</MPTypography>
          </MPBox>
        </MPGridItem>
      ))}
    </MPGrid>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// Material's own layout grid: four columns in a compact window, twelve from
/// medium up, with the gutter widening from 16dp to 24dp at the same moment.
///
/// Narrow the window and the cards go from four a row to two and then to one.
/// The window size class is read off the window, so the grid changes shape at
/// the same widths as everything else on the screen.
class GridResponsive extends StatelessWidget {
  const GridResponsive({super.key});

  static const List<(String, String)> _articles = <(String, String)>[
    ('Window size classes', 'compact · medium · expanded'),
    ('Columns', '4 · 12 · 12'),
    ('Gutters', '16dp · 24dp · 24dp'),
    ('Margins', '16dp · 24dp · 24dp'),
  ];

  @override
  Widget build(BuildContext context) {
    return SizedBox(
      width: double.infinity,
      child: MPGrid(
        columns: const MPResponsive<int>(4, medium: 12),
        spacing: const MPResponsive<double>(4, medium: 6),
        children: <Widget>[
          for (final (String title, String meta) in _articles)
            MPGridItem(
              span: const MPResponsive<MPGridSpan>(
                MPGridSpan(4),
                medium: MPGridSpan(6),
                expanded: MPGridSpan(3),
              ),
              child: MPBox(
                variant: MPVariant.elevated,
                child: Column(
                  crossAxisAlignment: CrossAxisAlignment.start,
                  children: <Widget>[
                    MPTypography(title, level: MPTypographyLevel.h6, gutter: true),
                    MPTypography(meta, level: MPTypographyLevel.caption),
                  ],
                ),
              ),
            ),
        ],
      ),
    );
  }
}

기본값은 아닙니다. 기본값은 12열에 16dp 간격입니다. 600dp에서 나눗수가 저 혼자 바뀌는 기본값은 휴대폰에서 span={6}의 의미를 소리 없이 바꿔 놓고, 적어 둔 적 없는 폭에 산술이 의존하는 그리드는 화면만 봐서는 읽어 낼 수 없기 때문입니다.

span="grow" ​

열의 개수가 아닌 유일한 폭입니다. 다른 아이템들이 자기 몫을 가져간 뒤 행에 남은 폭을 가져갑니다.

ReactFlutter
tsx
import { MPBox, MPGrid, MPGridItem, MPTypography } from 'material-plus-ui';

/**
 * A thumbnail and the words beside it, which is the layout `span="grow"` is
 * for.
 *
 * The picture is three columns because that is what it is; the body is
 * everything left over, and stays right when the picture's column count
 * changes. Written as two numbers — `span={3}` and `span={9}` — it would be
 * right until somebody edited one of them.
 */
const ARCHIVE = [
  { title: 'Sonic the Hedgehog', meta: '1998 · Flash · 2.1 MB' },
  { title: 'A Duck Has an Adventure', meta: '2012 · Flash · 4.8 MB' }
];

export default function GridGrow() {
  return (
    <MPGrid spacing={4} style={{ width: '100%' }}>
      {ARCHIVE.map((entry) => (
        <MPGridItem key={entry.title} span={12}>
          <MPBox variant="outlined">
            <MPGrid spacing={4} alignItems="center">
              <MPGridItem span={3}>
                <MPBox
                  variant="tonal"
                  style={{ aspectRatio: '4 / 3', display: 'grid', placeItems: 'center' }}
                >
                  <MPTypography level="caption">Thumbnail</MPTypography>
                </MPBox>
              </MPGridItem>

              <MPGridItem span="grow">
                <MPTypography level="h6" gutter>
                  {entry.title}
                </MPTypography>
                <MPTypography level="caption">{entry.meta}</MPTypography>
              </MPGridItem>
            </MPGrid>
          </MPBox>
        </MPGridItem>
      ))}
    </MPGrid>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// A thumbnail and the words beside it, which is the layout `MPGridSpan.grow`
/// is for.
///
/// The picture is three columns because that is what it is; the body is
/// everything left over, and stays right when the picture's column count
/// changes. Written as two numbers, three and nine, it would be right until
/// somebody edited one of them.
class GridGrow extends StatelessWidget {
  const GridGrow({super.key});

  static const List<(String, String)> _archive = <(String, String)>[
    ('Sonic the Hedgehog', '1998 · Flash · 2.1 MB'),
    ('A Duck Has an Adventure', '2012 · Flash · 4.8 MB'),
  ];

  @override
  Widget build(BuildContext context) {
    return SizedBox(
      width: double.infinity,
      child: MPGrid(
        spacing: const MPResponsive<double>(4),
        children: <Widget>[
          for (final (String title, String meta) in _archive)
            MPGridItem(
              span: const MPResponsive<MPGridSpan>(MPGridSpan(12)),
              child: MPBox(
                child: MPGrid(
                  spacing: const MPResponsive<double>(4),
                  alignItems: MPGridAlign.center,
                  children: <Widget>[
                    const MPGridItem(
                      span: MPResponsive<MPGridSpan>(MPGridSpan(3)),
                      child: MPBox(
                        variant: MPVariant.tonal,
                        child: AspectRatio(
                          aspectRatio: 4 / 3,
                          child: Center(
                            child: MPTypography('Thumbnail', level: MPTypographyLevel.caption),
                          ),
                        ),
                      ),
                    ),
                    MPGridItem(
                      span: const MPResponsive<MPGridSpan>(MPGridSpan.grow),
                      child: Column(
                        crossAxisAlignment: CrossAxisAlignment.start,
                        children: <Widget>[
                          MPTypography(title, level: MPTypographyLevel.h6, gutter: true),
                          MPTypography(meta, level: MPTypographyLevel.caption),
                        ],
                      ),
                    ),
                  ],
                ),
              ),
            ),
        ],
      ),
    );
  }
}

썸네일 옆에 본문이 오는 레이아웃이 이것이 있는 이유이고, span으로는 표현할 수 없는 이유는 남은 폭이 그 행의 다른 아이템들이 배치된 뒤에야 정해지기 때문입니다. span={3}과 span={9}는 썸네일의 열 개수가 바뀌어 합이 맞지 않게 되기 전까지만 같은 그림입니다.

한 행의 growing 아이템 둘은 안에 든 내용에 비례하는 것이 아니라 남은 폭을 똑같이 나눠 갖습니다. 예측 가능해지는 쪽의 절반이 이것입니다.

다른 값과 마찬가지로 반응형입니다.

크기가 실행 시점에 정해지는 묶음을 위한 값입니다. 플레이어의 컨트롤 바는 페이지가 무엇을 할 수 있느냐에 따라 아이콘 버튼을 하나에서 다섯 개까지 답니다. 12열 중 몇 열인지는 미리 적어 두어야 하므로, 그 숫자는 너무 작거나 너무 큽니다. 32px 버튼 네 개는 128px가 필요하고 768px 바에서 large: 2가 정확히 128px인데, 서브픽셀 반올림이 깎아 가는 1px 때문에 마지막 버튼이 다음 줄로 넘어가면서 바의 높이가 두 배가 됩니다. 같은 행에 버튼이 하나만 남으면 이번에는 빈 자리가 생깁니다.

offset ​

아이템 앞에 비워 두는 열입니다. 행 안의 절대 위치가 아니라, 앞으로 밀어 넣는 공간입니다.

12열 행의 첫 번째에서 offset={4}에 span={4}면 가운데 3분의 1이 되고, 이미 4열을 가져간 아이템 뒤에서는 같은 offset이 4열을 더 건너뛰어 마지막 3분의 1에 놓입니다. span과 같은 방식으로 반응형입니다.

구현은 margin-inline-start이고, 그 선언은 offset을 실제로 요청한 아이템에만 쓰입니다. 이게 중요한 이유는 이 규칙들이 레이어 밖에 있고 Tailwind 유틸리티는 그렇지 않기 때문입니다. 모든 그리드의 모든 아이템에 대해 0px으로라도 마진을 항상 선언하던 .mp-grid-item은 소비자가 직접 준 m-6을 inline-start 쪽에서만 이겨서, 나머지 세 방향만 남는 마진을 만들었습니다. offset을 주면 마진은 라이브러리의 것이고, 주지 않으면 여러분의 것입니다. 명시적인 offset={0}은 요청한 것으로 세며, 이는 지금까지도 늘 같던 답입니다.

폭이 진짜 CSS인 이유 ​

한 열은 (100% + 간격) * span / columns - 간격이고, 네 개의 폭에서 다시 계산되어야 하며, 그 열 개수는 부모에 선언되어 있는 엘리먼트의 폭입니다.

Tailwind는 이 중 무엇도 표현할 수 없습니다. Tailwind는 소스 텍스트를 훑어서 클래스를 찾는데 columns는 런타임에 호출자가 고르는 숫자이고, JavaScript로 조립한 클래스 이름은 Tailwind가 결코 보지 못하는 클래스 이름입니다. 그래서 산술은 스타일시트에 한 번만 쓰이고, 인스턴스마다 다른 숫자는 인라인 커스텀 프로퍼티로 도착합니다. 이 라이브러리에서 color가 배경까지 도달하는 방식 그대로입니다.

열 개수와 두 간격은 그리드에 선언되어 아이템에게 상속되며, React 컨텍스트로 전달되지 않습니다. 편법이 아닙니다. 미디어 쿼리는 React가 알지 못하는 사이에 상속된 커스텀 프로퍼티를 바꿀 수 있고, 그래서 아이템이 자신을 배치하는 기준이 되는 열 개수는 항상 지금 화면에 실제로 적용된 값입니다. 컨텍스트라면 같은 말을 하기 위해 윈도우 클래스가 바뀔 때마다 하위 트리를 다시 렌더해야 합니다.

행보다 넓은 span은 넘치는 대신 행에 맞춰 잘립니다. span={99}가 의미한 것이 그것이기 때문입니다.

그리드가 자신을 배치하는 방식 ​

한 열은 (폭 + 간격) * span / columns - 간격이고, 그리드가 배치될 때 받은 폭을 기준으로 계산합니다. 그리드는 행을 쌓은 열이 아니라 렌더 객체 하나입니다. span 중 둘은 바깥에서 계산할 수 없기 때문입니다. auto 아이템은 어느 행에 들어갈지 정하기 전에 먼저 재야 하고, grow 아이템은 그 행이 남긴 폭을 가져갑니다. 행을 한곳에서 배치하면 아이템마다 자기 정렬을 가질 수 있고, 기준선 정렬도 여기에 포함됩니다.

열 개수와 간격은 그리드를 만들 때 윈도우 크기 클래스에서 읽고, 창이 경계를 넘으면 다시 만듭니다. 행보다 넓은 span은 행에 맞춰 잘립니다.

MPGridItem은 Expanded가 자기 Row의 자식이어야 하듯 그리드의 직접 자식이어야 합니다. 다른 곳에 놓인 아이템은 자기 자식만 그립니다.

그리드가 일부러 아닌 것들 ​

표면. variant도 color도 패딩도 없습니다. 그리드는 그 안에 있는 표면들의 배치이고, 자기 시트를 그리기 시작하는 순간 페이지의 가장 바깥 요소로는 쓸 수 없게 됩니다. 시트가 필요하면 MPBox나 MPCard로 감싸세요.

페이지 여백. 그건 MPContainer이고, 질문이 서로 다르기 때문에 별개의 컴포넌트입니다. 내용이 창 가장자리에서 얼마나 떨어져 있는가와, 내용이 자기를 어떻게 나누는가는 다른 질문입니다. 컨테이너는 그리드를 담는 것만큼이나 문단 하나도 잘 담고, 그리드에 컨테이너가 반드시 필요하지도 않습니다.

분할 패널. 손잡이로 나뉘는 두 영역이 필요하면 MPPanes를 쓰세요.

중첩 ​

MPGridItem 안의 MPGrid이지, 아이템이면서 동시에 그리드인 것이 아닙니다. 안쪽 그리드는 자기 하위 트리에 대해 열 개수를 다시 선언하고, 그것을 감싼 아이템은 바깥 그리드가 준 폭을 그대로 유지합니다.

그리고 그리드는 span이 더 이상 아무 뜻도 갖지 않는 경계이기도 하며, 그렇게 말합니다. .mp-grid가 자신이 내려보내는 슬롯을 전부 — span, offset, grow, width — initial로 되돌립니다. 이 리셋이 없으면 compact만 선언한 안쪽 아이템이 compact 위의 모든 클래스에서 바깥 아이템의 large를 resolve하게 되어 — span={12}이 실제로 속한 행의 6분의 1로 나옵니다 — 슬롯이 상속되는 커스텀 프로퍼티이기 때문입니다. 쓸 것은 없고, 스타일시트에 들어 있습니다.

둘 사이에 새는 것은 없습니다. 그리드마다 자기 columns를 읽고, 아이템은 자신이 직접 속한 그리드를 기준으로 계산됩니다.

tsx
<MPGrid>
  <MPGridItem span={6}>
    <MPGrid columns={2}>
      <MPGridItem span={1}>페이지의 4분의 1</MPGridItem>
      <MPGridItem span={1}>또 4분의 1</MPGridItem>
    </MPGrid>
  </MPGridItem>
</MPGrid>
dart
const MPGrid(
  children: <Widget>[
    MPGridItem(
      span: MPResponsive<MPGridSpan>(MPGridSpan(6)),
      child: MPGrid(
        columns: MPResponsive<int>(2),
        children: <Widget>[
          MPGridItem(span: MPResponsive<MPGridSpan>(MPGridSpan(1)), child: Text('페이지의 4분의 1')),
          MPGridItem(span: MPResponsive<MPGridSpan>(MPGridSpan(1)), child: Text('또 4분의 1')),
        ],
      ),
    ),
  ],
)

접근성 ​

  • 그리드는 레이아웃이므로 role을 갖지 않고 아무것도 알리지 않습니다. 알리는 것은 그 안의 내용입니다.
  • DOM 순서가 곧 읽히는 순서입니다. offset은 아이템을 문서에서 옮기지 않은 채 행 안에서만 밀어냅니다. 그게 핵심입니다 — 시각적으로만 존재하는 재배치는 스크린 리더가 결코 듣지 못하는 재배치입니다.
  • 배치 자체가 의미를 갖는 경우를 위해 render가 있습니다. 그리드에 render={<ul />}, 아이템에 render={<li />}를 주면 카드 목록이 실제로 목록이 됩니다.
  • 그리드는 레이아웃이므로 시맨틱 트리에 아무것도 더하지 않습니다. 알리는 것은 그 안의 내용입니다.
  • children의 순서가 곧 읽히는 순서입니다. offset은 아이템을 그 순서에서 옮기지 않은 채 행 안에서만 밀어냅니다.
