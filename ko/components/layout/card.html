MPCard ​

카드를 이루는 부분들을 배치한 MPBox입니다. 사진, 제목, 부제, 본문, 푸터 — MD3 자신의 카드 해부도를 슬롯으로 옮긴 것입니다.

ReactFlutter
tsx
import { MPCard, MPButton } from 'material-plus-ui';

<MPCard
  variant="elevated"
  title="주간 요약"
  subtitle="매주 월요일 09:00 발송"
  footer={<MPButton>지금 보내기</MPButton>}
>
  지난 호는 42명이 열어 봤습니다.
</MPCard>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPCard(
  variant: MPVariant.elevated,
  title: const Text('주간 요약'),
  subtitle: const Text('매주 월요일 09:00 발송'),
  footer: MPButton(onPressed: send, child: const Text('지금 보내기')),
  child: const Text('지난 호는 42명이 열어 봤습니다.'),
);

Props ​

Prop타입기본값설명
titleReactNode—카드의 제목. 평범한 문자열은 카드의 제목 역할로 그려지고, 문서 개요에 나타나야 한다면 진짜 제목 엘리먼트(`title={<h3>…</h3>}`)를 넘기세요 — 브라우저가 아니라 카드의 타이포그래피를 물려받습니다
subtitleReactNode—제목 아래 한 줄. 타입 스케일 한 단계 아래이고 한 톤 물러납니다
headerActionReactNode—헤더 행 끝에 고정되는 내용 — 메뉴 버튼, 상태 칩. 제목이 옆에서 줄바꿈되는 동안에도 제목의 줄에 남습니다
mediaReactNode—사진, 차트, 지도. 위쪽에 가장자리까지 그려져 카드의 모서리가 잘라냅니다. 여백이 붙으면 안 되는 유일한 부분이라서 독립된 슬롯입니다
footerReactNode—아래 영역. 줄바꿈되는 행으로 배치되므로 버튼 두 개에 별도의 래퍼가 필요 없습니다
dividersbooleanfalse구획 사이를 여백 대신 실선으로 나눕니다. 선이 시트의 양 끝까지 닿아야 하므로 세로 여백이 카드에서 각 구획으로 옮겨 갑니다
variant'filled' | 'tonal' | 'elevated' | 'outlined' | 'text''outlined'시트가 칠하는 면의 양. 컨테이너의 사다리라서 `filled`도 강조 색이 아니라 MD3의 filled 카드 표면인 `surface-container-highest`입니다 — 남의 내용을 담는 상자를 물들이면 그 내용의 배경이 물듭니다
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'구획들의 안쪽 여백과 본문의 타입 스케일. 모서리는 사다리에 없습니다 — 카드는 어느 단계에서나 `corner-medium`입니다
density0 | -1 | -2 | -30시트와 각 섹션의 여백을 함께 덜어냅니다
elevation0 | 1 | 2 | 3 | 4 | 5—면을 얼마나 띄울지, MD3의 단계 그대로. 그림자와 함께 **색조**도 옮깁니다 — 머터리얼에서 이 둘은 하나의 결정입니다. 값을 주지 않으면 `variant`가 정하고, `variant="elevated"`가 곧 `1`입니다
renderRenderProp—`<div>` 대신 다른 엘리먼트로 렌더링합니다 — `render={<article />}`
childrenReactNode—카드의 본문
transitionMPAnimation | MPTransitionOptions—마운트될 때 한 번 실행되는 등장 효과. `transition="fade"`처럼 이름만 주거나, 지속 시간과 방향과 시작 배율을 담은 객체를 줍니다. 다시 실행돼야 하는 것 — 스크롤, 호버, 직접 제어 — 은 `MPAnimate*` 컴포넌트의 일입니다
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다
Prop타입기본값설명
titleWidget?—카드의 제목. 시트의 제목 역할로 그려지며, `headingLevel`을 주지 않으면 제목으로 읽히지 않습니다
headingLevelint?—제목이 화면 개요에서 몇 단계인지, `1`부터 `6`까지. React에서 `title`에 제목 엘리먼트를 넘기는 자리입니다
subtitleWidget?—제목 아래 한 줄. 타입 스케일 한 단계 아래이고 한 톤 물러납니다
headerActionWidget?—헤더 행 끝에 고정되는 내용 — 메뉴 버튼, 상태 칩. 제목이 옆에서 줄바꿈되는 동안에도 제목의 줄에 남습니다

MPBox의 모든 prop이 그대로 통과하므로, 카드는 자신이기도 한 박스와 정확히 같은 축으로 스타일링됩니다.

카드가 박스의 variant, elevation, size, density를 직접 받으므로 박스와 같은 축으로 스타일링됩니다. footer는 위젯 하나입니다. 버튼 두 개를 넣으려면 Wrap이나 Row로 묶어서 넘기고, 카드는 그것을 같은 8px 간격으로 배치합니다.

구획이 prop인 이유 ​

<MPCard.Header>나 <MPCard.Title>은 없고, 이는 MPDialog와 같은 결정입니다.

카드의 배치는 고정되어 있습니다. 미디어, 제목, 부제, 본문, 액션 순서인데, 그것이 MD3 자신의 해부도이기 때문입니다. 호출자가 정하고 싶은 것은 각 슬롯에 무엇을 넣을지이지 슬롯의 순서가 아니고, compound 서브컴포넌트는 정답이 하나뿐인 순서를 선택지로 내미는 셈입니다.

그리고 그 방식은 누군가 중첩을 잊어서 제목이 조용히 사라진 카드도 함께 제공합니다. 비어 있는 슬롯은 아무것도 그리지 않습니다. 래퍼도, 여백도, 간격도 없습니다.

표면은 MD3의 카드입니다 ​

corner-medium이고, 다섯 variant 중 셋은 명세 자신의 카드 variant 그대로입니다 — filled는 surface-container-highest, elevated는 레벨 1 그림자 아래의 surface-container-low, outlined는 outline-variant 실선입니다.

어느 것도 물들지 않고 color도 없습니다. 근거는 MPBox의 것 그대로입니다. 카드가 담는 것은 남의 내용이고, 그것은 자기 색을 가지고 도착했습니다.

media ​

ReactFlutter
tsx
import { MPButton, MPCard, MPImage } from 'material-plus-ui';

/**
 * `media` is drawn edge to edge across the top, so the card's own corners crop
 * it.
 *
 * It is a slot of its own rather than part of `children` because it is the one
 * part of a card that must not be padded — and because the sheet only clips when
 * there is something to crop, so a card with no picture keeps its focus rings
 * intact.
 */
export default function CardMedia() {
  return (
    <div style={{ display: 'grid', gap: 12, width: '100%', maxWidth: 320 }}>
      <MPCard
        variant="filled"
        title="Sunrise over the terraces"
        subtitle="05:41, from the top of the ridge"
        media={
          <MPImage
            src="/samples/photos/thumbs/misty-tea-terraces-sunrise.webp"
            alt="Rows of tea terraces in low mist, with the sun just over the hills"
            ratio="16 / 9"
          />
        }
        footer={<MPButton variant="text">Open</MPButton>}
      >
        The picture reaches all four edges of the top. Nothing above it is padded.
      </MPCard>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class CardMedia extends StatelessWidget {
  const CardMedia({super.key});

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 320),
      child: MPCard(
        variant: MPVariant.filled,
        title: const Text('Sunrise over the terraces'),
        subtitle: const Text('05:41, from the top of the ridge'),
        media: const MPImage(
          image: NetworkImage('/samples/photos/thumbs/misty-tea-terraces-sunrise.webp'),
          semanticLabel: 'Rows of tea terraces in low mist, with the sun just over the hills',
          ratio: 16 / 9,
        ),
        footer: MPButton(variant: MPVariant.text, onPressed: () {}, child: const Text('Open')),
        child: const Text(
          'The picture reaches all four edges of the top. Nothing above it is padded.',
        ),
      ),
    );
  }
}

위쪽에 가장자리까지 그려지므로, 카드 자신의 모서리가 사진을 잘라냅니다. children의 일부가 아니라 독립된 슬롯인 이유는, 카드에서 여백이 붙으면 안 되는 유일한 부분이기 때문입니다. 다른 구획들이 놓이는 세로 트랙은 미디어 아래에서 시작하므로, 사진이 시트 자신의 여백에 액자처럼 갇히는 일이 없습니다.

카드는 미디어가 있을 때만 잘라냅니다. 모든 카드를 잘라내면 시트 가장자리에 붙은 컨트롤의 포커스 링이 깎여 나가는데, 잘라낼 것이 없는 카드에서는 그 대가로 얻는 게 없습니다.

dividers ​

ReactFlutter
tsx
import { MPButton, MPCard } from 'material-plus-ui';

/**
 * Space or rules, which is one prop and two different trades.
 *
 * Without `dividers` the *sheet* carries the vertical padding and the sections
 * are told apart by a gap. With them each section carries both axes, so a
 * hairline can reach the sheet's own edges — the same trade `MPDialog` makes,
 * and the reason to turn it on is the same: the lines are what say the parts are
 * parts.
 */
export default function CardDividers() {
  return (
    <div style={{ display: 'grid', gap: 16, width: '100%', maxWidth: 420 }}>
      <MPCard title="Separated by space" footer={<MPButton variant="text">Act</MPButton>}>
        The default.
      </MPCard>

      <MPCard dividers title="Separated by rules" footer={<MPButton variant="text">Act</MPButton>}>
        The rules reach both edges, because the padding moved off the sheet and onto each section.
      </MPCard>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

class CardDividers extends StatelessWidget {
  const CardDividers({super.key});

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 420),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        mainAxisSize: MainAxisSize.min,
        spacing: 16,
        children: <Widget>[
          MPCard(
            title: const Text('Separated by space'),
            footer: MPButton(variant: MPVariant.text, onPressed: () {}, child: const Text('Act')),
            child: const Text('The default.'),
          ),
          MPCard(
            dividers: true,
            title: const Text('Separated by rules'),
            footer: MPButton(variant: MPVariant.text, onPressed: () {}, child: const Text('Act')),
            child: const Text(
              'The rules reach both edges, because the padding moved off the sheet and onto '
              'each section.',
            ),
          ),
        ],
      ),
    );
  }
}

기본은 꺼짐입니다. 켜는 것은 선이 하나 생기는 일이 아니라 교환입니다.

끔켬
세로 여백시트가 부담각 구획이 부담
구획 사이간격양 끝까지 닿는 실선

선은 카드 자신의 테두리와 같은 outline-variant라서, 별개의 두 번째 선이 아니라 시트에 새겨진 자국으로 읽힙니다. 첫 구획 위에는 선이 없고, 미디어 아래에도 없습니다. 사진이 이미 구분이기 때문입니다.

카드를 누를 수 없게 한 이유 ​

href도 onClick도 없고, Flutter에는 onPressed도 없습니다.

MD3가 카드를 상호작용할 수 있는 컨테이너로 설명하는 건 맞지만, 카드 전체를 과녁으로 삼는 건 이 카드에 맞지 않는 모양입니다. 제목과 본문과 푸터의 버튼 두 개를 가진 카드가 동시에 커다란 링크 하나이면, 그건 링크 안의 링크이고 HTML 파서가 들어오는 길에 분해해 버립니다. 그러면 모든 키보드 사용자가 스크린 리더로는 설명되지 않는 컨트롤을 만나게 됩니다.

대신 이렇게 하세요.

tsx
// 제목이 링크입니다.
<MPCard title={<MPTextLink href="/digests/42">주간 요약</MPTextLink>}>…</MPCard>

// 또는 푸터가 액션을 들고 있습니다.
<MPCard title="주간 요약" footer={<MPButton onClick={open}>열기</MPButton>}>…</MPCard>

타일 전체가 하나의 과녁인 타일 격자는 다른 컴포넌트이고, 그건 안에 <a>가 들어 있는 평범한 MPBox입니다. 클릭을 두고 경쟁하는 것이 아무것도 없습니다.

dart
// 푸터가 액션을 들고 있습니다.
MPCard(
  title: const Text('주간 요약'),
  footer: MPButton(onPressed: open, child: const Text('열기')),
  child: const Text('…'),
);

타일 전체가 하나의 과녁이어야 한다면 그건 다른 위젯입니다. 안에서 누름을 두고 경쟁하는 것이 없는, 직접 만든 누를 수 있는 표면을 쓰세요.

예시 ​

제목 엘리먼트로서의 title / headingLevel ​

문서 개요에 나타나야 하는 카드에는 진짜 제목이 필요합니다. 넘기면 브라우저의 것이 아니라 카드의 타이포그래피를 그대로 유지합니다.

tsx
<MPCard title={<h3>합계</h3>}>…</MPCard>

평범한 문자열은 일부러 제목으로 만들지 않습니다. 그랬다면 카드가 늘어선 페이지는 렌더링 순서대로 놓인 <h3> 더미가 되는데, 그건 아무도 쓰지 않은 개요입니다.

화면 개요에 나타나야 하는 카드는 제목이 제목으로 읽혀야 합니다. 위젯에는 이를 말할 태그가 없으므로 단계를 제목 옆의 매개변수로 넘기고, 타이포그래피는 카드의 것을 그대로 씁니다.

dart
MPCard(title: const Text('합계'), headingLevel: 3, child: body);

넘기지 않으면 제목은 일부러 제목이 되지 않습니다. 그랬다면 카드가 늘어선 화면은 빌드 순서대로 놓인 제목 더미가 되는데, 그건 아무도 쓰지 않은 개요입니다.

headerAction ​

제목이 옆에서 줄바꿈되는 동안에도 제목의 줄에 남습니다.

tsx
<MPCard title="주간 요약" headerAction={<MPIconButton icon={…} label="더 보기" size="xs" />}>
  …
</MPCard>
dart
MPCard(
  title: const Text('주간 요약'),
  headerAction: MPIconButton(icon: moreIcon, label: '더 보기', size: MPSize.xs, onPressed: openMenu),
  child: body,
);

본문만 있는 카드 ​

모든 슬롯은 선택 사항이고, 아무것도 채우지 않은 카드는 MPBox입니다 — 실제로 그것이기도 합니다.

tsx
<MPCard>시트뿐입니다.</MPCard>
dart
const MPCard(child: Text('시트뿐입니다.'));

접근성 ​

  • 카드는 자기 역할이 없습니다. 표면을 가진 <div>이고, 박스와 같은 이유로 그대로 둡니다. 스크린 리더가 알려야 할 영역에는 이름과 그 이름을 받을 엘리먼트가 필요하며, 그것이 render가 있는 이유입니다.
  • title은 조용히 제목이 되지 않습니다. 카드가 개요에 속한다면 제목 엘리먼트를 넘기세요.
  • 누를 수 있는 것이 없으므로, 여기서 컨트롤 안에 컨트롤이 중첩될 일도 없습니다.
tsx
<MPCard render={<article />} aria-labelledby="digest-title" title={<h3 id="digest-title">…</h3>}>
  …
</MPCard>
  • 카드는 자기 semantics 노드를 만들지 않고 포커스 정지점도 갖지 않습니다. 컨테이너로서 맞는 동작입니다. 스크린 리더가 알려야 할 영역이라면 label을 준 Semantics로 감싸세요.
  • title은 조용히 제목이 되지 않습니다. 카드가 개요에 속한다면 headingLevel을 주세요.
  • 누를 수 있는 것이 없으므로, 여기서 컨트롤 안에 컨트롤이 중첩될 일도 없습니다.

React 빌드와 다른 점 ​

ReactFlutter이유
title={<h3>…</h3>}headingLevel: 3title이 엘리먼트가 아니라 위젯이므로, 개요에서의 깊이는 옆의 매개변수로 받습니다.
footer의 프래그먼트위젯 하나배치할 프래그먼트가 없으므로, 여러 개를 담는 푸터는 직접 Wrap이나 Row로 묶습니다.
transition—등장 효과는 카드를 감싸는 애니메이션 위젯이 맡습니다.
render, className, style—Flutter에는 바꿔 끼울 엘리먼트도, 넘길 클래스 목록이나 style 속성도 없습니다.
