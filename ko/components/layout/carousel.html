MPCarousel ​

슬라이드가 늘어선 띠이고, 그중 하나가 화면에 들어와 있습니다. 브라우저 자신의 스크롤과 CSS 스냅 포인트 위에 세워져서, 스와이프도 트랙패드 드래그도 화살표 키도 제스처 핸들러 없이 동작합니다.

tsx
import { MPCarousel } from 'material-plus-ui';

<MPCarousel label="숲길">
  <img src="/forest-trail.jpg" alt="키 큰 나무 사이로 난 오솔길" />
  <img src="/snowy-cabin.jpg" alt="얼어붙은 개울 옆 눈 덮인 오두막" />
</MPCarousel>;

Props ​

Prop타입기본값설명
childrenReactNode—슬라이드들. 최상위 자식 하나가 슬라이드 하나가 되며, 컴포넌트는 안에서 무엇을 렌더링하든 하나입니다. 조건부 슬라이드가 남긴 `null`과 `false`는 걸러집니다
valuenumber—보이고 있는 슬라이드. 0부터 셉니다. `onValueChange`와 함께 쓰면 controlled입니다
defaultValuenumber0처음 보이는 슬라이드. uncontrolled일 때 씁니다
onValueChange(index: number) => void—인덱스가 움직이는 모든 경로에서 호출됩니다 — 화살표, 표시점, 새 스냅 포인트에 안착한 드래그까지
loopbooleantrue화살표가 마지막에서 처음으로 감기는지. 끄면 양 끝에서 `disabled`가 됩니다 — 시작과 끝이 있는 묶음에는 그쪽이 정직합니다
autoPlaybooleanfalse스스로 넘어갑니다. 호버, 내부 포커스, 백그라운드 탭에서 멈추고, `prefers-reduced-motion`에서는 아예 시작하지 않습니다. live region도 그동안 조용해집니다
intervalnumber5000각 슬라이드가 머무는 시간, 밀리초
arrowsbooleantrue이전/다음 버튼
indicatorsbooleantrue프레임 아래의 위치 표시. 현재 것은 더 큰 점이 아니라 짧은 막대라서, 이웃이 움직이지 않습니다
labelstring'Carousel'캐러셀의 접근성 이름
previousLabelstring'Previous slide'이전 버튼의 접근성 이름
nextLabelstring'Next slide'다음 버튼의 접근성 이름
slideLabel(index: number, count: number) => string(index, count) => `Slide ${index} of ${count}`슬라이드 하나가 스크린 리더에 어떻게 불리는지, 그리고 그 표시점의 이름
variant'filled' | 'tonal' | 'elevated' | 'outlined' | 'text''outlined'프레임이 슬라이드 뒤에 칠하는 면의 양. `text`는 프레임을 아예 그리지 않으므로, 슬라이드가 이미 자기 테두리를 가지고 있을 때 쓰세요
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'화살표와 표시점의 크기, 그리고 화살표가 프레임 가장자리에서 들어온 정도. 슬라이드의 크기는 아닙니다 — 그건 프레임 그 자체입니다
color'primary' | 'secondary' | 'tertiary' | 'error''primary'현재 표시점과 화살표가 읽는 강조 색 계열. 프레임은 다른 컨테이너와 마찬가지로 중립으로 남습니다
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다

스크롤 컨테이너인 이유 ​

이 컴포넌트의 좋은 점은 거의 전부 한 가지 선택에서 따라 나옵니다. 띠는 옮겨지는(translate) 트랙이 아니라 scroll-snap-type이 걸린 진짜 스크롤 컨테이너입니다.

  • 스와이프와 트랙패드 드래그가 동작합니다. 흉내가 아니라 브라우저 자신의 스크롤이기 때문입니다.
  • RTL에서 알아서 반대로 흐릅니다. 스크롤에는 방향이 있고 translate에는 없기 때문입니다.
  • 화살표 키가 동작합니다. 역시 브라우저의 것이고, RTL에서도 올바릅니다. →를 "다음"에 대응시킨 핸들러였다면 그렇지 않았을 겁니다.
  • 변형되는 것이 없습니다. 표면을 움직이지 않는다는 이 라이브러리의 규칙이 공짜로 지켜집니다.

움직임은 scroll-behavior: smooth입니다. 즉 움직임을 줄여 달라고 한 사람은 그 사람을 기억하려고 따로 쓴 두 번째 코드 경로가 아니라 같은 경로에서 즉시 전환을 얻습니다.

최상위 자식 하나가 슬라이드 하나 ​

MPCarouselSlide는 없습니다. <MPCarousel><img /><img /></MPCarousel>이 API의 전부입니다.

컴포넌트가 각 자식을 감싸는 래퍼가 스냅 포인트, 너비, 스크린 리더에 필요한 role="group"/aria-roledescription="slide" 짝을 들고 있습니다. 사진 한 장에 그것들을 잊지 않고 붙이는 일을 호출자에게 시킬 이유는 없습니다. 조건부 슬라이드가 남긴 null이나 false는 걸러지고, 살아남은 것에는 안정적인 key가 붙습니다.

알아 둘 만한 결과가 하나 있습니다. 컴포넌트는 안에서 무엇을 렌더링하든 슬라이드 하나입니다. 슬라이드 셋은 자식 셋이므로, 배열을 반환하는 .map()은 셋이고 셋을 렌더링하는 <Group />은 하나입니다.

autoPlay는 꺼져 있고, 핑계만 있으면 멈춥니다 ​

읽고 있는 동안 움직이는 캐러셀은 웹에서 가장 많은 불만을 받는 패턴이므로, 요청받기 전에는 아무것도 저절로 넘어가지 않습니다. 요청받은 뒤에도 이렇습니다.

멈추는 때이유
포인터가 위에 있을 때누군가 이 슬라이드를 보고 있습니다
안쪽 어딘가에 포커스가 있을 때키보드 사용자가 슬라이드로 들어와 읽고 있습니다
탭이 백그라운드일 때아무도 아무것도 읽고 있지 않습니다
prefers-reduced-motion이 켜져 있을 때읽는 사람이 바로 이것을 하지 말아 달라고 했습니다

live region도 같이 조용해집니다. 5초마다 새 슬라이드 이름을 읽는 영역은 그 페이지에서 스크린 리더를 쓸 수 없게 만듭니다. 그래서 autoPlay 중에는 aria-live="off"이고, 읽는 사람은 스스로 움직였을 때만 위치를 듣습니다.

loop ​

기본은 켜짐입니다. 끄면 화살표가 양 끝에서 감기는 대신 disabled가 되는데, 시작과 끝이 있는 묶음에는 그쪽이 정직합니다. 사진 세 장의 갤러리에는 시작과 끝이 있고, 돌아가는 배너에는 없습니다.

tsx
import { useState } from 'react';
import { MPCarousel, MPChip, MPTypography } from 'material-plus-ui';

/**
 * Driven from outside, and read back from outside.
 *
 * `onValueChange` fires for every way the index can move — an arrow, a mark, a
 * drag that settled on a new snap point — so a caption beside the frame stays in
 * step with a gesture nobody wrote a handler for.
 */
const CITIES = ['Seoul', 'Busan', 'Jeju'];

export default function CarouselControlled() {
  const [index, setIndex] = useState(0);

  return (
    <div style={{ display: 'grid', gap: 12, width: '100%', maxWidth: 480 }}>
      <div style={{ display: 'flex', gap: 8, flexWrap: 'wrap' }}>
        {CITIES.map((city, cityIndex) => (
          <MPChip key={city} selected={cityIndex === index} onClick={() => setIndex(cityIndex)}>
            {city}
          </MPChip>
        ))}
      </div>

      <MPCarousel
        value={index}
        onValueChange={setIndex}
        loop={false}
        variant="filled"
        label="Cities"
      >
        {CITIES.map((city) => (
          <div
            key={city}
            style={{
              display: 'flex',
              alignItems: 'center',
              justifyContent: 'center',
              height: 140
            }}
          >
            <MPTypography level="h4">{city}</MPTypography>
          </div>
        ))}
      </MPCarousel>
    </div>
  );
}

onValueChange는 인덱스가 움직이는 모든 경로에서 호출됩니다. 화살표, 표시점, 새 스냅 포인트에 안착한 드래그까지. 그래서 프레임 옆의 무언가가, 아무도 핸들러를 쓰지 않은 제스처에도 발을 맞출 수 있습니다.

MD3의 언어로 이것이 무엇인지 ​

명세는 캐러셀 레이아웃을 네 가지로 설명합니다. 그중 셋 — hero, multi-browse, uncontained — 은 항목이 프레임 가장자리를 지나갈 때 크기를 바꿉니다. 이건 네 번째입니다. 한 화면에 한 항목, 스냅.

나머지 셋은 스크롤 위치로 구동되는 항목별 변형이고, 그건 다른 컴포넌트이며 이 라이브러리가 아직 제공하지 않습니다. 여기 있는 것은 명세 자신의 부품으로 그렸습니다. 양옆의 filled 아이콘 버튼, 그리고 더 큰 점이 아니라 짧은 막대인 선택 표시자입니다. 후자는 이웃을 움직이지 않는 유일한 처리이기도 합니다. 표시가 확대되는 대신 자기 행을 따라 길어지기 때문입니다.

예시 ​

사진이 아닌 슬라이드 ​

무엇이든 슬라이드가 될 수 있습니다. 카드, 폼 단계, 차트.

tsx
<MPCarousel variant="text" arrows={false} label="설정">
  <MPCard title="1단계">…</MPCard>
  <MPCard title="2단계">…</MPCard>
</MPCarousel>

variant="text"는 프레임을 아예 그리지 않습니다. 슬라이드가 이미 자기 테두리를 가지고 있을 때 쓰세요.

slideLabel ​

스크린 리더가 듣는 문장이자 각 표시점의 이름입니다. 위치와 전체 개수를 받으므로 어떤 언어로든 쓸 수 있습니다.

tsx
<MPCarousel slideLabel={(index, count) => `${count}장 중 ${index}번째`}>…</MPCarousel>

접근성 ​

  • 컴포넌트 전체가 aria-roledescription="carousel"을 가진 region이고, 이름은 label에서 옵니다.
  • 슬라이드 하나하나가 aria-roledescription="slide"를 가진 group이고, 이름은 slideLabel에서 옵니다.
  • 화면 밖 슬라이드는 aria-hidden이 아닙니다. 띠는 스크롤되므로 그 안의 모든 것에 실제로 닿을 수 있고, 탭 순서에는 남아 있는데 aria-hidden인 서브트리는 키보드 사용자가 스크린 리더는 설명을 거부하는 곳에 도착하는 바로 그 버그의 모양입니다.
  • 띠 자체가 포커스를 받으므로 화살표 키가 닿습니다. 브라우저 자신의 스크롤 컨테이너 처리이고, RTL에서도 이미 올바릅니다.
  • 표시점은 이름이 있는 진짜 버튼이며, 현재 것은 aria-current를 가집니다.

함께 보기 ​

  • MPPanes — 넘기는 대신 읽는 사람이 크기를 조절하는 내용.
  • MPAccordion — 하나만 열려 있다는 점이 핵심인 구획들.
  • MPProgressBox — "네 단계 중 세 번째"를 컨트롤이 아니라 표시로 말하는 것.
