MPSidebar ​

본문 옆의 열이고, 창이 그것을 담기에 좁아지면 서랍입니다. MD3의 standard navigation drawer와 modal navigation drawer를 하나의 컴포넌트로 만든 것입니다.

ReactFlutter
tsx
import { MPPageLayout, MPSidebar, MPList, MPListItem } from 'material-plus-ui';

<MPPageLayout sidebar={<MPSidebar title="섹션">…</MPSidebar>}>…</MPPageLayout>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPPageLayout(
  sidebar: MPSidebar(title: const Text('섹션'), child: navigation),
  child: page,
)

하나의 패널, 두 가지 모습 ​

MD3가 긋는 구분 그대로입니다. standard navigation drawer는 레이아웃의 일부이고 내용이 그 주위로 배치됩니다. expanded 창 아래에서는 같은 목적지들이 스크림 위의 modal 서랍으로 도착합니다. 포커스 트랩, Escape, 트리거로 돌아가는 길과 함께.

여기서 둘이 하나의 컴포넌트인 데에는 두 가지 이유가 있습니다.

호출자가 중단점에서 컴포넌트를 바꿔 끼워서는 안 됩니다. 목적지는 같은 목적지이고, 840dp 위에서는 <MPSidebar>를 아래에서는 <MPDrawer>를 그리는 페이지는 목록 두 벌을 관리하는 페이지입니다.

그리고 자식은 어느 쪽이든 한 번만 존재합니다. 컴포넌트가 둘이면 트리 둘이 문서에 들어가고 그중 하나는 숨겨집니다. 스크린 리더는 그것을 두 번 읽고, 폼은 두 번 제출합니다.

ReactFlutter
tsx
import {
  MPHeader,
  MPList,
  MPListItem,
  MPPageLayout,
  MPSidebar,
  MPSidebarTrigger
} from 'material-plus-ui';

/**
 * The same sidebar, below the window size class it collapses at.
 *
 * `collapseBelow="extra-large"` is set so the preview is always on the narrow
 * side of the line — in a real page the default is `expanded`, which is MD3's
 * own answer: a standard navigation drawer is what an expanded window gets, and
 * a compact one gets the same destinations behind a modal drawer.
 *
 * Nothing here is conditional. The trigger hides itself from the breakpoint up
 * with a media query, and the sidebar is one component in both shapes, so the
 * children exist once either way.
 */
export default function SidebarCollapse() {
  return (
    <div style={{ width: '100%', maxWidth: 420 }}>
      <MPPageLayout
        height={220}
        scroll="content"
        collapseBelow="extra-large"
        className="rounded-mp-md border-mp-outline-variant overflow-hidden border"
        header={
          <MPHeader
            size="xs"
            brand={
              <>
                <MPSidebarTrigger size="xs" />
                Acme
              </>
            }
          />
        }
        sidebar={
          <MPSidebar title="Sections" size="sm">
            <MPList variant="text" size="sm">
              <MPListItem onClick={() => {}}>Overview</MPListItem>
              <MPListItem onClick={() => {}}>Schedule</MPListItem>
              <MPListItem onClick={() => {}}>Reports</MPListItem>
            </MPList>
          </MPSidebar>
        }
      >
        <div className="text-mp-body-medium text-mp-on-surface-variant p-4">
          Press the hamburger. The column is a drawer at this width, and the trigger exists exactly
          while the column does not.
        </div>
      </MPPageLayout>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// The same sidebar, below the window size class it collapses at.
///
/// `collapseBelow: MPPageCollapse.extraLarge` is set so the preview is always
/// on the narrow side of the line. In a real screen the default is
/// `expanded`, which is MD3's own answer: a standard navigation drawer is what
/// an expanded window gets, and a compact one gets the same destinations
/// behind a modal drawer.
///
/// Nothing here is conditional. The trigger draws itself exactly while the
/// column does not, and the sidebar is one widget in both shapes, so the
/// children exist once either way.
class SidebarCollapse extends StatelessWidget {
  const SidebarCollapse({super.key});

  @override
  Widget build(BuildContext context) {
    final MPThemeData theme = MPTheme.of(context);
    final MPColorScheme colors = theme.colors;
    final BorderRadius corner = BorderRadius.circular(theme.shapes.medium);

    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 420),
      child: SizedBox(
        width: double.infinity,
        height: 220,
        child: DecoratedBox(
          position: DecorationPosition.foreground,
          decoration: BoxDecoration(
            border: Border.all(color: colors.outlineVariant),
            borderRadius: corner,
          ),
          child: ClipRRect(
            borderRadius: corner,
            child: MPPageLayout(
              collapseBelow: MPPageCollapse.extraLarge,
              header: const MPHeader(
                size: MPSize.xs,
                brand: <Widget>[
                  MPSidebarTrigger(size: MPSize.xs),
                  Text('Acme'),
                ],
              ),
              sidebar: MPSidebar(
                title: const Text('Sections'),
                size: MPSize.sm,
                child: MPList(
                  variant: MPVariant.text,
                  size: MPSize.sm,
                  children: <Widget>[
                    MPListItem(onPressed: () {}, child: const Text('Overview')),
                    MPListItem(onPressed: () {}, child: const Text('Schedule')),
                    MPListItem(onPressed: () {}, child: const Text('Reports')),
                  ],
                ),
              ),
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Text(
                  'Press the hamburger. The column is a drawer at this width, and the trigger '
                  'exists exactly while the column does not.',
                  style: theme.typescale.bodyMedium.style(colors.onSurfaceVariant),
                ),
              ),
            ),
          ),
        ),
      ),
    );
  }
}

열이 서랍이 되는 윈도우 크기 클래스입니다. MPPageLayout에서 두 사이드바 몫으로 한 번 정해져 내려오고, expanded는 MD3 자신의 답입니다. 명세는 standard 서랍을 expanded 창에 주고, 그 아래에는 같은 목적지를 modal 서랍 뒤에 둡니다.

레이아웃 밖에서 기본값은 none이고, 이는 의도적인 거절입니다. 페이지의 무엇도 되돌릴 수 없는 채로 접힌 사이드바는 독자가 잃어버린 사이드바입니다. 되돌리는 것은 MPSidebarTrigger이고, 그것은 이야기할 레이아웃이 필요합니다.

어느 쪽이 보이는지는 일부러 두 번 답합니다 ​

첫 페인트는 CSS가, 그다음부터는 JavaScript가 답합니다.

서버가 보내는 마크업은 열입니다. 접힌 사이드바는 modal 서랍이고, modal 서랍은 document.body로 가는 포털이며, 마크업을 렌더링하는 동안에는 포털로 들어갈 body가 없기 때문입니다. 그래서 좁은 화면은 전체 폭 사이드바를 그렸다가 잠시 뒤 버리게 됩니다. 중단점 아래에서 열을 숨기는 클래스가 그것을 막고, 물어볼 창이 생긴 뒤에 서랍이 존재해야 한다고 결정하는 것이 matchMedia입니다.

휴대폰 폭의 크롤러 ​

접힌 사이드바는 닫힌 모달 서랍이고, 닫힌 서랍은 페이지에 없습니다. 그래서 collapseBelow보다 좁으면 사이드바의 링크가 크롤러가 휴대폰 폭으로 렌더링하는 문서에서 빠지고, 모바일 페이지를 색인하는 검색 엔진은 그 링크를 보지 못합니다. keepMounted를 주면 서랍이 닫혀 있는 동안에도 링크가 숨겨진 채로 문서에 남습니다. 사이트 내비게이션 역할을 하는 사이드바에 주세요.

어느 쪽이 보이는지는 한 번 답합니다 ​

폭은 첫 프레임에 이미 알려져 있으므로, 사이드바는 필요한 모습만 짓습니다. 레이아웃 안에서는 레이아웃이 받은 폭을, 자기 collapseBelow를 가진 단독 사이드바는 창의 폭을 읽습니다.

서랍은 자기 쪽 가장자리에서 들어옵니다. 앞쪽 사이드바라면 영어에서는 left, 아랍어에서는 right입니다. 열려 있는 동안 포커스를 안에 붙잡아 두고, Escape, 시스템 뒤로 가기, 스크림, 닫기 버튼 어느 것으로든 닫히며, 닫히면 포커스가 원래 자리로 돌아갑니다.

표면 ​

컨테이너의 사다리입니다. 사이드바는 남의 내용을 담고, 사이드바를 물들이면 그 내용이 물듭니다.

기본값은 outlined입니다. 페이지 자신의 표면에, 내용을 마주 보는 가장자리의 실선 하나. 바깥 가장자리는 창에 붙어 있고 그 반대편에는 나뉠 것이 없습니다 — MPHeader와 MPDrawer가 긋는 것과 같은, 가장자리 하나의 규칙입니다.

접히고 나면 여기서 정한 무게는 적용되지 않습니다. 그때 화면에 있는 것은 MPDrawer이고, 서랍은 MD3 자신의 navigation drawer 표면 — 레벨 1 그림자 아래의 surface-container-low — 을 칠합니다. 그 시점에 패널은 옆에 앉아 있는 것이 아니라 페이지를 덮었기 때문입니다.

폭, 그리고 크기 조절 ​

size는 열의 기본 폭이고 md는 360px입니다. MD3 자신의 navigation drawer이자 MPDrawer가 그려지는 것과 같은 단이므로, 사이드바는 자신이 되는 서랍과 정확히 같은 폭입니다.

 * The drag writes the width straight onto the element rather than into state,

import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// `resizable` puts a handle on the inner edge, the one facing the content.
///
/// The drag writes the width into a notifier rather than into state, because
/// nothing in the tree depends on the number except one box and a `setState`
/// per pointer move would rebuild every row in the sidebar. What the caller
/// hears is `onResize` while it moves and `onResizeEnd` when it is let go,
/// which is the number worth storing.
///
/// The handle takes the focus, so the arrow keys move it too.
class SidebarResizable extends StatefulWidget {
  const SidebarResizable({super.key});

  @override
  State<SidebarResizable> createState() => _SidebarResizableState();
}

class _SidebarResizableState extends State<SidebarResizable> {
  double _width = 200;

  @override
  Widget build(BuildContext context) {
    final MPThemeData theme = MPTheme.of(context);
    final BorderRadius corner = BorderRadius.circular(theme.shapes.medium);

    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 480),
      child: SizedBox(
        width: double.infinity,
        height: 200,
        child: DecoratedBox(
          position: DecorationPosition.foreground,
          decoration: BoxDecoration(
            border: Border.all(color: theme.colors.outlineVariant),
            borderRadius: corner,
          ),
          child: ClipRRect(
            borderRadius: corner,
            child: MPPageLayout(
              collapseBelow: MPPageCollapse.none,
              sidebar: MPSidebar(
                size: MPSize.sm,
                width: 200,
                minWidth: 120,
                maxWidth: 320,
                resizable: true,
                onResizeEnd: (double width) => setState(() => _width = width),
                child: const MPTypography('Drag the inner edge', level: MPTypographyLevel.caption),
              ),
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: MPTypography('Settled at ${_width.round()}px.'),
              ),
            ),
          ),
        ),
      ),
    );
  }
}

resizable은 안쪽 가장자리에 핸들을 놓습니다. 가장자리 안에 들어앉는 대신 걸쳐 있습니다 — 1픽셀짜리 실선은 1픽셀짜리 과녁이고, 그건 과녁이 아닙니다 — 그리고 탭 정지를 가진 진짜 separator라서 방향키로도 움직입니다.

드래그는 폭을 상태가 아니라 엘리먼트에 곧장 씁니다. 트리에서 그 숫자에 의존하는 것은 CSS 선언 하나뿐이고, 포인터가 움직일 때마다 setState를 하면 그 하나를 바꾸자고 사이드바의 모든 행을 다시 렌더링하게 됩니다. 호출자가 듣는 것은 매 단계의 onResize와 멈췄을 때의 onResizeEnd이고, 저장할 값어치가 있는 것은 두 번째입니다. 독자가 고른 폭은 다시 찾을 것을 기대하는 폭이니까요.

드래그는 폭을 setState가 아니라 ValueNotifier에 씁니다. 열에서 그 숫자에 의존하는 것은 SizedBox 하나뿐이고, 포인터가 움직일 때마다 다시 빌드하면 그 하나를 바꾸자고 사이드바의 모든 행을 다시 빌드하게 됩니다. 호출자가 듣는 것은 매 단계의 onResize와 멈췄을 때의 onResizeEnd이고, 저장할 값어치가 있는 것은 두 번째입니다. 위젯에 새 width를 주면 드래그한 폭보다 그 값이 우선합니다.

명시한 width는 모양이 바뀌어도 살아남고, 기본 폭은 그러지 않습니다. 옆의 기사에 맞춰 잰 열의 폭과 휴대폰에 맞춰 잰 패널의 폭은 다른 숫자이고, 두 번째는 서랍 자신의 사다리가 이미 알고 있습니다.

페이지 레이아웃의 내용 안에 둔 사이드바는 이름은 그대로 두고 complementary 역할은 내려놓습니다. Flutter는 주 영역 안에 그 역할을 허용하지 않습니다.

접근성 ​

  • 열은 <aside>이고 complementary 랜드마크입니다. 스스로 이름을 붙입니다 — 이름 없는 것이 둘인 페이지는 스크린 리더가 "complementary" 영역을 둘 내놓는 페이지입니다 — 그리고 label이 그 기본값을 대체합니다.
  • 서랍은 다이얼로그이고 항상 제목을 갖습니다. 열이었을 때는 필요 없었더라도 그렇습니다. 제목 없는 다이얼로그에는 접근 가능한 이름이 없기 때문입니다.
  • 크기 조절 핸들은 이름과 탭 정지와 방향키를 가진 separator입니다. 드래그로만 되는 핸들은 키보드가 닿지 못하는 컨트롤입니다.
  • 안에 들어가는 것의 마크업은 여러분의 몫입니다. 목적지 목록에는 <nav>를 둘러 주세요. 그래야 스크린 리더가 그것을 별도의 영역으로 내놓습니다.
  • 열은 SemanticsRole.complementary를 맡고 스스로 이름을 붙이며, label이 그 기본값을 대체합니다. 페이지 레이아웃의 내용 안에서는 이름은 두고 역할은 내려놓습니다. Flutter는 주 영역 안에 그 역할을 허용하지 않습니다.
  • 서랍은 포커스를 붙잡아 두는 레이어이고 항상 제목을 갖습니다. 열이었을 때는 필요 없었더라도 그렇습니다. title이 없으면 사이드바의 이름이 제목이 되고 레이어의 이름도 됩니다.
  • 크기 조절 핸들은 이름, 포커스 정지점, 방향키, 늘리기와 줄이기 동작을 가진 슬라이더입니다. 드래그로만 되는 핸들은 키보드가 닿지 못하는 컨트롤입니다.
  • 트리거의 이름은 상태를 따라 바뀌고, aria-expanded처럼 서랍이 펼쳐졌는지 알립니다.
  • 안에 들어가는 것의 마크업은 여러분의 몫입니다.

함께 보기 ​

  • MPPageLayout — 슬롯 둘을 가진 뼈대.
  • MPDrawer — 이것이 되는 패널이고, 일부가 될 레이아웃이 없을 때 바로 손에 잡을 것.
  • MPHeader — 트리거가 들어갈 자리.
  • MPBottomNavigation — 목적지가 적을 때 MD3가 서랍 대신 내놓는 compact 창의 패턴.
  • MPShow — 사이드바 자신의 접힘이 다루지 않는 페이지의 나머지에서, 한 배치만 보이고 다른 배치는 보이지 않게 하기.
  • 브레이크포인트 — collapseBelow의 클래스가 시작하는 지점과, 옮기는 방법.
