MPColorPicker ​

눈으로 고르는 색입니다. 채도 사각형과 그 옆의 색조 레일 — 모든 디자인 도구가 결국 정착한 배치이고, 한 번의 포인터 움직임 안에 한 색조의 모든 색을 넣어 주는 유일한 배치이기 때문입니다.

tsx
import { MPColorPicker } from 'material-plus-ui';

<MPColorPicker label="태그 색" value={colour} onValueChange={setColour} />;

Props ​

Prop타입기본값설명
valuestring—색. CSS 문자열입니다. 넘기면 picker를 직접 몰게 됩니다
defaultValuestring'#00639b'uncontrolled picker의 시작값
onValueChange(value: string) => void—`format`으로 쓰인 새 색과 함께
format'hex' | 'rgb' | 'hsl''hex'값이 어떤 표기로 나갈지
alphabooleanfalse불투명도 레일을 더하고, 값이 네 번째 채널을 갖게 합니다
swatchesreadonly string[] | false—패널 아래의 미리 준비된 색. `false`면 그리지 않고, 배열이면 기본 세트를 대체합니다. 기본 세트가 라이브러리의 네 계열이 *아닌* 것은 그것들이 의미를 가진 role이고, picker에게 묻는 것은 의미가 아니라 색이기 때문입니다
inlinebooleanfalse팝업 대신 페이지 안에 패널을 그립니다. 트리거가 없습니다
editablebooleantrue패널 아래에 값을 직접 입력할 수 있는 필드
labelReactNode—외곽선 노치 안의 라벨. `inline`이면 패널 위. 고른 색이 없고 포커스도 없는 동안에는 트리거 줄 위에 내려와 있습니다 — `floatingLabel` 참고
floatingLabelbooleantrue비어 있는 동안 라벨을 트리거 줄에 내려두고 포커스나 첫 색에서 홈으로 올릴지 여부. 견본은 라벨과 함께 내려갑니다 — 색이 없는 견본은 빈 고리일 뿐이라, 라이브러리에서 유일하게 내려온 라벨에게 자리를 내주는 앞머리 표식입니다. `inline`이면 무시됩니다
descriptionReactNode—컨트롤 아래 한 줄. `errorMessage`가 있으면 그쪽으로 대체됩니다
errorMessageReactNode—컨트롤 아래 메시지. 이 값이 있으면 컨트롤 전체가 오류 상태가 되므로, 설명 없는 오류는 만들 수 없습니다
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'컨트롤의 크기와 타입 스케일. `md`가 머터리얼 본래의 크기이고, 나머지 네 단계는 이 라이브러리의 것입니다
fullWidthbooleanfalse컨테이너 너비만큼 늘어납니다
requiredbooleanfalse필수 입력으로 표시합니다. 라벨과 보조기술 양쪽에 반영됩니다
disabledbooleanfalse컨트롤을 비활성화하고 입력을 받지 않습니다
readOnlybooleanfalse값을 보여주되 바꾸지 못하게 합니다. `disabled`와 달리 탭 순서에 남습니다
clearablebooleanfalse컨트롤을 비우는 ×를 답니다
namestring—폼 컨트롤의 이름. 값은 `format`으로 쓰인 문자열로 제출됩니다
openboolean—팝업의 열림 여부. controlled로 쓸 때

idstring—컨트롤에 붙고 라벨이 가리키는 id. 생략하면 자동 생성됩니다

이것은 테마가 아닙니다 ​

여기서 고른 색은 데이터입니다. 태그의 색, 캘린더의 색, 프로젝트의 색. --mp-source-color가 아니고, 런타임에 라이브러리를 다시 테마하는 방법도 아닙니다. 그쪽은 색상입니다.

picker는 스킴의 네 계열을 스와치로 제공하지도 않습니다. 그것들은 의미를 가진 role이고 — primary는 "이 화면에서 가장 중요한 것"을 뜻합니다 — 여기서 그것을 내주는 것은 누군가 애플리케이션을 다시 테마하는 순간 사용자 눈앞에서 움직이는 네 가지 색을 내주는 일입니다.

패널의 상태는 HSV이고, 거기서 벗어나지 않습니다 ​

그것이 포인터가 검은 구석에 있을 때 색조 레일을 가만히 있게 하는 것입니다. RGB를 거치면 모든 검정은 같은 색이고, 사각형 바닥에 닿는 순간 레일이 빨강으로 튀게 됩니다.

값은 모델에서 유도되지 그 반대가 아니며, 들어온 value는 모델이 이미 뜻하는 것과 다른 말을 할 때만 모델을 다시 심습니다 — 문자열이 아니라 색으로 비교합니다. #FF0000과 #ff0000은 두 가지로 적힌 같은 색이기 때문입니다.

이 아래에 색 라이브러리는 없습니다. 변환은 백 줄 남짓의 산술이고, 그것이 이 패키지가 아직 런타임 의존성 하나로 남아 있는 이유입니다.

예시 ​

format과 swatches ​

tsx
import { MPColorPicker } from 'material-plus-ui';

/**
 * `format` decides which notation comes back out, and `swatches` puts the
 * handful of colours a product actually uses one click away. `false` draws
 * none.
 */
export default function ColorPickerFormat() {
  return (
    <div style={{ display: 'grid', gap: 20, justifyItems: 'start' }}>
      <MPColorPicker label="Hex" defaultValue="#7c3aed" format="hex" />
      <MPColorPicker label="RGB" defaultValue="#7c3aed" format="rgb" alpha />
      <MPColorPicker
        label="Brand only"
        defaultValue="#0f766e"
        format="hsl"
        swatches={['#0f766e', '#7c3aed', '#b91c1c', '#a16207']}
        editable={false}
      />
    </div>
  );
}

format은 값이 어떤 표기로 나갈지 정합니다. hex는 불투명할 때 alpha 쌍을 떼고, 두 함수형 표기도 같은 이유로 네 번째 인자를 뗍니다 — alpha를 켠 적 없는 호출자가 세 채널만 쓴 컨트롤에서 rgba(…, 1)을 보게 되어서는 안 됩니다.

swatches는 제품이 실제로 쓰는 몇 가지 색을 한 번의 클릭 거리에 둡니다. false면 그리지 않습니다.

floatingLabel ​

색이 없고 트리거에 포커스도 없는 동안 라벨은 트리거 자신의 줄 위에 내려와 있다가 포커스나 첫 색에서 노치로 올라갑니다. 규칙 전체는 MPTextField에 있습니다.

견본도 함께 내려갑니다. 라이브러리에서 앞머리 표식이 자리를 내주는 컨트롤은 이것 하나뿐입니다. 다른 곳에서 값 앞의 표식은 어포던스입니다 — 달력 글리프는 트리거를 누르면 달력이 열린다고 말합니다 — 그래서 자리를 지키고 라벨을 밀어냅니다. 견본은 값을 그린 것입니다. 피커에 색이 없으면 아무 말도 하지 않는 빈 고리이므로, 자리를 내주었다가 라벨과 함께 돌아옵니다.

inline ​

트리거 없이 패널을 페이지 안에 그립니다. picker가 폼 속 필드가 아니라 내용 자체인 사이드바나 설정 화면을 위한 것입니다.

tsx
import { useState } from 'react';
import { MPColorPicker, MPTypography } from 'material-plus-ui';

/**
 * `inline` draws the panel in the page with no trigger at all — for a sidebar
 * or a settings pane, where the picker is the content rather than a field in a
 * form.
 */
export default function ColorPickerInline() {
  const [color, setColor] = useState('rgba(0, 99, 155, 0.75)');

  return (
    <div style={{ display: 'grid', gap: 12, justifyItems: 'start' }}>
      <MPColorPicker
        label="Brand"
        inline
        alpha
        format="rgb"
        value={color}
        onValueChange={setColor}
      />
      <MPTypography level="caption">{color}</MPTypography>
    </div>
  );
}

alpha ​

세 번째 레일을 더하고 값이 네 번째 채널을 갖게 합니다. 레일은 체커보드 위에 그려지는데, 일부만 존재하는 색을 정직하게 보여주는 방법은 그것뿐입니다.

editable ​

패널 아래의 필드입니다. 이해할 수 있는 색을 입력하면 패널이 움직이고, 그 외의 것을 입력하면 패널은 그대로 있고 입력한 글자만 보입니다.

labels ​

picker가 지어내야 하는 여섯 문자열입니다. 채도 사각형에는 이름을 가져올 데가 없기 때문입니다. 하나의 prop에 모은 것은 그것들이 한 묶음이기 때문입니다. 다른 언어를 쓰는 애플리케이션은 각자 영어를 기본값으로 갖고 각자 override prop이 필요한 컴포넌트 여섯 개를 원하지 않습니다.

접근성 ​

  • 사각형과 두 레일은 모두 slider이고 화살표 키로 움직입니다. Shift는 라이브러리의 다른 곳과 마찬가지로 열 칸씩 움직입니다.
  • 트리거는 MPSelect와 똑같이 노치의 라벨로 이름이 붙습니다.
  • 고른 스와치 위의 체크는 검정이거나 흰색이고, 아래 스와치의 상대 휘도가 그것을 정합니다. 고정된 흰 체크는 노란색 위에서 사라집니다.

함께 보기 ​

  • MPSelect — 이것이 빌려 쓰는 트리거.
  • 색상 — 이것이 설정하지 않는, 라이브러리 자신의 스킴.
