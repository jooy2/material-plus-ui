MPSelect ​

목록에서 값 하나를 고릅니다. 트리거는 `MPTextField`의 껍데기에 chevron을 단 것입니다 — 같은 홈이 파인 외곽선, 홈에 놓인 같은 라벨, 같은 보조 텍스트. 그래서 폼 안의 드롭다운이 주변 필드들과 같은 물건이 됩니다.

ReactFlutter
tsx
import { MPSelect } from 'material-plus-ui';

const [city, setCity] = useState(null);

<MPSelect
  label="도시"
  items={[
    { value: 'kr-11', label: '서울' },
    { value: 'jp-13', label: '도쿄' }
  ]}
  value={city}
  onValueChange={setCity}
/>;

옵션이 데이터인 이유 ​

조합해서 쓰는 <MPSelect.Option>은 없고, 그건 편법이 아닙니다.

목록은 팝업이 마운트되기도 전에 트리거에서 필요합니다. 그렇지 않으면 닫힌 셀렉트는 원본 값밖에 보여 줄 수 없고, "서울"이라고 말해야 할 필드가 kr-11이라고 말하며 앉아 있게 됩니다. children으로는 이걸 할 수 없습니다. 팝업이 열리기 전까지 존재하지 않으니까요.

조합해서 쓰는 옵션 위젯은 없고, 그건 편법이 아닙니다.

목록은 팝업이 빌드되기도 전에 트리거에서 필요합니다. 그렇지 않으면 닫힌 셀렉트는 원본 값밖에 보여 줄 수 없고, "서울"이라고 말해야 할 필드가 kr-11이라고 말하며 앉아 있게 됩니다. 자식 위젯으로는 이걸 할 수 없습니다. 팝업이 열리기 전까지 행이 빌드되지 않으니까요.

게다가 호출하는 쪽은 이미 배열을 갖고 있는 경우가 대부분입니다. 옵션은 손으로 쓰이는 것보다 API나 상수에서 오는 일이 훨씬 많습니다.

값이 될 수 있는 것 ​

string 또는 number입니다. 임의의 객체는 의도적으로 받지 않습니다.

String 또는 num입니다. 임의의 객체는 의도적으로 받지 않습니다. Dart에는 유니언 타입이 없어서 MPSelectValue는 Object의 별칭이고, 값은 ==로 비교합니다.

셀렉트는 폼 컨트롤이고 그 값은 폼이 제출하는 것입니다. 거기서 벗어나는 모든 장치 — 객체 값, 커스텀 동등성 비교, 트리거용 문자열 변환기 — 는 유연성을 사면서 흔한 경우를 더 쓰기 어렵게 만듭니다. 여기에는 식별자를 두고, 객체는 반대편에서 찾으세요.

고르지 않음은 null입니다. 0도, ''도, -1도 아닙니다. items에 짝이 없는 값은 보여 줄 라벨이 없으므로 트리거가 값 자체를 그립니다 — "아직 안 고름"을 0으로 들고 있는 폼은 독자가 채워야 할 그 필드에 0이라고 적어 놓게 됩니다.

값이 실재하고 그 행이 아직 도착하지 않은 경우에는 이쪽이 옳은 답입니다. 들고 있고 제출까지 할 값에 대해 아무 말도 하지 않는 필드가 더 나쁩니다. 다만 센티널에 대해서는 옳은 답이 아니며, MUI의 Select는 같은 상황에서 빈 칸을 그리므로 옮겨 오는 길에 걸려들기 쉽습니다.

예시 ​

errorMessage ​

별도의 error boolean은 없습니다. 메시지가 곧 오류 상태를 만들므로, 왜 잘못되었는지 설명 없이 잘못되어 보이기만 하는 컨트롤은 만들 수 없습니다.

ReactFlutter
tsx
import { useState } from 'react';
import { MPSelect, MPIcon, ICONS } from 'material-plus-ui';
import type { MPSelectValue } from 'material-plus-ui';

const PLANS = [
  { value: 'free', label: 'Free' },
  { value: 'pro', label: 'Pro' },
  { value: 'team', label: 'Team' }
];

/**
 * The three things a select can be, and the one it cannot.
 *
 * There is no `error` boolean: a message is what puts the control into its error
 * state, so there is no way to render a select that is visibly wrong with no
 * explanation of why. Clear the first one to see it recover.
 */
export default function SelectStates() {
  const [plan, setPlan] = useState<MPSelectValue | null>(null);

  return (
    <div style={{ display: 'grid', gap: 20, maxWidth: 280 }}>
      <MPSelect
        items={PLANS}
        label="Plan"
        placeholder="Choose a plan"
        value={plan}
        onValueChange={setPlan}
        errorMessage={plan ? undefined : 'Pick a plan to continue.'}
        required
        fullWidth
      />
      <MPSelect
        items={PLANS}
        label="Plan"
        defaultValue="pro"
        description="You can change this at any time."
        startIcon={<MPIcon icon={ICONS.info} size={20} />}
        fullWidth
      />
      <MPSelect items={PLANS} label="Plan" defaultValue="team" disabled fullWidth />
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

import 'package:material_plus_ui_example/demos/glyphs_display.dart';

const List<MPSelectOption> _plans = <MPSelectOption>[
  MPSelectOption(value: 'free', label: Text('Free')),
  MPSelectOption(value: 'pro', label: Text('Pro')),
  MPSelectOption(value: 'team', label: Text('Team')),
];

/// The three things a select can be, and the one it cannot.
///
/// There is no `error` flag: a message is what puts the control into its error
/// state, so there is no way to draw a select that is visibly wrong with no
/// explanation of why. Choose a plan in the first one to see it recover.
class SelectStates extends StatefulWidget {
  const SelectStates({super.key});

  @override
  State<SelectStates> createState() => _SelectStatesState();
}

class _SelectStatesState extends State<SelectStates> {
  MPSelectValue? _plan;

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 280),
      child: Column(
        mainAxisSize: MainAxisSize.min,
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 20,
        children: <Widget>[
          MPSelect(
            items: _plans,
            label: const Text('Plan'),
            placeholder: const Text('Choose a plan'),
            value: _plan,
            onChanged: (MPSelectValue? next) => setState(() => _plan = next),
            errorMessage: _plan == null ? const Text('Pick a plan to continue.') : null,
            required: true,
            fullWidth: true,
          ),
          const MPSelect(
            items: _plans,
            label: Text('Plan'),
            initialValue: 'pro',
            description: Text('You can change this at any time.'),
            startIcon: MPIcon(icon: InfoGlyph(), size: 20),
            fullWidth: true,
          ),
          const MPSelect(
            items: _plans,
            label: Text('Plan'),
            initialValue: 'team',
            disabled: true,
            fullWidth: true,
          ),
        ],
      ),
    );
  }
}

description은 같은 자리이고, errorMessage는 그 아래 쌓이는 것이 아니라 그것을 대체합니다. 머터리얼은 보조 텍스트에 한 줄을 줍니다. 자리를 만들려고 설명을 아래로 밀면, 읽는 사람은 방금 적용되지 않게 된 문장을 읽고 있게 됩니다.

비활성 옵션 ​

옵션은 선택 불가능하면서도 목록에 남을 수 있습니다.

tsx
items={[
  { value: 'free', label: 'Free' },
  { value: 'team', label: 'Team', disabled: true }
]}
dart
items: const <MPSelectOption>[
  MPSelectOption(value: 'free', label: Text('Free')),
  MPSelectOption(value: 'team', label: Text('Team'), disabled: true),
],

지우지 않고 남기는 것은 의도입니다. "있지만 당신에게는 아님"과 "없음"은 다른 말이고, 동료가 말한 요금제가 왜 안 보이는지 설명해 주는 쪽은 하나뿐입니다.

floatingLabel ​

고른 값이 없고 팝업도 닫혀 있는 동안 라벨은 플레이스홀더가 있을 자리, 즉 트리거 자신의 줄 위에 내려와 있다가 포커스나 첫 선택에서 노치로 올라갑니다. placeholder는 그때까지 보류됩니다 — 한 상자 안의 회색 문자열 두 개는 힌트가 아닙니다. 규칙 전체는 MPTextField에 있습니다.

팝업이 열려 있는 것도 포커스로 칩니다. Base UI가 포커스를 목록 안으로 옮기기 때문에, 트리거만 보는 라벨이라면 사용자가 한창 고르는 중에 다시 내려와 버립니다.

floatingLabel={false}는 라벨을 노치에 고정하고, startIcon이 있으면 어느 쪽이든 노치에 남습니다 — 글리프가 내려온 라벨이 설 자리에 이미 서 있기 때문입니다.

팝업이 열려 있는 것도 포커스로 칩니다. 그래서 목록이 열려 있는 동안에는 포커스가 어디에 있든 라벨이 올라가 있습니다.

floatingLabel: false는 라벨을 노치에 고정하고, startIcon이 있으면 어느 쪽이든 노치에 남습니다 — 글리프가 내려온 라벨이 설 자리에 이미 서 있기 때문입니다.

size ​

다섯 단계이고 텍스트 필드가 그려지는 것과 같은 단계입니다. 같은 size의 필드 옆에 놓인 셀렉트는 픽셀 단위로 맞춰집니다. 껍데기를 공유하는 이유가 그것입니다.

ReactFlutter
tsx
import { MPSelect } from 'material-plus-ui';
import type { MPSize } from 'material-plus-ui';

const PLANS = [
  { value: 'free', label: 'Free' },
  { value: 'pro', label: 'Pro' },
  { value: 'team', label: 'Team' }
];

/**
 * The same five rungs a text field is drawn at.
 *
 * A select and a field at the same `size` line up to the pixel, which is the
 * whole reason the shell is shared — put one of each in a filter bar and the row
 * is a row rather than two controls that nearly agree.
 */
const SIZES: { size: MPSize; note: string }[] = [
  { size: 'xs', note: '32px' },
  { size: 'sm', note: '40px' },
  { size: 'md', note: '56px — the default' },
  { size: 'lg', note: '64px' },
  { size: 'xl', note: '72px' }
];

export default function SelectSizes() {
  return (
    <div style={{ display: 'grid', gap: 20, maxWidth: 320 }}>
      {SIZES.map(({ size, note }) => (
        <div key={size} style={{ display: 'grid', gap: 6 }}>
          <small className="text-mp-on-surface-variant">
            <code>size=&quot;{size}&quot;</code> — {note}
          </small>
          <MPSelect items={PLANS} label="Plan" size={size} defaultValue="pro" fullWidth />
        </div>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

const List<MPSelectOption> _plans = <MPSelectOption>[
  MPSelectOption(value: 'free', label: Text('Free')),
  MPSelectOption(value: 'pro', label: Text('Pro')),
  MPSelectOption(value: 'team', label: Text('Team')),
];

/// The same five rungs a text field is drawn at.
///
/// A select and a field at the same `size` line up to the pixel, which is the
/// whole reason the shell is shared: put one of each in a filter bar and the
/// row is a row rather than two controls that nearly agree.
const List<(MPSize, String)> _sizes = <(MPSize, String)>[
  (MPSize.xs, '32px'),
  (MPSize.sm, '40px'),
  (MPSize.md, '56px — the default'),
  (MPSize.lg, '64px'),
  (MPSize.xl, '72px'),
];

class SelectSizes extends StatelessWidget {
  const SelectSizes({super.key});

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 320),
      child: Column(
        mainAxisSize: MainAxisSize.min,
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 20,
        children: <Widget>[
          for (final (MPSize size, String note) in _sizes)
            Column(
              mainAxisSize: MainAxisSize.min,
              crossAxisAlignment: CrossAxisAlignment.stretch,
              spacing: 6,
              children: <Widget>[
                MPTypography('size: MPSize.${size.name} — $note', level: MPTypographyLevel.caption),
                MPSelect(
                  items: _plans,
                  label: const Text('Plan'),
                  size: size,
                  initialValue: 'pro',
                  fullWidth: true,
                ),
              ],
            ),
        ],
      ),
    );
  }
}

fullWidth가 아닌 셀렉트는 말할 수 있는 가장 긴 문자열 — 모든 옵션, 플레이스홀더, 내려와 있는 라벨 — 의 너비를 유지합니다. 그래서 더 짧은 옵션을 골라도 방금 고른 포인터 아래에서 필드가 줄어들지 않습니다.

팝업 ​

surface-container에 elevation 2 — 이 라이브러리에서 정말로 떠 있는 유일한 면이고, 기본으로 그림자를 갖는 유일한 면입니다.

선택된 행은 채움만이 아니라 체크로 표시됩니다. 강조 표시는 키보드 커서의 모습이기도 하기 때문입니다. "선택됨"과 "화살표 키가 있는 곳"이 같은 색인 목록은 읽을 수 없는 목록입니다. 체크의 열은 모든 행에 예약되어 있어서, 선택이 아래로 내려가도 라벨이 옆으로 밀리지 않습니다.

팝업은 페이드로 나타납니다. 라이브러리의 다른 모든 팝업 — 메뉴, 팝오버, 콤보박스의 목록, 다이얼로그 — 과 같은 200ms, 같은 커브입니다. 불투명도만 바뀌고 그 외에는 아무것도 움직이지 않습니다. 미끄러지거나 확대되는 목록은 포인터가 이미 향하고 있던 행을 옮겨 버리기 때문입니다.

커서는 배경이 아니라 상태 레이어입니다. MPMenu가 강조된 행 아래에 까는 것과 같은 워시입니다. 배경으로 그리면 선택된 행의 채움을 대체할 수밖에 없고, 그러면 목록이 가장 자주 열리는 바로 그 행에서 커서가 보이지 않게 됩니다. 레이어는 그 위에 겹쳐지고, 나타나는 대신 서서히 짙어집니다.

접근성 ​

  • 트리거는 홈에 놓인 라벨로 이름이 붙고 id로 연결됩니다.
  • 팝업의 위치 계산과 뒤집기, 포커스 트랩, typeahead, 폼과 함께 제출되는 숨은 input은 모두 Base UI가 담당합니다.
  • readOnly는 값을 보여 주되 바꾸지 못하게 하고 탭 순서에 남습니다. disabled는 둘 다 아닙니다.
  • 화면 낭독기에게 필드는 버튼 노드 하나입니다. 홈에 놓인 라벨로 이름이 붙고, 고른 옵션의 라벨을 값으로 갖고, 목록이 펼쳐졌는지 알립니다. 라벨, 값, 보조 텍스트를 한 번에 읽습니다.
  • 목록이 열려 있는 동안에도 포커스는 트리거에 남습니다. 화살표 키는 목록을 열고 비활성 행을 건너뛰며 움직이고, Home과 End는 양 끝으로 갑니다. Enter나 Space는 강조된 행을 고르고, Escape, Tab, 바깥 누르기는 고르지 않고 닫습니다.
  • 글자를 치면 그 글자로 시작하는 옵션으로 갑니다. 열린 목록에서는 강조가, 닫힌 셀렉트에서는 값 자체가 옮겨 갑니다. native select와 같습니다.
  • 방향 탐색, 즉 리모컨의 D-pad에서는 닫힌 셀렉트가 화살표를 포커스 시스템에 넘기고 Select나 Enter로 열립니다.
  • readOnly는 값을 보여 주되 바꾸지 못하게 하고 포커스 순서에 남습니다. disabled는 둘 다 아닙니다.
  • MPForm 안에서는 name으로 값이 나머지와 함께 넘어가고, 아무것도 고르지 않은 필수 셀렉트는 제출을 막고 포커스를 받으며, 폼이 그 이름으로 돌려준 오류가 트리거 아래에 보입니다.

React 빌드와 다른 점 ​

이 페이지의 대부분은 두 패키지에서 같습니다. 아래는 같지 않은 지점과 그 이유입니다.

ReactFlutter이유
onValueChangeonChanged평범한 변경에 붙는 Flutter의 이름입니다.
defaultValueinitialValueFlutter의 이름입니다. value를 빼면 값이 아닌 표식이 기본값으로 들어가고, 그것이 셀렉트가 값을 직접 들게 만듭니다. value: null은 아무것도 고르지 않은 controlled 셀렉트입니다.
string | numberMPSelectValue (Object)Dart에는 유니언 타입이 없습니다. String이나 num을 넘기세요.
label, placeholder, 옵션의 label (ReactNode)Widget?보통 Text입니다. 화면 낭독기와 typeahead는 Text의 글자를 읽습니다.
포커스가 목록 안으로 이동포커스가 트리거에 남음목록의 키가 트리거의 것이므로, 목록이 열려 있는 동안 외곽선이 포커스 색을 유지합니다.
onKeyDown, onKeyUponKeyEventKeyEventResult를 돌려주는 콜백 하나입니다. 셀렉트보다 먼저 모든 키를 듣습니다.
onFocus, onBluronFocusChangebool을 받는 콜백 하나입니다.
onClick, onDoubleClick, onContextMenu—포인터는 셀렉트를 GestureDetector로 감싸서 받습니다.
id, className, style, classNames—넘겨줄 대상이 없습니다.
—semanticLabel, focusNode, autofocus보이는 라벨이 없는 셀렉트의 이름과, 밖에서 다루는 포커스입니다.

나머지는 일부러 맞췄습니다. 껍데기, 팝업의 면과 페이드, 행의 체크와 상태 레이어, 떠오르는 라벨, 크기 단계가 그렇습니다.
