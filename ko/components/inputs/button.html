MPButton ​

머터리얼의 다섯 가지 버튼 — filled, tonal, elevated, outlined, text — 을 네 가지 강조 색 계열과 이 라이브러리의 크기 사다리 위에서 그립니다. 스테이트 레이어, 비활성 불투명도, 알약 모양이 모두 Material Design 3의 컴포넌트 토큰에서 옵니다.

ReactFlutter
tsx
import { MPButton } from 'material-plus-ui';

<MPButton onClick={save}>저장</MPButton>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPButton(onPressed: save, child: const Text('저장'));

MPButton은 트리 위쪽에 아무것도 필요하지 않습니다. MPTheme이 없으면 플랫폼의 밝기를 따르므로, 어느 앱에 놓아도 이미 맞는 스킴으로 그려집니다. React 패키지에서 넘어오지 않는 것은 React 빌드와 다른 점에 있습니다.

예시 ​

variant ​

다섯 가지이고, 한 가지의 다섯 가지 농도가 아닙니다. 각각은 같은 질문 — 이 동작이 페이지에서 어떻게 자기를 구분하는가 — 에 대한 서로 다른 대답입니다.

ReactFlutter
tsx
import { MPButton } from 'material-plus-ui';
import type { MPVariant } from 'material-plus-ui';

/**
 * Material's five, in the order they get quieter.
 *
 * They are not five shades of one thing. Each is a different answer to "how does
 * this action separate itself from the page": `filled` paints the accent,
 * `tonal` dilutes it, `elevated` uses a shadow instead of colour, `outlined` a
 * hairline, `text` nothing at all.
 */
const VARIANTS: { variant: MPVariant; note: string }[] = [
  { variant: 'filled', note: 'the one thing this screen is for' },
  { variant: 'tonal', note: 'the second-most-important action' },
  { variant: 'elevated', note: 'over a busy or coloured background' },
  { variant: 'outlined', note: 'an alternative to the filled one' },
  { variant: 'text', note: 'the least of them — a link that acts' }
];

export default function ButtonVariants() {
  return (
    <div style={{ display: 'grid', gap: 16 }}>
      {VARIANTS.map(({ variant, note }) => (
        <div key={variant} style={{ display: 'flex', alignItems: 'center', gap: 16 }}>
          <MPButton variant={variant}>Continue</MPButton>
          <small className="text-mp-on-surface-variant">
            <code>{variant}</code> — {note}
          </small>
        </div>
      ))}
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// Material's five, in the order they get quieter.
///
/// They are not five shades of one thing. Each is a different answer to "how
/// does this action separate itself from the page": `filled` paints the accent,
/// `tonal` dilutes it, `elevated` uses a shadow instead of colour, `outlined` a
/// hairline, `text` nothing at all.
class ButtonVariants extends StatelessWidget {
  const ButtonVariants({super.key});

  static const List<(MPVariant, String)> _variants = <(MPVariant, String)>[
    (MPVariant.filled, 'the one thing this screen is for'),
    (MPVariant.tonal, 'the second-most-important action'),
    (MPVariant.elevated, 'over a busy or coloured background'),
    (MPVariant.outlined, 'an alternative to the filled one'),
    (MPVariant.text, 'the least of them, a link that acts'),
  ];

  @override
  Widget build(BuildContext context) {
    final MPThemeData theme = MPTheme.of(context);

    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: <Widget>[
        for (final (MPVariant variant, String note) in _variants)
          Padding(
            padding: const EdgeInsets.only(bottom: 16),
            child: Row(
              children: <Widget>[
                MPButton(variant: variant, onPressed: () {}, child: const Text('Continue')),
                const SizedBox(width: 16),
                Flexible(
                  child: Text(
                    '${variant.name}: $note',
                    style: theme.typescale.bodySmall.style(theme.colors.onSurfaceVariant),
                  ),
                ),
              ],
            ),
          ),
      ],
    );
  }
}

알아 둘 만한 것은 elevated입니다. 색이 아니라 그림자로 자기를 구분하는 중립 면이라서, 사진이나 색이 있는 패널 위에서 쓸 수 있는 유일한 변형입니다. 거기서는 tonal 계열이 앉을 만큼 조용한 자리가 없습니다.

화면당 filled 버튼 하나

머터리얼의 규칙이고, 실제 화면에서도 살아남는 규칙입니다. filled는 이 화면이 존재하는 이유 하나입니다. filled 버튼이 세 개 있는 화면은 무엇을 눌러야 하는지 아무 말도 하지 않은 화면입니다.

color ​

네 가지 강조 계열입니다 — primary, secondary, tertiary, error. Material UI의 여섯 가지가 아닙니다. 스펙의 색상 시스템에는 info, success, warning이 없고, 그것을 제공하면 토큰 시트가 만들어 낼 방법이 없는 롤을 약속하는 셈이 됩니다.

tsx
<MPButton color="error">계정 삭제</MPButton>
dart
MPButton(color: MPColor.error, onPressed: deleteAccount, child: const Text('계정 삭제'));

여기서 error는 다른 계열과 완전히 똑같이 취급됩니다. 의도한 것입니다. 파괴적인 버튼과 기본 버튼의 차이는 어떤 팔레트를 읽느냐뿐이고, 오류 색만 특별 취급하는 컴포넌트는 "다른 모든 것과 똑같아 보여야 하는" 그 한 경우를 위해 두 번째 코드 경로를 갖게 됩니다.

임의의 색상값은 받지 않습니다. primary가 무엇인지 바꾸려면 토큰을 설정하세요 / MPTheme의 sourceColor를 설정하세요. 그러면 한 번의 변경이 모든 호출부가 아니라 모든 컴포넌트에 한꺼번에 닿습니다.

loading ​

startIcon 자리를 스피너로 바꾸고 클릭을 막습니다.

ReactFlutter
tsx
import { useState } from 'react';
import { MPButton } from 'material-plus-ui';

/**
 * `loading` is not `disabled`, and the difference is the point.
 *
 * Press Save: the button stops firing and grows a spinner, but it keeps its
 * place in the tab order. A button that leaves the tab order the moment it is
 * pressed takes the keyboard focus with it, and returns the reader to the top of
 * the document while the request they just made is still in flight.
 *
 * Tab away and back while it is working — the focus is still there.
 */
export default function ButtonStates() {
  const [saving, setSaving] = useState(false);

  return (
    <div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 12 }}>
      <MPButton
        loading={saving}
        loadingLabel="Saving"
        onClick={() => {
          setSaving(true);
          setTimeout(() => setSaving(false), 2000);
        }}
      >
        Save
      </MPButton>
      <MPButton variant="tonal" disabled>
        Disabled
      </MPButton>
      <MPButton variant="outlined" disabled>
        Disabled
      </MPButton>
      <MPButton color="error">Delete</MPButton>
    </div>
  );
}
dart
import 'dart:async';

import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// `loading` is not `disabled`, and the difference is the point.
///
/// Press Save: the button stops firing and grows a spinner, but it keeps the
/// focus. A button that leaves the focus order the moment it is pressed takes
/// the keyboard focus with it.
class ButtonStates extends StatefulWidget {
  const ButtonStates({super.key});

  @override
  State<ButtonStates> createState() => _ButtonStatesState();
}

class _ButtonStatesState extends State<ButtonStates> {
  bool _saving = false;
  Timer? _timer;

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }

  void _save() {
    setState(() => _saving = true);
    _timer = Timer(const Duration(seconds: 2), () {
      if (mounted) {
        setState(() => _saving = false);
      }
    });
  }

  @override
  Widget build(BuildContext context) {
    return Wrap(
      spacing: 12,
      runSpacing: 12,
      crossAxisAlignment: WrapCrossAlignment.center,
      children: <Widget>[
        MPButton(
          loading: _saving,
          loadingLabel: 'Saving',
          onPressed: _save,
          child: const Text('Save'),
        ),
        const MPButton(variant: MPVariant.tonal, onPressed: null, child: Text('Disabled')),
        const MPButton(variant: MPVariant.outlined, onPressed: null, child: Text('Disabled')),
        MPButton(color: MPColor.error, onPressed: () {}, child: const Text('Delete')),
      ],
    );
  }
}

의도적으로 disabled가 아닙니다. 누르는 순간 탭 순서 / 포커스 순서에서 사라지는 버튼은 키보드 포커스를 함께 가져가 버립니다. 방금 보낸 요청이 아직 처리 중인데 읽는 사람은 문서 맨 위로 되돌아가 있게 됩니다.

그래서 버튼은 자기 자리를 지키고, aria-busy와 aria-disabled를 말하고, 클릭만 삼킵니다.

그래서 버튼은 자리와 포커스를 그대로 지키고, 눌러도 아무 일도 하지 않습니다. 화면 낭독기는 스피너를 loadingLabel로 읽고, 이 값이 없으면 버튼의 언어로 된 '불러오는 중' 문구로 읽습니다.

startIcon과 endIcon ​

라벨 양쪽에 놓이는 내용입니다. 아이콘은 받은 크기 그대로 그려지고, size 없는 MPIcon은 아이콘 세트 자신의 크기를 씁니다. 버튼 단계에 맞춰 크기가 정해지는 것은 loading 동안 startIcon 자리를 대신하는 스피너뿐입니다.

tsx
<MPButton startIcon={<MPIcon icon={ICONS.check} size={20} />}>저장</MPButton>

라벨 양쪽에 놓이는 내용입니다. 버튼은 두 자리를 IconTheme으로 감싸 자기 단계의 아이콘 크기와 라벨 색을 내려 줍니다. 그래서 size를 따로 주지 않은 Icon은 알아서 라벨에 맞춰 그려집니다. 글리프는 앱이 쓰는 어떤 아이콘 세트에서 와도 됩니다.

dart
MPButton(startIcon: const Icon(Icons.check), onPressed: save, child: const Text('저장'));
children / child 없이 아이콘만 주면 버튼이 정사각형이 되어 아이콘 버튼이 됩니다. 그럴 때는 aria-label / semanticLabel을 주세요. 이름이 될 텍스트가 남아 있지 않습니다.
tsx
<MPButton aria-label="검색" startIcon={<MPIcon icon={ICONS.search} size={20} />} />
dart
MPButton(semanticLabel: '검색', startIcon: const Icon(Icons.search), onPressed: openSearch);

size ​

다섯 단계이고 라이브러리의 컨트롤 사다리를 그대로 씁니다 — 32, 40, 56, 64, 72픽셀. 앞의 세 단계는 머터리얼 자신의 extra-small, small, medium 버튼 높이입니다. lg와 xl은 이 라이브러리의 것인데, 스펙의 값이 96과 136이고 64px 필드 옆의 96px 버튼은 한 줄이 아니기 때문입니다. Prop 규약을 참고하세요.

ReactFlutter
tsx
import { MPButton } from 'material-plus-ui';
import type { MPSize } from 'material-plus-ui';

/**
 * Five rungs off the library's control ladder.
 *
 * The first three are MD3's own extra-small, small and medium button heights;
 * `lg` and `xl` are this library's, because the spec's are 96 and 136 and a 96px
 * button beside a 64px field is not a row. The label's type scale and the
 * padding around it come off the same rung, which is why a taller button is not
 * just a taller pill.
 */
const SIZES: { size: MPSize; note: string }[] = [
  { size: 'xs', note: '32px — MD3’s extra-small' },
  { size: 'sm', note: '40px — MD3’s small' },
  { size: 'md', note: '56px — MD3’s medium, and the default' },
  { size: 'lg', note: '64px' },

    (MPSize.lg, '64px'),
    (MPSize.xl, '72px'),
  ];

    return Column(

라벨의 타입 스케일과 그 주위의 여백도 같은 단계에서 나옵니다. 더 큰 버튼이 그저 더 큰 알약이 아닌 이유가 그것입니다.

이 컴포넌트에 없는 것 ​

href가 없습니다. 이동하는 버튼은 링크이고, 그 차이는 겉모습이 아닙니다. 링크는 링크로 읽히고, 읽는 사람은 그것을 링크로 다룰 수 있기를 기대합니다.

링크는 가운데 버튼으로 새 탭에서 열리고, 상태 표시줄에 목적지를 보여 줍니다. 그래서 버튼처럼 보이는 링크는 링크로 씁니다.

tsx
<MPButton render={<a href="/pricing" />} nativeButton={false} role="link">
  요금제
</MPButton>

셋 다 필요합니다. render는 Base UI의 탈출구이고 표면 전체를 그대로 가져옵니다. nativeButton={false}는 이 엘리먼트가 <button>이 아니라고 Base UI에게 알리는 것으로, 알리지 않으면 콘솔에 그렇게 적힙니다. 그리고 role="link"는 nativeButton={false}가 대신 가정하는 한 가지를 되돌립니다. Base UI는 그것을 "이 엘리먼트가 버튼처럼 동작한다"는 뜻으로 받아들여 role="button"을 붙이기 때문입니다. 이 마지막 prop이 없으면 앵커가 버튼으로 안내되는데, 그것이 바로 이 절이 말하는 거짓말입니다.

Flutter에는 바꿔 끼울 엘리먼트가 없어서, 버튼에 링크의 semantics를 줄 render도 없습니다. 읽는 사람이 링크로 다룰 수 있어야 하는 목적지는 라우터가 제공하는 링크 위젯에 맡기세요. 어떤 동작의 결과로 화면을 옮기는 버튼이라면 onPressed에서 라우터를 호출하면 됩니다.

리플이 없습니다. MD3에는 아직 리플이 있습니다. 누른 상태가 누른 지점에서 퍼져 나가는 스테이트 레이어입니다. 이 라이브러리는 누른 상태의 레이어를 한 번에 평평하게 그립니다. 같은 말을 하면서도 "애니메이션이 끝나야 화면이 바뀐다"는 문제를 만들지 않습니다.

접근성 ​

  • 포커스 표시는 secondary 색이고 버튼 바깥쪽에 그려집니다. MD3의 규칙인데, filled 버튼 안쪽에 그린 링은 그 링이 구분되어야 할 바로 그 면 위에 그린 링이기 때문입니다.
  • type의 기본값은 native의 submit이 아니라 button입니다. 폼 안의 관계없는 버튼이 폼을 제출하지 않습니다.
  • loading은 aria-busy로 자기 상태를 알리고 버튼을 포커스 가능한 상태로 둡니다.
  • 아이콘만 있는 버튼에는 aria-label이 필요합니다. 이름이 될 다른 것이 없습니다.
  • 포커스 표시는 secondary 색이고 버튼 바깥쪽에 그려집니다. MD3의 규칙인데, filled 버튼 안쪽에 그린 링은 그 링이 구분되어야 할 바로 그 면 위에 그린 링이기 때문입니다. 키보드로 포커스를 옮겼을 때만 나타나고, 탭했을 때는 나타나지 않습니다.
  • Enter, Space, 숫자 패드의 Enter로 버튼을 누릅니다. 이 키는 버튼 자체에 연결되어 있어서, 위쪽에 앱 위젯이 있든 없든 똑같이 동작합니다.
  • 버튼은 버튼으로 읽히고, 비활성일 때는 비활성으로 읽힙니다.
  • loading 중에도 버튼은 포커스를 받을 수 있고, 스피너는 loadingLabel로 읽힙니다.
  • 아이콘만 있는 버튼에는 semanticLabel이 필요합니다. 이름이 될 다른 것이 없습니다.
  • 글자가 있는 버튼에 semanticLabel을 주면 화면 낭독기에는 그 글자 대신 semanticLabel이 읽힙니다. 버튼에 보이는 글자를 semanticLabel에도 넣으세요. 그래야 그 글자를 음성 제어 도구에 말하는 사람도 버튼에 닿습니다.

React 빌드와 다른 점 ​

이 페이지의 대부분은 두 패키지에서 같습니다. 아래는 같지 않은 지점과 그 이유입니다.

ReactFlutter이유
onClickonPressedFlutter의 이름입니다. null로 두면 Flutter 어디서나 그렇듯 버튼이 비활성이 됩니다.
disableddisabled콜백이 늘 있는 버튼을 위해 남겨 두었습니다. 둘 중 어느 쪽으로도 버튼이 비활성이 됩니다.
childrenchildFlutter의 이름입니다.
aria-labelsemanticLabelFlutter의 이름입니다.
render, nativeButton—Flutter에는 바꿔 끼울 엘리먼트가 없습니다. 이동은 onPressed에서 하거나 라우터의 링크 위젯을 쓰세요.
type—버튼이 제출할 폼 엘리먼트가 없습니다.
className, style, 네이티브 속성—넘겨받을 곳이 없습니다. 대신 focusNode와 autofocus가 있습니다.

—locale스피너 기본 이름의 언어입니다. 주변 앱과 다른 언어를 쓰는 버튼을 위한 것입니다.

파라미터는 아니지만 하나 더 있습니다. React에서는 startIcon이나 endIcon에 넣은 글리프가 받은 크기를 그대로 지키지만, Flutter에서는 Icon이 버튼이 둘러 준 IconTheme을 읽어 단계의 크기를 따릅니다.

나머지는 의도적으로 맞췄습니다. 다섯 가지 변형, 네 가지 색 계열, 크기 사다리, 버튼 바깥에 그리는 포커스 표시, 그리고 포커스를 지킨 채 누름을 막는 loading이 그렇습니다.
