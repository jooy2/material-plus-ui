MPFieldset ​

하나의 질문에 함께 답하는 컨트롤 묶음이고, 그 위에 이름이 하나 붙습니다.

ReactFlutter
tsx
import { MPFieldset, MPTextField } from 'material-plus-ui';

<MPFieldset legend="청구지 주소" description="청구서가 가는 곳">
  <MPTextField name="street" label="도로명" value={street} onChange={setStreet} />
  <MPTextField name="city" label="도시" value={city} onChange={setCity} />
</MPFieldset>;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPFieldset(
  legend: const Text('청구지 주소'),
  description: const Text('청구서가 가는 곳'),
  children: <Widget>[
    MPTextField(name: 'street', label: const Text('도로명'), value: street, onChanged: setStreet),
    MPTextField(name: 'city', label: const Text('도시'), value: city, onChanged: setCity),
  ],
);

Props ​

Prop타입기본값설명
legendReactNode—그룹의 이름. 안에 있는 모든 컨트롤의 접근 가능한 이름의 일부가 되므로, 각각의 앞에 놓아도 여전히 말이 되는 구절이어야 합니다 — "어디로 보낼까요?"가 아니라 "청구지 주소"
descriptionReactNode—레전드 아래 한 줄
disabledbooleanfalse안의 모든 컨트롤을 한 번에 비활성화합니다. `<fieldset>`이 늘 해 온 대로이고, 세 단계 아래의 컴포넌트가 그린, 이 그룹의 존재를 들어 본 적도 없는 컨트롤까지 닿습니다
size'xs' | 'sm' | 'md' | 'lg' | 'xl''md'레전드의 타입 스케일과 컨트롤들이 서는 간격
childrenReactNode—함께 하나의 질문에 답하는 컨트롤들
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다
Prop타입기본값설명
legendWidget?—그룹의 이름. 그룹 안에서 가장 먼저 읽히므로, 각 컨트롤 앞에 놓아도 여전히 말이 되는 구절이어야 합니다 — "어디로 보낼까요?"가 아니라 "청구지 주소"
descriptionWidget?—레전드 아래 한 줄
disabledboolfalse안의 모든 컨트롤을 한 번에 비활성화합니다. 포인터와 포커스를 거둬 가고, 이 패키지의 컨트롤은 스스로 비활성으로 그려집니다
sizeMPSize?MPSize.md레전드의 타입 스케일과 컨트롤 사이 간격
children * List<Widget>—함께 하나의 질문에 답하는 컨트롤들

표면을 그리지 않는 이유 ​

필드 묶음은 묶음이지 시트가 아니고, 시트는 이미 있기 때문입니다.

시트가 필요하면 이것을 MPCard나 MPBox 안에 넣으세요. 자기 표면을 칠하는 fieldset은 누군가 그렇게 하는 순간 첫 번째 시트 안의 두 번째 시트가 됩니다. 페이지 반대쪽 끝에서 MPContainer가 대는 것과 같은 논리입니다.

대신 소유하는 것은 셋입니다. 레전드, 컨트롤들이 서는 간격, 그리고 disabled.

disabled, 그리고 이것이 진짜 <fieldset>인 이유 ​

disabled ​

ReactFlutter
tsx
import { MPCheckbox, MPFieldset, MPSwitch, MPTextField } from 'material-plus-ui';
import { useState } from 'react';

/**
 * The one thing only a real `<fieldset>` can do.
 *
 * `disabled` reaches every control inside it — including ones a component three
 * levels down rendered and never heard of it. That is not something a React
 * context could promise, and it is the reason this component exists rather than
 * a `<div>` with a heading.
 */
export default function FieldsetDisabled() {
  const [inherit, setInherit] = useState(true);
  const [street, setStreet] = useState('221B Baker Street');

  return (
    <div style={{ display: 'grid', gap: 16, width: '100%', maxWidth: 360 }}>
      <MPSwitch label="Same as delivery address" checked={inherit} onCheckedChange={setInherit} />

      <MPFieldset legend="Billing address" disabled={inherit}>
        <MPTextField name="street" label="Street" value={street} onChange={setStreet} fullWidth />
        <MPCheckbox label="This is a business address" />
      </MPFieldset>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// The one thing a fieldset is for beyond a heading.
///
/// `disabled` reaches every control inside it, including ones a widget three
/// levels down drew and never heard of.
class FieldsetDisabled extends StatefulWidget {
  const FieldsetDisabled({super.key});

  @override
  State<FieldsetDisabled> createState() => _FieldsetDisabledState();
}

class _FieldsetDisabledState extends State<FieldsetDisabled> {
  bool _inherit = true;
  String _street = '221B Baker Street';

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 360),
      child: Column(
        mainAxisSize: MainAxisSize.min,
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 16,
        children: <Widget>[
          MPSwitch(
            label: const Text('Same as delivery address'),
            checked: _inherit,
            onChanged: (bool next) => setState(() => _inherit = next),
          ),
          MPFieldset(
            legend: const Text('Billing address'),
            disabled: _inherit,
            children: <Widget>[
              MPTextField(
                name: 'street',
                label: const Text('Street'),
                value: _street,
                onChanged: (String next) => setState(() => _street = next),
                fullWidth: true,
              ),
              const MPCheckbox(label: Text('This is a business address')),
            ],
          ),
        ],
      ),
    );
  }
}

<fieldset>의 disabled는 안의 모든 컨트롤에 닿습니다. 세 단계 아래의 컴포넌트가 그린, 이 그룹의 존재를 들어 본 적도 없는 컨트롤까지요.

React 컨텍스트로는 약속할 수 없는 일입니다. 컨텍스트는 그것을 읽는 컴포넌트에 닿지만, fieldset은 누가 그렸든 얼마나 깊든 폼 컨트롤에 닿습니다. 이것이 제목을 얹은 <div>가 아니라 컴포넌트인 이유의 전부입니다.

disabled는 안의 모든 컨트롤에 닿습니다. 세 단계 아래의 위젯이 그린, 이 그룹의 존재를 들어 본 적도 없는 컨트롤까지요. 그룹은 안의 모든 것에서 포인터와 포커스를 거둬 가므로, 안에서는 아무것도 눌리지 않고 Tab도 멈추지 않습니다. 이 패키지의 컨트롤은 자기 disabled를 받았을 때처럼 비활성으로 그려지고 화면 낭독기에도 그렇게 알립니다. 다른 곳에서 온 위젯은 모양은 그대로지만 누르거나 포커스를 줄 수 없습니다.

disabled를 껐다 켜도 입력한 내용은 남습니다. 필드를 다시 만들지 않기 때문입니다.

레전드 ​

안에 있는 모든 컨트롤의 접근 가능한 이름의 일부가 되고, 그래서 어떻게 써야 하는지가 달라집니다. 각각의 앞에 놓아도 여전히 말이 되는 구절이어야 합니다.

그룹에서 가장 먼저 읽히고, 읽는 사람이 안의 컨트롤에 닿을 때마다 그 앞에 놓입니다. 그래서 어떻게 써야 하는지가 달라집니다. 각각의 앞에 놓아도 여전히 말이 되는 구절이어야 합니다.

청구지 주소 → "청구지 주소 도로명", "청구지 주소 도시". ✓

어디로 보낼까요? → "어디로 보낼까요? 도로명". ✗

<legend> 엘리먼트가 아닌 이유 ​

레전드는 aria-labelledby가 가리키는 <div>입니다. Base UI의 결정이고, 그룹을 평범한 flex 컨테이너로 만드는 결정입니다.

실제로 렌더링된 <legend>는 모든 브라우저가 fieldset의 콘텐츠 박스 밖으로 들어 올리므로, gap을 줘도 그 아래에는 아무 공간도 생기지 않고 첫 컨트롤이 그룹 이름에 붙어 버립니다. 접근 가능한 이름은 어느 쪽이든 같고, 살아남아야 했던 것은 그것뿐입니다.

예시 ​

폼 안에서 ​

tsx
<MPForm onSubmit={save}>
  <MPFieldset legend="청구지 주소">…</MPFieldset>
  <MPFieldset legend="배송지 주소">…</MPFieldset>
  <MPButton type="submit">저장</MPButton>
</MPForm>
dart
MPForm(
  key: form,
  onSubmit: save,
  children: <Widget>[
    MPFieldset(legend: const Text('청구지 주소'), children: <Widget>[...]),
    MPFieldset(legend: const Text('배송지 주소'), children: <Widget>[...]),
    MPButton(onPressed: () => form.currentState!.submit(), child: const Text('저장')),
  ],
)

각각은 자기 단으로 쌓이고, 폼은 fieldset들을 자기 단으로 쌓습니다.

라디오 그룹은 이미 하나입니다 ​

MPRadioGroup은 자기 label을 가지고 스스로를 그룹으로 알리므로 감쌀 필요가 없습니다.

tsx
// MPFieldset으로 감싸지 말고 이렇게.
<MPRadioGroup label="배송">…</MPRadioGroup>

fieldset은 컨트롤들이 함께 묶이는 서로 다른 질문일 때 — 도로명, 도시, 우편번호 — 손에 잡으세요. 답이 여럿인 하나의 질문이 아니라요.

접근성 ​

  • 그룹은 하나로 알려지고, 레전드가 그 이름입니다.
  • disabled는 네이티브 그것이므로 브라우저도, 폼 제출도, 안의 모든 컨트롤도 무엇이 그렸든 그것을 지킵니다.
  • description은 레전드 블록 안에 있으므로 따로 찾아야 하는 것이 아니라 그룹 이름의 일부입니다.
  • 여기서 자기 탭 정지를 갖는 것은 없습니다.
  • 그룹은 자기만의 시맨틱 노드이고, 그 안에서 레전드와 description이 먼저 읽힙니다.
  • 비활성 그룹은 안의 모든 것에서 포커스와 포인터를 거둬 가고, 안에 있는 이 패키지의 필드는 모두 사용할 수 없다고 알립니다. 비활성 필드는 MPForm의 검사와 값에서도 빠집니다.
  • 여기서 자기 Tab 정지를 갖는 것은 없습니다.

React 빌드와 다른 점 ​

ReactFlutter이유
legend, description (노드)legend, description (위젯)보통 Text를 넘깁니다.
childrenchildren (List<Widget>)쌓기에 쓰는 Flutter의 모양입니다.
native <fieldset disabled>컨트롤이 읽는 스코프와, 거둬 간 포커스와 포인터Flutter에는 안의 것을 비활성으로 만드는 엘리먼트가 없습니다. 읽는 사람이 겪는 결과는 같습니다.
native <fieldset> 속성, className—넘겨줄 대상이 없습니다.

함께 보기 ​

  • MPForm — 보통 이것들이 쌓이는 폼.
  • MPRadioGroup — 답이 여럿인 하나의 질문을 위한, 이미 스스로 이름을 붙이는 그룹.
  • MPCard — 시트가 필요할 때 fieldset을 올릴 곳.
