MPDatePicker ​

달력에서 고르는 하루. 트리거는 텍스트 필드의 껍데기에 달력 글리프를 단 것이라, 폼 안의 날짜 필드가 주변 필드들과 같은 물건이 됩니다.

tsx
import { MPDatePicker } from 'material-plus-ui';

const [due, setDue] = useState(null);

<MPDatePicker label="마감일" value={due} onValueChange={setDue} />;

달력이 실제로 존재하는 이유 ​

헤더 때문입니다.

한 번에 한 달씩만 넘기는 피커는 30년 전 생일을 180번의 클릭 너머에 둡니다. 그래서 월 이름과 연도가 각각 자기 격자를 여는 버튼입니다 — 열두 달, 그다음 한 번에 열두 해. 화면에 있는 해의 어떤 달이든 두 번, 어떤 해든 세 번입니다.

세 뷰는 의도적으로 너비도 높이도 같습니다. 일 뷰는 헤더까지 일곱 행이고, 나머지 둘은 같은 높이 위에 네 행과 세 행을 펼칩니다. 그래서 뷰를 바꿔도 팝업을 연 포인터 아래에서 팝업 크기가 변하지 않습니다.

날짜 라이브러리도, 타이핑도 없습니다 ​

사실상 하나인 두 결정입니다.

아래에 날짜 라이브러리가 없습니다. 산술 전부가 Date이고, 피커가 그리는 모든 이름은 Intl에서 옵니다. 슬그머니 date-fns를 추가하는 — 더 나쁘게는, 소비자를 대신해 dayjs/luxon/Temporal 논쟁에서 편을 드는 — 컴포넌트 라이브러리는 자기 것이 아닌 결정을 내린 것입니다. 이 패키지의 런타임 의존성은 여전히 하나뿐이고, 그건 아이콘 세트입니다.

그리고 트리거에 타이핑할 수 없습니다. 자유 텍스트에서 날짜를 파싱하는 일은 날짜 라이브러리 없이는 정직하게 해낼 수 없을 만큼 로케일에 얽혀 있습니다. 27/7/26은 읽는 사람에 따라 세 개의 다른 날입니다. 어떤 브라우저에서는 알아듣고 다음 브라우저에서는 못 알아듣는 필드는, 애초에 알아듣는다고 하지 않은 필드보다 나쁩니다. 그래서 트리거는 셀렉트와 똑같이 버튼이고, 답은 달력에서 옵니다.

현지화 ​

움직이는 것은 전부 플랫폼에서 옵니다.

tsx
import { useState } from 'react';
import { MPDatePicker, MPSegmentedButton } from 'material-plus-ui';

/**
 * The same picker in four languages, with nothing translated by hand.
 *
 * Everything that moves here comes from `Intl`: the month names, the weekday
 * initials, which day the week starts on (Sunday in the US and Korea, Monday in
 * Germany), the order of the header's two buttons — `July 2026` against
 * `2026년 7월` — and how the trigger writes the date.
 *
 * The only strings this library supplies are the ones the platform has no
 * opinion about: "Previous month", "Today", "Clear". Those are translated for
 * eighteen languages and overridable with `labels`.
 */
const LOCALES = [
  { value: 'en-US', label: 'English' },
  { value: 'ko', label: '한국어' },
  { value: 'de-DE', label: 'Deutsch' },
  { value: 'ar', label: 'العربية' }
];

export default function DatePickerLocale() {
  const [locale, setLocale] = useState('ko');
  const [value, setValue] = useState<Date | null>(new Date(2026, 6, 15));

  return (
    <div style={{ display: 'grid', gap: 20, width: '100%', maxWidth: 340 }}>
      <MPSegmentedButton
        items={LOCALES}
        value={[locale]}
        onValueChange={([next]) => setLocale(next ?? locale)}
        aria-label="Locale"
        size="sm"
        showCheck={false}
        fullWidth
      />
      <MPDatePicker
        key={locale}
        locale={locale}
        label="Date"
        value={value}
        onValueChange={setValue}
        defaultOpen
        fullWidth
      />
    </div>
  );
}

Intl이 월 이름, 요일 머리글자, 주가 시작하는 요일(미국과 한국은 일요일, 유럽 대부분은 월요일), 헤더 두 버튼의 순서 — July 2026 대 2026년 7월 — 그리고 트리거의 날짜 표기를 제공합니다. 이 순서를 틀리면 티가 잘 안 나면서도 정확히 그게 틀린 사람들에게는 고장으로 읽히므로, 추측하지 않고 물어봅니다.

이 라이브러리가 직접 대는 문자열은 Intl이 의견을 갖지 않는 것들뿐입니다. "이전 달", "오늘", "지우기". 열여덟 개 언어로 번역되어 있고, 그 밖의 언어에서는 영어로 내려가며, labels로 하나씩 덮어쓸 수 있습니다. 전체는 현지화 페이지에 있습니다.

경계 ​

tsx
import { useState } from 'react';
import { MPDatePicker } from 'material-plus-ui';

/**
 * The three ways a day can be unavailable, and one thing they have in common:
 * every blocked day is still *drawn*.
 *
 * A grid with holes in it is a grid a reader arrowing across a month falls into,
 * and "this day does not exist" and "this day is not for you" are different
 * claims. So a blocked cell keeps its place, keeps its name, and loses only the
 * ability to be chosen.
 */
const today = new Date();
const startOfDay = (date: Date) => new Date(date.getFullYear(), date.getMonth(), date.getDate());

export default function DatePickerBounds() {
  const [soon, setSoon] = useState<Date | null>(null);
  const [weekday, setWeekday] = useState<Date | null>(null);

  return (
    <div style={{ display: 'grid', gap: 20, maxWidth: 300 }}>
      <MPDatePicker
        label="Within the next fortnight"
        description="minDate and maxDate, day-granular."
        minDate={startOfDay(today)}
        maxDate={new Date(today.getFullYear(), today.getMonth(), today.getDate() + 14)}
        value={soon}
        onValueChange={setSoon}
        fullWidth
      />
      <MPDatePicker
        label="A working day"
        errorMessage={weekday ? undefined : 'Pick a weekday to continue.'}
        shouldDisableDate={(date) => date.getDay() === 0 || date.getDay() === 6}
        value={weekday}
        onValueChange={setWeekday}
        required
        fullWidth
      />
    </div>
  );
}

여기서 minDate와 maxDate는 날짜 단위입니다. 7월 27일 09:00을 최대로 두어도 27일은 여전히 고를 수 있습니다. 경계가 말하는 건 어떤 날이 존재하느냐이고, 하루 중 시각은 시계의 문제이기 때문입니다. MPDateTimePicker는 같은 prop을 전체 정밀도로 읽고, 그게 둘 사이의 유일한 실질적 차이입니다.

shouldDisableDate는 규칙이 말하는 것을 막습니다 — 주말, 공휴일, 이미 예약된 방.

막힌 날도 전부 그려지고, 그중 어느 것도 disabled 버튼이 아닙니다. 구멍 뚫린 격자는 화살표로 한 달을 가로지르는 사람이 빠지는 격자이고, "이 날은 존재하지 않는다"와 "이 날은 당신 것이 아니다"는 다른 주장입니다.

예시 ​

날짜를 바꿔도 시각은 살아남습니다 ​

날을 고르면 날만 바뀝니다. 시각도 함께 담는 필드에 묶인 피커가, 날짜를 고칠 때마다 조용히 자정으로 되돌려서는 안 됩니다.

tsx
// value가 7월 10일 14:30일 때 15일을 고르면 7월 15일 14:30이 됩니다.
<MPDatePicker value={value} onValueChange={setValue} />

floatingLabel ​

이 라이브러리에서 노치를 두른 컨트롤은 자리를 비켜줄 것이 없는 동안 라벨을 자기 줄 위에 내려둡니다 — MPTextField 참고. 다만 피커는 실질적으로 예외입니다. 내려온 라벨이 설 바로 그 자리에 달력 글리프를 그리고, 둘 중에서는 글리프 쪽이 "누르면 달력이 열린다"고 말하는 쪽이기 때문입니다.

그래서 글리프를 빼달라고 하지 않는 한 라벨은 노치에 남습니다.

tsx
<MPDatePicker label="Due date" startIcon={null} value={due} onValueChange={setDue} />

MPDateRangePicker, MPDateTimePicker, MPTimePicker도 마찬가지입니다.

clearable ​

트리거에 ×를, 푸터에 단어를 답니다. 피커가 비어 있거나 읽기 전용이거나 비활성일 때는 나타나지 않습니다. 지울 게 없으니까요.

readOnly ​

값을 보여 주고, 탭 순서에 남고, 열리지 않습니다. 읽기 전용 피커가 담고 있는 건 읽을 거리이고, 모든 칸이 죽어 있는 달력은 아무것도 없는 메뉴입니다.

name ​

hidden input을 더해서 전체가 폼과 함께 제출되게 합니다.

html
<input type="hidden" name="due" value="2026-07-15" />

UTC가 아니라 로컬이고, 그게 핵심 전부입니다. 서울에서 7월 15일을 뜻하는 Date에 toISOString()을 하면 2026-07-14T15:00:00Z가 나옵니다. 화면에 보이는 날의 전날을 조용히 보고하는 폼 필드는 날짜 피커가 낼 수 있는 가장 비싼 버그입니다. 형식은 <input type="date">가 제출하는 그것이므로, 이미 그걸 파싱하는 서버는 새로 쓸 코드가 없습니다.

접근성 ​

  • 트리거는 홈에 놓인 라벨이 id로 이름 붙인 버튼입니다.
  • 격자는 roving tab stop 하나를 가진 role="grid"이고, 이게 ARIA의 날짜 피커 관행입니다. Tab은 마흔두 칸을 걷는 대신 달력을 떠납니다.
  • 화살표는 하루씩, Home/End는 그 주의 양끝으로, PageUp/PageDown은 한 달씩 — Shift와 함께면 한 해씩 움직입니다. 가장자리를 넘어가면 멈추는 대신 달력이 넘어갑니다.
  • 모든 칸은 맨 숫자가 아니라 온전한 날짜로 이름 붙습니다. 그래서 "15"가 아니라 "2026년 7월 15일 수요일"로 읽힙니다.
  • 오늘은 채움이 아니라 테두리 원으로 표시하고, 그 테두리는 border라서 포커스 링과 공존할 수 있습니다.
