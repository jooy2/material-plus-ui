MPDateRangePicker ​

두 날 사이의 구간. 달을 넘나드는 범위가 예외가 아니라 일반적인 경우이고, 한 달짜리 피커는 그걸 탐색 문제로 만들기 때문에 두 달을 나란히 보여 줍니다.

tsx
import { MPDateRangePicker } from 'material-plus-ui';

const [stay, setStay] = useState({ start: null, end: null });

<MPDateRangePicker
  label="숙박"
  startPlaceholder="체크인"
  endPlaceholder="체크아웃"
  value={stay}
  onValueChange={setStay}
/>;

Props ​

Prop타입기본값설명
valueMPDateRange | null—고른 범위. `{ start, end }` 객체이며, 한쪽만 있는 상태도 실재하는 상태입니다
defaultValueMPDateRange | null—처음 고른 범위
onValueChange(value: MPDateRange) => void—항상 객체로 호출됩니다. 비운 범위는 `null`이 아니라 `{ start: null, end: null }`입니다
labelReactNode—외곽선의 홈에 놓이는 라벨. 고른 값이 없고 포커스도 없고 앞에 글리프도 없는 동안에는 트리거 줄 위에 내려와 있습니다 — `floatingLabel` 참고
floatingLabelbooleantrue비어 있는 동안 라벨을 트리거 줄에 내려두고 포커스나 첫 선택에서 홈으로 올릴지 여부. 피커는 값 앞에 자기 글리프를 그리고 그 글리프가 바로 내려온 라벨이 설 자리이므로, 실제로는 `startIcon={null}`로 글리프를 뺀 피커에서만 동작합니다
startPlaceholderReactNode—시작이 비어 있을 때 트리거 왼쪽에 보이는 문구
endPlaceholderReactNode—끝이 비어 있을 때 트리거 오른쪽에 보이는 문구
descriptionReactNode—컨트롤 아래 한 줄. `errorMessage`가 있으면 그쪽으로 대체됩니다
errorMessageReactNode—컨트롤 아래 메시지. 이 값이 있으면 컨트롤 전체가 오류 상태가 되므로, 설명 없는 오류는 만들 수 없습니다

clearablebooleanfalse값을 비우는 ×를 트리거에 답니다. 비어 있거나 읽기 전용일 때는 나타나지 않습니다

startIconReactNode—값 앞에 놓이는 내용. 기본값은 피커 자신의 글리프(달력 또는 시계)이고, `null`을 주면 글리프가 사라집니다

disabledbooleanfalse컨트롤을 비활성화하고 입력을 받지 않습니다
readOnlybooleanfalse값을 보여주되 바꾸지 못하게 합니다. `disabled`와 달리 탭 순서에 남습니다

idstring—컨트롤에 붙고 라벨이 가리키는 id. 생략하면 자동 생성됩니다
onKeyDown(event: React.KeyboardEvent) => void—달력을 여는 트리거 버튼에서. 수식 키를 포함한 모든 키 입력이라 조합을 다루는 자리입니다. 컴포넌트 자신의 처리보다 먼저 불리므로, `event.preventDefault()`가 그 키를 컴포넌트에게서 가져옵니다
onKeyUp(event: React.KeyboardEvent) => void—달력을 여는 트리거 버튼에서. 같은 키가 떨어질 때
onFocus(event: React.FocusEvent) => void—달력을 여는 트리거 버튼에서. 컨트롤이 포커스를 가져갈 때. 옆의 버튼이 가져가는 포커스는 여기 오지 않습니다
onBlur(event: React.FocusEvent) => void—달력을 여는 트리거 버튼에서. 컨트롤이 포커스를 잃을 때. 폼 라이브러리의 touched 처리가 기다리는 짝입니다
onClick(event: React.MouseEvent) => void—달력을 여는 트리거 버튼에서. 누를 때. 컴포넌트 자신의 반응은 그대로 일어납니다
onDoubleClick(event: React.MouseEvent) => void—달력을 여는 트리거 버튼에서. 두 번 누를 때
onContextMenu(event: React.MouseEvent) => void—달력을 여는 트리거 버튼에서. 오른쪽 클릭. `event.preventDefault()`로 브라우저 메뉴를 자신의 것으로 바꿉니다
classNamestring—컴포넌트가 그리는 가장 바깥 엘리먼트에, 컴포넌트 자신의 클래스 뒤에 붙습니다. 병합이 아니라 이어 붙이기입니다 — 같은 속성을 지정하는 두 유틸리티가 어떻게 결정되는지는 시작하기 가이드의 `클래스와 스타일`을 보세요
styleReact.CSSProperties—같은 엘리먼트에 붙는 인라인 스타일이며, 컴포넌트가 거기에 지정해 둔 것 위에 덮입니다. 인라인은 어떤 스타일시트보다 우선하므로, 인스턴스 하나에만 토큰을 넘기는 길입니다

값이 객체인 이유 ​

[Date, Date] 튜플도 아니고 prop 두 개도 아닌 { start, end }입니다.

범위는 하나의 값입니다. 한 번의 제스처로 고르고, 한 번의 제스처로 비우고, 통째로 검증됩니다. 그리고 두 이름은 호출자가 끝을 시작에 써 넣는 걸 막아 주는 장치입니다 — 튜플의 두 자리는 인덱스로만 구분됩니다.

절반짜리 범위는 실재하는 상태입니다. 첫 클릭과 두 번째 클릭 사이에 피커가 들고 있는 것이 그것입니다. 그래서 onValueChange는 항상 객체로 호출되고 null로는 호출되지 않습니다. 비운 범위는 { start: null, end: null }이므로, 호출자가 "비었음"을 두 가지 모양으로 검사할 일이 없습니다.

다만 절반 상태가 controlled 부모에게까지 가지는 않습니다. 첫 클릭은 컴포넌트 안에 붙들려 있고 부모는 { start, end: null }을 받습니다. 폼이 다루는 건 범위이고, 버려진 절반의 선택은 팝업이 닫히면 남지 않습니다.

미리보기가 곧 어포던스입니다 ​

한 번 클릭하고 포인터를 움직여 보세요. 두 번째 클릭이 도착하기 전에, 기준점과 포인터가 있는 곳 사이에 띠가 그려집니다.

그게 없으면 첫 클릭에는 눈에 보이는 결과가 아예 없고, 두 클릭 사이의 1초 남짓 동안 컨트롤은 고장 난 것처럼 보입니다. 범위 피커가 그리는 것 중 단연 가장 중요한 것입니다.

거꾸로 클릭하는 건 거부할 실수가 아닙니다. 같은 범위를 반대 순서로 입력한 것이고, 정규화됩니다.

두 패널은 하나의 달력입니다 ​

왼쪽에는 앞으로 가는 버튼이 없고, 오른쪽에는 뒤로 가는 버튼이 없으며, 어느 헤더의 월·연도 버튼이든 둘 다 움직입니다. 빠진 버튼 자리에는 그 버튼 크기만큼의 빈 자리가 남아서, 두 제목이 같은 중심선에 놓입니다.

패널은 앞뒤 달의 날짜도 그리지 않는데, 여기가 범위 피커가 단일 피커와 다른 유일한 지점입니다. 둘 다 여섯 주를 꽉 채워 그리면 8월 1일이 7월 패널의 뒤쪽 날이면서 동시에 8월 패널의 첫날이 됩니다. 한 팝업 안에 이름이 같은 칸이 둘이면 포인터에게는 모호하고 스크린 리더에게는 아예 망가진 것입니다.

띠의 색 ​

양 끝은 강조 색 자체이고, 그 사이의 날들은 강조 색의 컨테이너 톤 위에 그 톤의 잉크입니다.

MD3가 선택된 범위에 쓰는 짝과 같고, 끝과 가운데를 구별되게 유지하는 것이 바로 이것입니다. 띠를 강조 색으로 그리면 9일짜리 범위가 따로따로 고른 9개의 날처럼 보입니다. 띠는 연속 구간의 가운데에서는 각지고 구간이 끝나는 곳에서만 둥글어져서, 띠가 걸린 한 주가 일곱 개의 토큰이 아니라 하나의 형태로 읽힙니다.

예시 ​

presets ​

달력 옆의 단축 범위 — 분석 필터가 실제로 요구받는 그것입니다.

tsx
presets={[
  { label: '지난 7일', value: () => ({ start: daysAgo(6), end: today() }) },
  { label: '이번 달', value: () => ({ start: startOfMonth(), end: today() }) }
]}

범위가 오늘에 따라 달라진다면 — 거의 항상 그렇습니다 — 함수로 넘기세요. 모듈 스코프에서 한 번 계산한 "지난 7일"은, 탭을 켜 둔 채 밤을 넘긴 사람에게는 틀린 범위입니다.

monthCount ​

기본은 2입니다. 좁은 레이아웃이거나 범위가 거의 항상 한 달 안에 있다면 1로 줄이세요.

tsx
<MPDateRangePicker monthCount={1} />

패널이 하나면 오른쪽 버튼이 돌아옵니다. 충돌할 두 번째 패널이 없으니까요.

트리거의 두 칸 ​

어느 쪽도 flex-1이 아닙니다. 똑같이 반씩 나누면 트리거가 둘 중 짧은 쪽의 두 배로 잡혀서, "체크아웃" 같은 단어 옆의 날짜가 잘립니다. 각자 자기 너비를 갖게 두면 컨트롤이 실제로 말해야 하는 만큼의 크기가 됩니다. 각 칸은 자기가 보여 줄 수 있는 가장 긴 날짜 너비로 따로 열려 있어서, 범위를 채워 넣는 동안 어느 쪽도 튀지 않습니다.

name ​

같은 이름의 hidden input 두 개라, 양 끝이 함께 도착합니다.

js
const [start, end] = formData.getAll('stay');

둘 다 로컬 YYYY-MM-DD입니다. 이유는 MPDatePicker 쪽에 있습니다.

접근성 ​

  • 두 달력 모두 각자의 roving tab stop을 가진 격자이고, 단일 피커의 키보드 어휘 전부가 각각에서 동작합니다.
  • 푸터가 다음 클릭이 어느 끝을 채울지 말해 줍니다. 트리거도 두 칸으로 같은 말을 하지만, 팝업이 떠 있는 동안 트리거는 팝업 뒤에 있습니다. 그래서 읽힐 자리에서 그 말을 할 수 있는 건 푸터뿐입니다.
  • 띠는 색만으로 전달되지 않습니다. 양 끝은 aria-selected이고, 모든 칸은 온전한 날짜로 이름 붙습니다.

함께 보기 ​
