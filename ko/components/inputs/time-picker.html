MPTimePicker ​

열에서 고르는 하루 중 시각. 경계를 지금 그리고 있는 열의 단위로 검사하는데, 그게 잘 동작하는 시간 피커와 짜증나는 시간 피커를 가르는 지점입니다.

ReactFlutter
tsx
import { MPTimePicker } from 'material-plus-ui';

const [startsAt, setStartsAt] = useState(null);

<MPTimePicker label="시작 시각" minuteStep={5} value={startsAt} onValueChange={setStartsAt} />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPTimePicker(
  label: const Text('시작 시각'),
  minuteStep: 5,
  value: startsAt,
  onChanged: (DateTime? next) => setState(() => startsAt = next),
);

MD3의 다이얼이 아닌 이유 ​

명세의 시간 피커는 시계 문자판입니다. 이건 그게 아니고, 이 라이브러리에서 가장 큰 의도적 이탈입니다 — 그러니 이유를 분명히 적어 둘 만합니다.

다이얼은 포인터 컨트롤입니다. 읽으려면 아날로그 시계를 한 번 봐야 하고, 맞추려면 끌어야 합니다. 키보드 경로도 스크린 리더 경로도 없고, 바로 그 때문에 MD3는 그런 사용자를 위해 별도의 time input 모드 — 텍스트 필드 두 개 — 를 함께 내놓습니다. 결과적으로 하나의 질문에 두 벌의 구현을 가진 컴포넌트가 되고, 그중 접근 가능한 쪽은 아무도 못 보는 쪽이며, 둘을 오가는 토글은 대부분의 애플리케이션이 끝내 연결하지 않습니다.

열은 하나의 컨트롤로 양쪽 모두에게 답합니다. "9시 30분"은 두 번의 시선이고, "정각이면 아무 때나"는 아예 건드리지 않는 열입니다. 모든 행은 화살표 키가 이미 닿는 진짜 옵션이고, 머터리얼처럼 보이게 하는 나머지는 이 라이브러리 자신의 크기 사다리와 모서리와 state layer가 합니다.

열 단위의 경계 ​

ReactFlutter
tsx
import { useState } from 'react';
import { MPTimePicker } from 'material-plus-ui';

/**
 * The detail that separates a working time picker from a frustrating one.
 *
 * With a minimum of 09:30, the hour `9` stays available — the hour *contains*
 * allowed minutes — and it is the minute column that greys out `00` through
 * `25`. The naive check compares the whole candidate instant, hides the 9
 * entirely, and makes half past nine unreachable.
 *
 * Open it and look at the two columns together.
 */
const at = (hours: number, minutes: number) => {
  const date = new Date();

  date.setHours(hours, minutes, 0, 0);

  return date;
};

export default function TimePickerBounds() {
  const [value, setValue] = useState<Date | null>(at(9, 0));

  return (
    <div style={{ width: '100%', maxWidth: 280 }}>
      <MPTimePicker
        label="Appointment"
        description="Between 09:30 and 17:00."
        minTime={at(9, 30)}
        maxTime={at(17, 0)}
        value={value}
        onValueChange={setValue}
        defaultOpen
        fullWidth
      />
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// The detail that separates a working time picker from a frustrating one.
///
/// With a minimum of 09:30, the hour `9` stays available, because the hour
/// *contains* allowed minutes, and it is the minute column that greys out `00`
/// through `25`. The naive check compares the whole candidate instant, hides
/// the 9 entirely, and makes half past nine unreachable.
///
/// Open it and look at the two columns together.
class TimePickerBounds extends StatefulWidget {
  const TimePickerBounds({super.key});

  @override
  State<TimePickerBounds> createState() => _TimePickerBoundsState();
}

class _TimePickerBoundsState extends State<TimePickerBounds> {
  static DateTime _at(int hours, int minutes) {
    final DateTime now = DateTime.now();

    return DateTime(now.year, now.month, now.day, hours, minutes);
  }

  DateTime? _value = _at(9, 0);

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 280),
      child: MPTimePicker(
        label: const Text('Appointment'),
        description: const Text('Between 09:30 and 17:00.'),
        minTime: _at(9, 30),
        maxTime: _at(17, 0),
        value: _value,
        onChanged: (DateTime? next) => setState(() => _value = next),
        initialOpen: true,
        fullWidth: true,
      ),
    );
  }
}

여기가 핵심입니다. minTime이 09:30이면,

  • 시 9는 남아 있습니다. 그 시는 09:00:00–09:59:59를 덮고, 그건 허용 구간과 겹칩니다 — 그 시가 허용된 분들을 담고 있기 때문입니다.
  • 흐려지는 건 분 열의 00부터 25까지입니다.

순진한 검사는 후보 순간 전체를 비교해서 9시를 통째로 감추고, 9시 30분을 도달 불가능하게 만듭니다. 그래서 각 행은 그 안의 한 순간이 아니라 그 행이 나타내는 하루의 구간에 대해 검사됩니다.

shouldDisableTime도 같은 짝을 받습니다 — 그 행이 만들어 낼 순간과, 그게 어느 열인지. 그래서 "오후는 전부 안 됨"만큼 거칠게도, 1분 단위만큼 세밀하게도 규칙을 쓸 수 있습니다.

값이 Date인 이유 ​

문자열도, 자정으로부터의 분 수도 아닙니다. Flutter에서는 같은 이유로 DateTime입니다.

이 라이브러리에서 순간을 담는 다른 모든 것이 Date이고, 시각만으로는 그게 어느 날인지 적어 둘 데가 없습니다. 서머타임 경계를 넘었는지를 결정하는 게 바로 그것입니다. referenceDate는 값이 아직 없을 때 고른 시각이 얹힐 날입니다.

그 기준 날짜는 피커가 마운트되어 있는 동안 고정됩니다. 자정을 넘겨 열려 있던 팝업이, 자기가 쓰고 있는 값을 조용히 다른 날로 옮겨서는 안 됩니다.

여기서 closeOnSelect가 false인 이유 ​

날을 고르는 즉시 닫히는 MPDatePicker와 다릅니다.

시각은 답이 둘입니다. 첫 번째에서 닫으면 9시 30분을 고르려고 팝업을 두 번 열어야 합니다. 그래서 팝업은 열린 채로 있고, 완료 버튼이 있습니다 — 열린 채로 있는 팝업에는 "그게 맞다"고 말할 누를 것이 필요하니까요.

예시 ​

hour12 ​

로케일이 하는 대로가 기본입니다. en-US는 오전/오후 열이 붙은 12시간제를, de-DE는 그 열이 없는 24시간제를 받습니다.

이 값을 지정하면 열뿐 아니라 트리거에도 닿습니다. 다이얼은 24시간제인데 트리거는 여전히 "9:05 AM"이라고 말하는 피커는 자기 자신과 어긋난 컨트롤이고, hour12를 지정한 호출자는 이미 어느 쪽인지 말했습니다. 명시적인 format은 여전히 둘 모두를 이깁니다.

step 계열 ​

hourStep, minuteStep, secondStep이 각 열의 행 간격을 정합니다. 흔히 쓰는 건 minuteStep={5}입니다. 60개짜리 분 열은 아무도 끝까지 스크롤하지 않는 열입니다.

showSeconds ​

초 열을 더하고, 트리거의 표기와 폼 제출 값에도 초를 더합니다.

name ​

<input type="time">이 제출하는 형식의 hidden input입니다 — HH:MM, 초를 보이면 HH:MM:SS. UTC가 아니라 로컬입니다.

피커를 감싼 MPForm에 <input type="time">이 제출하는 형식으로 값을 등록합니다. HH:MM이고, 초를 보이면 HH:MM:SS입니다. UTC가 아니라 로컬입니다.

접근성 ​

  • 각 열은 이름이 붙은 role="listbox"입니다. 이름 없는 숫자 목록 셋은 보지 않고 읽는 사람에게 아무 말도 하지 않으니까요.
  • 각 열은 이름이 붙은 묶음이고, 각 행은 숫자와 열 이름으로 읽힙니다(09 시). 이름 없는 숫자 목록 셋은 보지 않고 읽는 사람에게 아무 말도 하지 않으니까요. 열 하나가 Tab의 정류장 하나이고, 열 안에서는 화살표, PageUp/PageDown, Home/End로 움직입니다.
  • 그 아래에는 시각 전체를 한 문장으로 되읽어 주는 live region이 있습니다 — "오전 9시 30분" — 세 열이 실제로 합쳐서 만들어 낸 것이 그것입니다.
  • 각 열의 선택된 행은 열릴 때 한 번 화면 안으로 스크롤됩니다. 값이 45인데 00에서 열린 60행짜리 분 열은 자기 답을 스스로 감춘 셈입니다.
  • 막힌 행은 제거되지 않고 자리를 지키며 쓸 수 없는 것으로 읽힙니다. 그래서 경계가 바뀔 때 열의 번호가 다시 매겨지지 않습니다.

React 빌드와 다른 점 ​

이 페이지의 대부분은 두 패키지에서 같습니다. 아래는 같지 않은 지점과 그 이유입니다.

ReactFlutter이유
onValueChange, defaultValue, defaultOpenonChanged, initialValue, initialOpenFlutter의 이름입니다.
format (Intl.DateTimeFormatOptions)format (String Function(DateTime))옵션을 넘길 Intl이 없습니다.
숫자로 받는 hourStep, minuteStep, secondStepint간격은 행의 개수이고, 두 패키지 모두 1과 열의 범위 사이로 묶습니다.
Intl로 다이얼을 정하는 locale패키지의 표로 다이얼을 정하는 locale, 그리고 names두 패키지 모두 en은 12시간제, de는 24시간제입니다. MPDatePicker의 현지화를 보세요.
name 아래의 hidden inputMPForm에 값을 등록하는 nameFlutter에는 native 폼이 없습니다. 문자열은 같습니다.
listbox, option 역할이름 붙은 버튼 묶음, 각 버튼은 선택 여부를 알림Flutter의 시맨틱에는 listbox 역할이 없습니다.
원시 DOM 이벤트, id, className, styleonKeyEvent, onFocusChange, semanticLabel, focusNode, autofocusMPDatePicker와 같습니다.

나머지는 일부러 맞췄습니다. 다이얼이 아닌 열, 열 단위로 읽는 경계, 붙잡아 둔 기준일, 완료 버튼, 열릴 때 보여 주는 선택 행이 그렇습니다.
