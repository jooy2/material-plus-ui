MPRating ​

별 다섯 개로 표현하는 점수입니다. 밑에는 고를 수 있는 점수마다 하나씩 놓인 진짜 라디오 입력들이 있고, 그래서 행 전체가 하나의 탭 스톱이 되고, 방향키가 그 안에서 동작하고, 아무것도 연결하지 않아도 값이 폼 제출에 실려 갑니다.

tsx
import { MPRating } from 'material-plus-ui';

const [score, setScore] = useState(0);

<MPRating value={score} onValueChange={setScore} />;

Props ​

localestring—말로 된 이름을 쓸 언어 — `ko`, `pt-BR`, `zh-Hant` 같은 BCP 47 태그

버튼이 아니라 라디오인 이유 ​

별점은 곧 "이 중 정확히 하나"이고, 그것이 라디오 그룹의 뜻이기 때문입니다.

그러면 브라우저가 별점에 필요한 모든 것을 대신 해 줍니다. 묶음 전체가 하나의 탭 스톱, 그 안에서의 방향키, 선택된 하나에 붙는 aria-checked, 폼 제출에 실리는 값, 그리고 required 검증까지 — <button> 행이었다면 전부 다시 만들어야 했을 것들입니다. 각 입력은 자기가 나타내는 별의 절반 아래에 시각적으로 숨겨져 있어서, 포인터는 별을 누르고 키보드는 라디오를 누릅니다.

각각에는 "5점 만점에 3점" 같은 이름이 붙습니다. 그려지는 것은 도형이고, 이름 없는 라디오 다섯 개는 아무도 들을 수 없는 컨트롤이기 때문입니다.

precision ​

tsx
import { useState } from 'react';
import { MPRating, MPTypography } from 'material-plus-ui';

/**
 * `precision` bounds what can be *chosen*, and nothing else.
 *
 * The read-only row at the bottom is an average of 4.3, and it is drawn as four
 * stars and a third at every precision — because an average is not a choice, and
 * rounding it to the nearest half would be reporting a different number from the
 * one the component was handed.
 */
export default function RatingPrecision() {
  const [half, setHalf] = useState(3.5);

  return (
    <div style={{ display: 'grid', gap: 20, justifyItems: 'start' }}>
      <div style={{ display: 'grid', gap: 4 }}>
        <MPTypography level="caption">precision={'{0.5}'} — half stars</MPTypography>
        <MPRating precision={0.5} value={half} onValueChange={setHalf} />
      </div>

      <div style={{ display: 'grid', gap: 4 }}>
        <MPTypography level="caption">readOnly — an average of 4.3</MPTypography>
        <MPRating value={4.3} readOnly />
      </div>

      <div style={{ display: 'grid', gap: 4 }}>
        <MPTypography level="caption">
          color=&quot;tertiary&quot;, if gold is what you want
        </MPTypography>
        <MPRating value={4} readOnly color="tertiary" />
      </div>
    </div>
  );
}

precision은 고를 수 있는 값의 단위를 정하고, 그것뿐입니다. 0.5면 반 개씩, 1이면 한 개씩이고, 0 < precision <= 1을 벗어나면 1로 돌아갑니다.

value가 4.3이면 어느 precision에서든 별 네 개와 3분의 1로 그려집니다. 평균은 선택이 아니고, 그것을 가장 가까운 0.5로 반올림하는 것은 건네받은 것과 다른 숫자를 보고하는 일이기 때문입니다.

분수는 채워진 별을 빈 별 위에 겹쳐 놓고 폭의 몇 퍼센트로 잘라내서 그립니다. 아무것도 변형하지 않고 어떤 글리프도 늘이지 않으므로, 반쪽 별은 그 옆 별의 정확히 왼쪽 절반입니다. 잘라내기는 inline start에서 시작하므로 RTL에서는 아무 지시 없이 오른쪽부터 채워집니다.

readOnly ​

상품의 평균 점수, 다른 사람이 남긴 평가. 같은 옷을 입은 다른 컴포넌트가 됩니다. 입력도, 라디오 그룹도 없고, 점수를 문장으로 든 role="img" 하나만 남습니다. 숫자 하나를 보고할 뿐인 페이지에 포커스 가능한 라디오 스무 개가 있는 것은 아무도 요청하지 않은 탭 스톱 스무 개이기 때문입니다.

이 라이브러리에서 채도를 빼지 않는 유일한 readOnly입니다. 붙잡아 둔 컨트롤이 아니라, 입력이 아예 없고 남은 것은 숫자의 그림입니다. 회색 별들의 행은 점수 자체를 쓸 수 없다고 말하게 됩니다.

disabled는 다른 것이고, 이쪽은 채도를 뺍니다. 강조 색이 사라지고 명세의 비활성 잉크가 들어옵니다. 다른 모든 컨트롤에서와 똑같습니다.

clearable ​

기본값은 켜짐입니다. 이미 선택된 점수를 다시 누르면 0으로 지워집니다.

이것은 change가 아니라 click 핸들러여야 하는데, 소스를 읽는다면 알아 둘 만합니다. 이미 체크된 라디오를 클릭하면 click만 발생하고 change는 전혀 발생하지 않는데, 바로 그 click이 여기서 듣고 있는 동작입니다.

별이 호박색이 아닌 이유 ​

이 라이브러리의 색 체계에 호박색이 없기 때문입니다.

MD3는 강조 색 계열을 넷 정의합니다 — primary, secondary, tertiary, error. 여기에 다섯 번째 색을 하드코딩하면 토큰 시트에 이름이 없고 테마가 바꿀 방법도 없는 색이 됩니다. 페이지가 다시 칠할 수 없는 이 라이브러리의 유일한 색이 되기도 합니다.

별이 반드시 금색이어야 하는 제품은 토큰을 설정하고 계열을 요청하면 됩니다.

css
:root {
  --mp-sys-color-tertiary: #b58900;
}
tsx
<MPRating color="tertiary" />

이 라이브러리가 다른 모든 곳에서 주는 답과 같습니다.

폼 안에서 ​

tsx
<form action={submit}>
  <MPRating name="score" required />
  <MPButton type="submit">보내기</MPButton>
</form>

name이 값을 식별하고 required가 별을 고르기 전까지 제출을 막습니다. 둘 다 브라우저가 합니다. name이 없으면 하나가 생성되므로, 한 페이지의 별점 두 개가 실수로 같은 라디오 그룹을 공유하는 일은 없습니다.

structuredData ​

점수는 검색 엔진이 결과 옆에 그려 주는 또 하나의 것이고, 그러려면 schema.org Rating 마크업이 필요합니다.

tsx
<div itemScope itemType="https://schema.org/Product">
  <h2 itemProp="name">주전자</h2>
  <MPRating readOnly value={4.3} structuredData itemProp="aggregateRating" />
  <meta itemProp="ratingCount" content="128" />
</div>

저 예시의 세 가지가 이 prop의 전부입니다.

readOnly일 때만 동작합니다. 아직 고르는 중인 점수는 무엇에 대한 사실도 아니고, 빈 컨트롤을 0점으로 마크업하는 것은 크롤러에게 페이지에 대해 사실이 아닌 것을 말하는 일입니다.

itemProp은 여러분의 것입니다. 마이크로데이터는 중첩이고, 이 컴포넌트는 자신이 무엇 안에 있는지 알 수 없습니다. 제품이면 aggregateRating, 리뷰 안이면 reviewRating, 또 다른 것일 수도 있습니다. 컴포넌트는 Rating과 그 값들을 내보내고, 관계를 이름 짓는 것은 페이지의 몫입니다.

개수도 여러분의 것입니다. aggregateRating은 검색 엔진이 무언가를 그리기 전에 옆에 ratingCount나 reviewCount를 필요로 하는데, 그 숫자는 별 한 줄이 알 수 있는 것이 아닙니다.

worstRating은 기본값 1에 맡기지 않고 0으로 적습니다. 이 컨트롤의 바닥이 0이기 때문입니다. 1에서 시작하는 척도에서 "5점 만점에 1점"은 다른 뜻입니다.

접근성 ​

  • 로케일이 "별점"이라고 부르는 이름을 가진 radiogroup이고, 고를 수 있는 점수마다 라디오가 하나씩 있습니다.
  • 모든 라디오에 말로 된 이름이 있습니다. 그려지는 것이 숫자가 아니라 도형이기 때문입니다.
  • 읽기 전용은 점수를 이름으로 가진 role="img" 하나이고, 그 안에 포커스 가능한 것은 없습니다.
  • 호버 미리보기는 포인터 전용입니다. 키보드 사용자가 듣는 것은 언제나 점수이고, 포인터가 지금 약속하고 있는 값이 아닙니다.

함께 보기 ​

  • MPRadioGroup — 같은 "이 중 정확히 하나"를, 글로 써 놓은 것.
  • MPSlider — 다섯 중 몇이 아니라 연속된 범위 위의 값.
  • 지역화 — 말로 된 이름들이 오는 곳.
