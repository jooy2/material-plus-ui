MPNumberField ​

숫자만 담는 필드이고, `MPTextField`의 껍데기를 픽셀 단위로 그대로 씁니다. 화살표 키와 증감 버튼이 `step`만큼 움직이고, 값은 `min`과 `max` 사이로 잘리며, `format`은 통화나 백분율로 써 주면서도 값 자체는 순수한 숫자로 남깁니다.

ReactFlutter
tsx
import { MPNumberField } from 'material-plus-ui';

const [quantity, setQuantity] = useState(1);

<MPNumberField label="수량" value={quantity} onValueChange={setQuantity} min={1} max={20} />;
dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPNumberField(
  label: const Text('수량'),
  value: quantity,
  onChanged: (double? next) => setState(() => quantity = next),
  min: 1,
  max: 20,
);

<input type="number">가 아닌 이유 ​

native 쪽도 될 것처럼 보이기 때문에 분명히 적어 둘 가치가 있습니다.

일부 브라우저에서는 텍스트를 조용히 받아들입니다. 스피너는 스타일을 줄 수 없고, 사파리에는 스피너가 아예 없습니다. 기본적으로 스크롤에 반응해서, 포인터 아래에서 페이지가 스크롤되면 값이 바뀝니다. 그리고 파싱에 실패한 모든 입력을 ''로 보고합니다. 즉 약간 잘못된 필드와 빈 필드를 읽는 쪽에서 구분할 수 없습니다.

이것은 inputmode="numeric"을 가진 type="text"에 role 설명을 붙인 것이고, Base UI의 number field가 하는 방식입니다. 그래서 휴대폰은 여전히 숫자 키패드를 띄우고 스크린 리더는 여전히 숫자 필드라고 말하면서, 파싱은 브라우저의 기분이 아니라 로케일을 기준으로 이루어집니다.

아래에 무엇이 있는가 ​

숫자 키보드를 띄우는 텍스트 필드이고, 숫자는 텍스트와 따로 관리합니다. -5로 가는 길에 혼자 입력된 -는 아직 숫자로 읽히지 않는 텍스트일 뿐이므로, 그동안 필드는 null을 알리고 필드를 떠날 때 상자를 정리합니다. 스텝, 범위 제한, 서식처럼 숫자 필드가 더하는 것은 모두 필드가 직접 하므로 어느 플랫폼에서나 똑같이 동작합니다.

예시 ​

format ​

format은 Intl.NumberFormat으로 그대로 전달됩니다. 그래서 상자는 $1,240.00이라고 말하면서 onValueChange는 1240을 넘깁니다.

format은 숫자를 상자에 들어갈 텍스트로 바꾸는 함수입니다. 그래서 상자는 $1,240.00이라고 말하면서 onChanged는 1240을 넘깁니다. parse는 그 반대쪽으로, 입력된 텍스트를 숫자로 되읽습니다. 빼 두면 숫자, 부호, 소수점을 뺀 나머지를 모두 버리고 읽으므로 통화나 단위는 그대로 되읽힙니다. 백분율은 15%가 0.15이므로 직접 줘야 합니다.

ReactFlutter
tsx
import { useState } from 'react';
import { MPNumberField } from 'material-plus-ui';

/**
 * The field shows a written number; the value stays a plain one.
 *
 * `format` goes to `Intl.NumberFormat`, so the box says `$1,240.00` while
 * `onValueChange` still hands over `1240` — which is the whole reason this is a
 * prop rather than something a caller does to `value` on the way in. Type into
 * it: the separators and the symbol come back on their own.
 */
export default function NumberFieldFormat() {
  const [price, setPrice] = useState<number | null>(1240);
  const [share, setShare] = useState<number | null>(0.15);

  return (
    <div style={{ display: 'grid', gap: 20, maxWidth: 300 }}>
      <MPNumberField
        label="Price"
        value={price}
        onValueChange={setPrice}
        format={{ style: 'currency', currency: 'USD' }}
        step={10}
        min={0}
        fullWidth
      />
      <MPNumberField
        label="Commission"
        value={share}
        onValueChange={setShare}
        format={{ style: 'percent', maximumFractionDigits: 1 }}
        step={0.01}
        min={0}
        max={1}
        fullWidth
      />
      <small className="text-mp-on-surface-variant">
        The values behind those are <code>{String(price)}</code> and <code>{String(share)}</code>.
      </small>
    </div>
  );
}
dart
import 'package:flutter/widgets.dart';
import 'package:material_plus_ui/material_plus_ui.dart';

/// The field shows a written number; the value stays a plain one.
///
/// `format` writes the box as `$1,240.00` while `onChanged` still hands over
/// `1240`, which is the whole reason it is a parameter rather than something a
/// caller does to `value` on the way in. Type into it: the separators and the
/// symbol come back on their own.
class NumberFieldFormat extends StatefulWidget {
  const NumberFieldFormat({super.key});

  @override
  State<NumberFieldFormat> createState() => _NumberFieldFormatState();
}

/// Thousands separated by commas, two decimal places, a dollar sign.
String _currency(double value) {
  final String fixed = value.abs().toStringAsFixed(2);
  final String whole = fixed
      .substring(0, fixed.length - 3)
      .replaceAllMapped(RegExp(r'(\d)(?=(\d{3})+$)'), (Match match) => '${match[1]},');

  return '${value < 0 ? '-' : ''}\$$whole${fixed.substring(fixed.length - 3)}';
}

/// A share written as a percentage, to one decimal place at most.
String _percent(double value) {
  final String fixed = (value * 100).toStringAsFixed(1);

  return '${fixed.endsWith('.0') ? fixed.substring(0, fixed.length - 2) : fixed}%';
}

/// What a percentage is typed as, read back as a share.
double? _readPercent(String text) {
  final String digits = text.replaceAll(RegExp(r'[^0-9.\-]'), '');
  final double? number = double.tryParse(digits);

  return number == null ? null : number / 100;
}

class _NumberFieldFormatState extends State<NumberFieldFormat> {
  double? _price = 1240;
  double? _share = 0.15;

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 300),
      child: Column(
        mainAxisSize: MainAxisSize.min,
        crossAxisAlignment: CrossAxisAlignment.stretch,
        spacing: 20,
        children: <Widget>[
          MPNumberField(
            label: const Text('Price'),
            value: _price,
            onChanged: (double? next) => setState(() => _price = next),
            format: _currency,
            step: 10,
            min: 0,
            fullWidth: true,
          ),
          MPNumberField(
            label: const Text('Commission'),
            value: _share,
            onChanged: (double? next) => setState(() => _share = next),
            format: _percent,
            parse: _readPercent,
            step: 0.01,
            min: 0,
            max: 1,
            fullWidth: true,
          ),
          MPTypography(
            'The values behind those are $_price and $_share.',
            level: MPTypographyLevel.caption,
          ),
        ],
      ),
    );
  }
}

steppers ​

세 가지 배치이고, 네 번째는 없습니다.

native 숫자 입력이 만들어 내는 모양 — 위아래로 쌓인 절반 높이 chevron 한 쌍 — 은 의도적으로 없습니다. xs에서는 화살표 하나가 3픽셀도 되지 않고, 그만한 표적은 아무도 맞히지 못합니다.

min이나 max에 닿은 증감 버튼은 그냥 반응하지 않는 것이 아니라 비활성화됩니다. 누르기 전에 갈 곳이 없다는 것을 볼 수 있어야 하니까요. readOnly는 두 버튼을 통째로 없앱니다. 비활성 상태로 남겨 두는 것은 같은 말을 두 번 하는 것이고, 그중 비활성 쪽은 고장 난 것처럼 보입니다. 증감 버튼을 누르고 있으면 잠깐 쉰 뒤 반복합니다.

floatingLabel ​

숫자가 없고 포커스도 없는 동안 라벨은 필드 자신의 줄 위에 내려와 있다가 포커스나 첫 숫자에서 노치로 올라갑니다. 규칙 전체는 MPTextField에 있습니다.

steppers="split"은 라벨을 노치에 고정합니다. startIcon과 같은 이유로, 빼기 버튼이 정확히 내려온 라벨이 설 자리에 앉기 때문입니다.

steppers: MPNumberFieldSteppers.split은 라벨을 노치에 고정합니다. startIcon과 같은 이유로, 빼기 버튼이 정확히 내려온 라벨이 설 자리에 앉기 때문입니다.

step, largeStep, smallStep ​

step은 화살표 키 한 번입니다. Shift는 largeStep(기본 10), Alt는 smallStep(기본 0.1)을 씁니다. Base UI의 관례이고 스프레드시트와 같은 동작입니다. Page Up과 Page Down도 largeStep을 쓰고, Home과 End는 범위에 끝이 있으면 min과 max로 갑니다.

<MPNumberField label="투명도" step={0.05} smallStep={0.01} min={0} max={1} />

onValueCommitted ​

onValueChange는 모든 변경마다 — 모든 키 입력, 모든 스텝, 휠 한 칸마다 — 발생합니다. onValueCommitted는 값이 확정될 때 한 번 발생합니다. 타이핑 후 blur, 버튼을 누르고 뗀 시점, 그리고 키보드에서는 onValueChange와 함께입니다.

onChanged는 모든 변경마다 — 모든 키 입력, 모든 스텝, 휠 한 칸마다 — 호출됩니다. onValueCommitted는 값이 확정될 때 한 번 호출됩니다. 타이핑 후 포커스를 잃거나 Enter를 누른 시점, 버튼을 누르고 뗀 시점, 그리고 키보드에서는 onChanged와 함께입니다.

앞의 것으로 폼 상태를 맞추고, 비싼 일은 뒤의 것에 두세요.

접근성 ​

  • 라벨은 외곽선의 홈에 놓이고 id로 input과 연결됩니다. 텍스트 필드와 똑같습니다.
  • 두 증감 버튼은 이름을 가진 진짜 버튼입니다. incrementLabel과 decrementLabel은 기본값이 영어이고, 현지화된 애플리케이션에서는 바꿔 주는 것을 전제로 합니다.
  • allowWheelScrub은 기본이 꺼짐입니다. 포인터 아래에서 페이지가 스크롤되는 것과 필드가 바뀌는 것은 같은 제스처이고, 의도한 쪽은 하나뿐입니다.
  • 화면 낭독기에게 필드는 라벨로 이름이 붙은 텍스트 필드 노드 하나입니다. 텍스트 필드와 똑같습니다.
  • 두 증감 버튼은 이름을 가진 버튼입니다. incrementLabel과 decrementLabel의 기본값은 locale의 단어입니다. Tab은 이 버튼에 멈추지 않습니다. 숫자를 움직이는 화살표 키가 필드의 것이므로, 버튼마다 멈추면 필드를 지나가는 데 두 번을 더 눌러야 합니다.

React 빌드와 다른 점 ​

이 페이지의 대부분은 두 패키지에서 같습니다. 아래는 같지 않은 지점과 그 이유입니다.
