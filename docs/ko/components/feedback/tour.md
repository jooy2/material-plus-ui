# MPTour

<p class="mp-lede">이미 있는 페이지 위를 걸으며 안내합니다. 몇 개의 단계가 각각 화면의 무언가에 붙고, 그 둘레만 어둠에서 도려냅니다.</p>

<Demo src="tour/hero" :minHeight="320" />

::: fw react

```tsx
import { MPTour } from 'material-plus-ui';

<MPTour
  open={running}
  onOpenChange={setRunning}
  steps={[
    { title: '환영합니다', content: '알아 두면 좋은 세 가지가 있습니다.' },
    { target: '#search', title: '검색', content: '무엇이든 여기서 찾을 수 있습니다.' }
  ]}
/>;
```

:::

::: fw flutter

```dart
import 'package:material_plus_ui/material_plus_ui.dart';

MPTour(
  open: _running,
  onOpenChange: (bool next) => setState(() => _running = next),
  steps: <MPTourStep>[
    const MPTourStep(title: Text('환영합니다'), content: Text('알아 두면 좋은 세 가지가 있습니다.')),
    MPTourStep(
      target: _search,
      title: const Text('검색'),
      content: const Text('무엇이든 여기서 찾을 수 있습니다.'),
    ),
  ],
);
```

위젯은 쓰인 자리에 아무것도 그리지 않고, 카드를 가장 가까운 `Overlay`로 띄웁니다. navigator가 있는 `WidgetsApp`이 `Overlay`를 제공합니다.

## 어둠은 포인터를 가져가지 않습니다

**투어와 대화상자 연속의 차이가 바로 이것입니다.** 카드가 떠 있는 동안에도 사용자는 지목된 컨트롤을 쓸 수 있습니다. 두 번째 단계가 말하는 필드에 입력하고, 세 번째 단계가 가리키는 버튼을 누를 수 있습니다. 그래서 할 수 있다는 설명을 읽는 대신 직접 해 보면서 배웁니다.

이 결정이 컴포넌트 전체로 이어집니다. 카드 바깥은 아무것도 막히지 않고, 포커스는 갇히지 않으며, 바깥을 누르거나 포커스가 나가도 투어는 끝나지 않습니다. 투어를 끝내는 것은 Escape, ×, 그리고 카드의 버튼들입니다. 반대쪽 동작이 필요하다면 [대화상자](dialog)를 쓰세요.

어둠은 블러도 걸지 않습니다. [MPOverlay](overlay)의 어둠은 블러를 겁니다. 2px 블러는 "지금은 이것을 쓸 수 없습니다"라고 말하는데, 투어가 하려는 말은 그 반대입니다.

## 구멍은 네 조각이 아니라 하나입니다

::: fw react

타깃 크기의 상자 하나가 어떤 화면보다도 큰 그림자를 두릅니다. 타깃 둘레에 사각형 네 개를 두르는 방법도 있지만, 그 모서리는 정확히 맞물리지 않습니다. 어둠이 완전히 불투명하지 않으면 이음매가 페이지를 가로지르는 가는 선으로 드러나고, MD3의 scrim은 32%라서 불투명하지 않습니다.

:::

::: fw flutter

화면 전체에서 타깃을 도려낸 경로 하나를 칠합니다. 타깃 둘레에 사각형 네 개를 두르는 방법도 있지만, 그 모서리는 정확히 맞물리지 않습니다. 어둠이 완전히 불투명하지 않으면 이음매가 페이지를 가로지르는 가는 선으로 드러나고, MD3의 scrim은 32%라서 불투명하지 않습니다.

:::

구멍은 단계 사이를 건너뛰지 않고 이동합니다. 투어가 진행되는 동안 화면에서 움직이는 것은 그 구멍 하나뿐입니다. 나머지는 전부 제자리에 있고, 그게 요점입니다.

## 단계가 타깃을 찾는 방법

::: fw react

`target`은 CSS 선택자입니다. 엘리먼트도 ref도 아닙니다. 투어가 말하는 대상은 이미 페이지에 있고, 그 단계에 도착한 순간의 페이지에서 찾습니다. 그래서 애플리케이션의 다른 부분이 렌더하는 것이나, 투어를 작성할 때는 아직 로드되지 않은 라우트가 그리는 것도 지목할 수 있습니다.

:::

::: fw flutter

`target`은 위젯에 단 `GlobalKey`입니다. 투어가 말하는 대상은 이미 화면에 있고, 그 단계에 도착한 순간의 화면에서 찾습니다. Flutter 화면의 위젯은 모두 누군가 직접 작성한 것이라 키를 달 수 있고, 키는 컴파일러가 확인합니다. React 빌드가 선택자를 받는 것은 웹 페이지에 자기 코드가 렌더하지 않은 엘리먼트가 있을 수 있기 때문입니다.

:::

`target`이 없는 단계는 아무것도 도려내지 않은 채 페이지 가운데에 놓입니다. 환영 단계와 마무리 단계가 그렇습니다.

## 구멍이 타깃을 따라가는 방법

::: fw react

**플랫폼에는 엘리먼트가 움직였다고 알려 주는 장치가 없습니다.** `ResizeObserver`는 _크기_가 바뀔 때 울리고, `scroll`과 `resize`는 창이 바뀔 때 울립니다. 타깃 위에서 배너가 로드되거나, 높이를 예약하지 않은 이미지가 도착하거나, 옆의 패널이 펼쳐지면 타깃이 움직이지만 아무도 알려 주지 않습니다. 사용자 눈에는 가리키던 것 옆의 빈 배경에 구멍이 뚫려 있게 됩니다.

그래서 투어는 실행되는 동안 매 프레임 타깃의 위치를 읽습니다. 같은 문제에 포지셔닝 라이브러리가 내놓는 답과 같습니다. 상태를 바꾸기 전에 rect를 비교하므로, 가만히 있는 페이지에서는 읽기 한 번 외에 렌더도 페인트도 들지 않습니다. 이 비용을 감수할 수 있는 것도 투어가 몇 초 동안, 한 번에 하나만, 사용자가 작업하는 대신 바라보는 페이지 위에 떠 있기 때문입니다.

:::

::: fw flutter

**프레임워크에는 위젯이 움직였다고 알려 주는 장치가 없습니다.** 타깃 위에서 배너가 로드되거나, 스크롤되거나, 옆의 패널이 펼쳐지면 타깃이 움직이지만 아무도 알려 주지 않습니다. 사용자 눈에는 가리키던 것 옆의 빈 배경에 구멍이 뚫려 있게 됩니다.

그래서 투어는 실행되는 동안 매 프레임이 끝날 때 타깃의 자리를 읽고, 자리가 바뀌었을 때만 다시 빌드합니다. 가만히 있는 화면은 프레임을 그리지 않으므로 비용이 전혀 들지 않고, 스크롤은 어차피 그리는 프레임마다 읽기 한 번이 듭니다. `ScrollController`를 따로 넘길 필요도 없습니다.

:::

## 이것이 아닌 것

투어는 문서가 아니고, 사용자가 두 번 찾을 내용을 담는 자리도 아닙니다. 투어는 요청하지 않은 사람에게, 다른 일을 하려는 페이지 위에서, 한 번 보입니다. 세 단계나 네 단계가 알맞은 길이입니다. 다시 찾아야 하는 것은 페이지에 있어야 하고, 한 문단이 필요한 것은 페이지가 링크하는 가이드에 있어야 합니다.

그리고 이것은 [MPStepper](../display/stepper)를 뒤집은 것입니다. 스테퍼는 안내를 페이지 _안에_ 넣고 사용자가 따라갑니다. 투어는 페이지를 그대로 두고 그 위에 섭니다. 단계가 작업에 대한 설명이 아니라 작업 자체라면 스테퍼를 쓰세요.

## 건너뛰기는 완료가 아닙니다

`onFinish`는 마지막 단계의 버튼에서만 호출됩니다. 건너뛰기, Escape, ×는 모두 이것을 부르지 않고 투어를 닫습니다. 완료할 때 "봤음"을 기록하는 온보딩이, 도중에 떠난 사람까지 완료로 표시하지 않게 하는 구분입니다.

::: fw flutter

## 접근성

- 카드는 단계의 제목을 머리글로 둔 대화상자로 읽히고, 그 아래 화면에도 여전히 닿을 수 있습니다. 일부러 route를 가져가지 않습니다. route를 가져가면 투어가 모달이 되어, 사용자가 투어가 설명하는 컨트롤에 닿지 못합니다.
- 투어가 열리면 카드가 포커스를 가져가서 Escape가 카드에 닿고, 투어가 닫히면 포커스를 원래 자리로 돌려줍니다. 포커스는 갇히지 않으며, Tab으로 다른 컨트롤 묶음처럼 카드를 벗어날 수 있습니다.
- 단계가 바뀌면 포커스가 다음 버튼에 머무는 동안 카드의 live region이 "3단계 중 2단계. 두 번째"처럼 도착한 자리를 알립니다. 투어가 처음 열린 단계에서는 포커스가 들어가면서 카드가 읽히므로 아무 말도 하지 않습니다.
- Escape와 시스템 뒤로 가기(안드로이드의 뒤로 버튼과 제스처, TalkBack의 뒤로, VoiceOver의 escape 제스처)는 `dismissible`이 `false`가 아니면 투어를 끝냅니다. 닫을 수 없는 투어는 뒤로 가기를 페이지로 넘깁니다. 투어는 페이지를 가져간 적이 없기 때문입니다.
- 영어보다 단어가 긴 언어에서는 카드의 버튼이 가장자리를 넘지 않고 두 번째 줄로 내려갑니다.

:::

## React 빌드와 다른 점

| React | Flutter | 이유 |
| --- | --- | --- |
| CSS 선택자인 `target` | `GlobalKey`인 `target` | 키는 컴파일러가 확인하고, 어느 위젯에든 달 수 있습니다. |
| `defaultOpen`, `defaultStep` | `initialOpen`, `initialStep` | 위젯이 시작값을 받아 스스로 기억할 때 Flutter가 쓰는 이름입니다. |
| 일부만 담은 객체인 `labels` | `Map<String, String>` | 같은 다섯 키를, 이 패키지의 모든 컴포넌트가 받는 모양으로 받습니다. |
| `className`, `style`, `classNames` | 없음 | 클래스를 걸 스타일시트가 없습니다. |
| 페이지 어디서든 Escape | 카드 안에서 Escape | 단축키는 투어가 열릴 때 포커스가 가는 카드에 걸려 있고, 페이지에서 누른 키는 페이지의 것입니다. |
| 렌더 없이 움직이는 구멍 | 프레임마다 읽기 | Flutter에는 스타일을 직접 쓰는 길이 없어서, 타깃이 움직였을 때만 다시 빌드합니다. |

:::
