# MPTour

<p class="mp-lede">이미 존재하는 페이지 위를 걷는 안내. 몇 개의 단계가 각각 화면의 무언가에 붙고, 그 둘레만 어둠에서 도려내집니다.</p>

<Demo src="tour/hero" :minHeight="320" />

```tsx
import { MPTour } from 'material-plus-ui';

<MPTour
  open={running}
  onOpenChange={setRunning}
  steps={[
    { title: '환영합니다', content: '알아 두면 좋은 세 가지가 있습니다.' },
    { target: '#search', title: '검색', content: '무엇이든 여기서 찾을 수 있습니다.' }
  ]}
/>;
```

## 어둠은 결코 포인터를 가져가지 않습니다

**이것이 투어와 다이얼로그 연속의 차이 전부입니다.** 카드가 떠 있는 동안에도 읽는 사람은 지목된 컨트롤을 쓸 수 있습니다 — 두 번째 단계가 말하는 필드에 타이핑하고, 세 번째 단계가 가리키는 버튼을 누를 수 있습니다. 그래서 배우는 모든 것이 "할 수 있다는 설명을 읽어서"가 아니라 "실제로 해 봐서" 배워집니다.

그 결정이 컴포넌트 나머지로 이어집니다. 카드 바깥의 어떤 것도 막히지 않고, 포커스가 갇히지 않으며, 바깥을 눌러도 포커스가 나가도 투어가 끝나지 않습니다. 끝내는 것은 Escape, ×, 그리고 카드 자신의 버튼들입니다. 다른 쪽을 원한다면 그 컴포넌트는 [다이얼로그](dialog)입니다.

어둠은 블러도 걸지 않습니다. [MPOverlay](overlay)의 어둠은 겁니다. 2px 블러는 "지금은 이것을 쓸 수 없습니다"라고 말하는데, 투어는 그 반대를 말하고 있습니다.

## 구멍은 네 조각이 아니라 하나입니다

타깃 크기의 상자 하나가 어떤 화면보다도 큰 그림자를 지고 있는 형태입니다. 타깃 둘레에 사각형 네 개를 두르는 것이 다른 방법인데, 그 모서리는 결코 정확히 만나지 않습니다. 어둠이 완전 불투명이 아닌 순간 이음매가 페이지를 가로지르는 실선으로 드러나고, MD3의 scrim은 32%라서 불투명이 아닙니다.

구멍은 단계 사이를 뛰지 않고 이동합니다. 그리고 투어가 진행되는 동안 화면에서 움직이는 것은 그것 하나뿐입니다. 나머지는 전부 있던 자리에 그대로 있고, 그게 요점입니다.

## 단계는 선택자로 지정합니다

`target`은 CSS 선택자입니다. 엘리먼트도 아니고 ref도 아닙니다. 투어가 말하는 대상은 이미 페이지에 있고, 그 단계에 도달한 순간의 페이지 모습에서 찾아집니다 — 그래서 애플리케이션의 다른 부분이 렌더하는 것이나, 투어를 작성하는 시점에는 아직 로드되지 않은 라우트가 그리는 것도 지목할 수 있습니다.

`target`이 없는 단계는 아무것도 도려내지 않은 채 페이지 가운데에 놓입니다. 환영 단계와 마무리 단계가 바로 그것입니다.

## 구멍은 어떻게 따라가는가

**플랫폼에는 "엘리먼트가 움직였다"를 알려 주는 것이 없습니다.** `ResizeObserver`는 *크기*가 바뀔 때 울리고, `scroll`과 `resize`는 창이 그럴 때 울립니다. 타깃 위에서 배너가 로드되는 것, 높이를 예약해 두지 않은 이미지가 도착하는 것, 옆의 패널이 펼쳐지는 것 — 이 모두가 타깃을 움직이지만 그중 무엇도 그렇다고 말해 주지 않습니다. 읽는 사람이 보는 것은 지목하던 것 옆의 빈 배경에 놓인 구멍입니다.

그래서 투어는 실행되는 동안 매 프레임 타깃의 위치를 읽습니다. 같은 질문에 대해 포지셔닝 라이브러리가 내놓는 답과 같습니다. 상태를 바꾸기 전에 rect를 비교하므로, 가만히 있는 페이지에는 읽기 한 번 말고는 아무 비용도 들지 않습니다 — 렌더도 페인트도 없습니다. 그리고 이것을 받아들일 만하게 만드는 것이 곧 그 경계입니다. 투어는 몇 초 동안, 한 번에 하나만, 읽는 사람이 작업 중이 아니라 바라보고 있는 페이지 위에 떠 있습니다.

## 이것이 아닌 것

문서가 아니고, 읽는 사람이 두 번 필요로 할 것을 담는 자리도 아닙니다. 투어는 요청하지 않은 사람에게, 지금 다른 일을 하려는 페이지 위에서, 한 번 보여집니다. 세 단계나 네 단계가 투어의 모양입니다. 다시 찾아야 하는 것은 페이지에 있어야 하고, 한 문단이 필요한 것은 그 페이지가 링크하는 가이드에 있어야 합니다.

그리고 이것은 [MPStepper](../display/stepper)를 뒤집은 것입니다. 그 컴포넌트는 안내를 페이지 _안에_ 넣고 읽는 사람이 그것을 따라갑니다. 이것은 페이지를 있는 그대로 두고 그 위에 섭니다. 단계들이 작업에 대한 설명이 아니라 작업 자체라면, 맞는 컴포넌트는 스테퍼입니다.

## 건너뛰기는 완료가 아닙니다

`onFinish`는 마지막 단계의 버튼에서만 발생하고 다른 어디서도 발생하지 않습니다. 건너뛰기, Escape, ×는 모두 그것 없이 투어를 닫습니다. 완료 시점에 "봤음"을 기록하는 온보딩이, 도중에 떠난 사람에게까지 완료 표시를 하지 않게 하는 것이 이 구분입니다.
