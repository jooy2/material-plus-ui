# MPMockup

<p class="mp-lede">진짜 페이지가 들어 있는 기기 그림. 내용은 그 기기 자신의 해상도에 맞춰 배치되고, 기기 전체가 주어진 자리에 맞게 한 번 축소됩니다.</p>

<Demo src="mockup/hero" :minHeight="460" />

```tsx
import { MPMockup } from 'material-plus-ui';

<MPMockup device="mobile" width={280}>
  <YourScreen />
</MPMockup>;
```

## 화면은 진짜 뷰포트입니다

`children`은 기기 자신의 해상도 — `md`인 폰이라면 CSS 픽셀 390×844 — 에 맞춰 배치되고, 그다음 기기가 축소됩니다. 그래서 안의 레이아웃은 그림이 들어간 상자가 아니라 그 기계에서 접히는 자리에서 접힙니다.

한 가지만 알고 계시면 됩니다. **미디어 쿼리는 여전히 창을 잽니다.** 노트북 위의 폰 목업 안에서 `@media (max-width: 600px)`는 거짓이고 앞으로도 그렇습니다. 페이지의 무엇도 창이 무엇인지를 바꿀 수 없습니다. 프레임 안에서 반응해야 하는 내용은 컨테이너 쿼리로 프레임을 재야 합니다.

```css
.card {
  container-type: inline-size;
}
```

## 그 축소는 transform이고, 예외입니다

이 라이브러리의 다른 모든 곳에서 지키는 규칙은 면을 옮기거나 키우지 않는다는 것입니다. 그건 **컨트롤**에 관한 규칙입니다. 크기가 바뀐 버튼은 눌린 그 순간에 글자가 다시 샘플링된 버튼입니다.

여기서는 아무것도 눌리지 않고, 축소 비율은 상호작용으로 바뀌지 않습니다. 남은 자리에서 한 번 정해지고, 그 자리가 바뀔 때만 다시 정해집니다. 1/3 크기로 그려진 기기는 기기의 그림이고 그것이 요점이며, 390픽셀 페이지를 130픽셀 상자 안에 배치하는 다른 방법은 없습니다.

## 여기서 `size`가 뜻하는 것

높이도 글자 크기도 아닙니다. `size`는 기기마다 다섯 개의 **실제 해상도** 중 하나를 고릅니다. 중요한 숫자는 미디어 쿼리가 발동하는 숫자이기 때문입니다. 390과 430에서 확인한 레이아웃은 대부분의 폰이 실제로 가진 두 너비에서 확인한 것입니다.

|           | `xs`     | `sm`     | `md`     | `lg`      | `xl`      |
| --------- | -------- | -------- | -------- | --------- | --------- |
| `mobile`  | 320×568  | 360×780  | 390×844  | 414×896   | 430×932   |
| `tablet`  | 744×1133 | 810×1080 | 820×1180 | 1024×1366 | 1032×1376 |
| `desktop` | 1024×640 | 1280×800 | 1440×900 | 1680×1050 | 1920×1200 |

다섯 중에 원하는 기계가 없으면 `resolution`이 통째로 덮습니다.

## 하드웨어는 사진이고, 소프트웨어는 페이지입니다

마감 색은 고정값이고 테마를 따르지 않습니다. 그래파이트 폰은 다크로 바뀐 페이지에서도 그래파이트입니다. 페이지를 따라 알루미늄이 하얘지는 목업은 아무것도 아닌 것의 목업이기 때문입니다.

화면 위의 크롬은 테마를 따릅니다. 메뉴 바와 상태 표시줄과 독은 `surface`와 `on-surface`로 그려지므로, 프레임은 남의 스크린샷 그림이 아니라 **여러분의** 페이지를 둘러싼 틀로 남습니다. 예외 안의 예외는 macOS의 창 조작 점 세 개입니다. 그것은 면이 아니라 모양이고, 페이지를 따라가는 빨강은 더 이상 닫기 버튼이 아닙니다.

## 크롬은 덮지 않고 자리를 차지합니다

시스템이 그리는 각 바 — 상태 표시줄과 홈 인디케이터, 메뉴 바와 독, 작업 표시줄 — 는 화면에서 자기 자리를 가져갑니다. 그래서 `systemUi={false}`는 아래 숨겨져 있던 것을 드러내는 것이 아니라 화면을 `children`에게 돌려줍니다. 크롬이 켜진 채로 프레임을 가득 채웠던 레이아웃은 꺼도 가득 채웁니다.

카메라 컷아웃은 반대입니다. 그것은 **하드웨어**라서 `systemUi`와 무관하게 그려지고 내용 위에 얹힙니다. 상태 표시줄을 껐다고 폰에 카메라가 없어지지는 않습니다.

## `bezel="none"`은 더 얇은 베젤이 아닙니다

하드웨어가 아예 없는 것입니다. 모서리만 깎인 화면 그 자체. 뷰포트만 원하는 목업이 요청하는 것이 그것입니다. 마케팅 사진이 아니라 반응형 미리 보기.

`thick`은 같은 기기의 두꺼운 판이 아니라 **옛날 기기**입니다. 좁은 옆면, 이마와 턱, 그리고 훨씬 각진 모서리. 그만한 베젤을 가진 기기가 실제로 그랬기 때문입니다.

## 어긋난 조합은 거부하지 않고 바로잡습니다

폰에 `os="macos"`를 준 것은 `device`를 바꾸고 다른 prop을 잊은 호출부이므로, 그 기기 자신의 시스템으로 떨어집니다. 390픽셀 화면을 가로지르는 데스크톱 메뉴 바가 아니라 폰이 쓸모 있는 답입니다.
