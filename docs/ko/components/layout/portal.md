# MPPortal

<p class="mp-lede">자식을 DOM의 다른 곳에, 보통은 <code>&lt;body&gt;</code> 끝에 렌더합니다. 제자리에 있으면 갇히게 되는 잘림이나 쌓임 맥락에서 빠져나와야 하는 서브트리를 위한 것입니다.</p>

<Demo src="portal/hero" :minHeight="220" />

```tsx
import { MPPortal } from 'material-plus-ui';

<MPPortal>
  <div className="fixed inset-x-0 bottom-0">…</div>
</MPPortal>;
```

## 빠져나오는 두 가지 덫

둘 다 마크업만 읽어서는 보이지 않습니다. 컴포넌트를 둘 만한 이유가 그것입니다.

**잘림.** 위쪽 어디에든 `overflow: hidden`이 있으면 잘립니다. 아무리 멀리 있어도 그렇습니다. 스크롤되는 카드 안에서 그린 패널은 자기 position이 무엇이든 카드 가장자리에서 잘립니다.

**containing block.** 조상에 `transform`이나 `filter`, `backdrop-filter`, 또는 1보다 작은 `opacity`가 있으면 새 containing block이 생기고, `position: fixed`인 자손은 뷰포트가 아니라 *그것*을 기준으로 측정됩니다. 그래서 애니메이션 중인 카드 안의 fixed 오버레이는 창과 무관한 자리에 놓이고, 그것도 애니메이션이 도는 동안에만 그렇습니다.

## 여기 대부분의 컴포넌트에는 필요 없습니다

이 라이브러리의 모든 팝업은 이미 스스로 포털합니다. 셀렉트의 목록, 다이얼로그, 툴팁, 메뉴, 드로어의 패널. 페이지 위에 떠 있는 것이 일의 전부인 컴포넌트가 그것을 호출부에 맡길 수는 없습니다.

이것은 호출부 **자신의** 오버레이를 위한 것입니다. 구조를 제어할 수 없는 페이지 안에서.

## 포커스를 가두지 않고 스택을 관리하지 않습니다

포털은 DOM에서 엘리먼트를 옮깁니다. 그것이 전부입니다.

포커스, Escape, 비활성 배경, 스크림, `z-index`는 *다이얼로그*의 관심사이고, 포털 안에 손으로 만든 오버레이는 그중 아무것도 갖지 않습니다. 이것보다 [MPDialog](./drawer)나 [MPDrawer](./drawer)를 먼저 보세요. 그것들이 지고 있는 접근성이 그것들의 대부분입니다.

## 첫 렌더에는 아무것도, 서버에서는 결코

포털에는 진짜 DOM 노드가 필요하고 서버가 렌더하는 동안에는 그런 것이 없습니다. 그래서 서버에서도 첫 클라이언트 렌더에서도 아무것도 그리지 않고, 그다음 렌더에서 엽니다.

hydration을 정직하게 유지하는 것이 그것입니다. 한 패스에는 있고 다른 패스에는 없는 마크업이야말로 React가 경고하는 불일치입니다. 실무적 결과는 **포털의 내용이 크롤러가 읽는 HTML에 결코 없다**는 것이므로, 색인돼야 하는 것은 포털에 넣지 마세요.

## `container`는 ref를 받고, 기다립니다

```tsx
const panel = React.useRef<HTMLDivElement>(null);

<div ref={panel} />
<MPPortal container={panel}>…</MPPortal>
```

ref는 첫 렌더에 `null`이고 그 엘리먼트를 그리는 커밋 중에 채워집니다. 이 컴포넌트는 마운트 때만이 아니라 **매** 렌더 뒤에 컨테이너를 찾으므로 나중에 나타나는 것도 잡습니다. 그리고 컨테이너가 없는 동안에는 아무것도 그리지 않습니다. body로 떨어뜨렸다가 한 프레임 뒤에 옮기는 대신에.

## 이벤트는 여전히 React를 타고 올라갑니다

포털 안의 클릭은 그것을 렌더한 엘리먼트의 `onClick`에 도달합니다. DOM상으로는 둘이 무관한데도 그렇습니다. 여기서 더한 것이 아니라 React 자신의 동작이고, 양쪽으로 사람을 놀라게 합니다. 클릭 가능한 카드 안의 포털 안의 메뉴는 여전히 그 카드를 엽니다.

## `disabled`는 분기를 아껴 주지 상태를 지켜 주지 않습니다

이 값을 바꾸면 자식이 **다시 마운트됩니다.** `{escape ? <MPPortal>{x}</MPPortal> : x}`와 똑같습니다. React는 포털과 인라인 서브트리를 다른 엘리먼트로 보고, 아래의 모든 것이 상태와 스크롤 위치와 그 안의 포커스를 잃습니다.

그러니 마운트마다 한 번 정하세요. 이 prop은 어떤 맥락에서는 포털되고 다른 맥락에서는 인라인인 컴포넌트를 위한 것이지, 토글할 것이 아닙니다.
