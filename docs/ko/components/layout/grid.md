# MPGrid

<p class="mp-lede">머터리얼의 레이아웃 그리드입니다. 한 행을 열로 나누고, 아이템이 그중 몇 개를 가져갑니다. 열 개수는 이 라이브러리가 임의로 정한 브레이크포인트가 아니라 명세가 정의한 <strong>윈도우 크기 클래스</strong>를 따라 바뀝니다 — 휴대폰에서 4열, 600dp부터 12열입니다.</p>

<Demo src="grid/hero" :minHeight="260" />

```tsx
import { MPGrid, MPGridItem } from 'material-plus-ui';

<MPGrid>
  <MPGridItem span={6}>절반</MPGridItem>
  <MPGridItem span={3}>4분의 1</MPGridItem>
  <MPGridItem span={3}>그리고 4분의 1</MPGridItem>
</MPGrid>;
```

## 브레이크포인트가 아니라 윈도우 크기 클래스

`span`, `offset`, `columns`, 그리고 간격 관련 세 prop은 값 하나를 받거나, 윈도우 크기 클래스를 키로 하는 맵을 받습니다.

| 클래스        | 시작   | MD3 열 개수 |
| ------------- | ------ | ----------- |
| `compact`     | 0      | 4           |
| `medium`      | 600dp  | 12          |
| `expanded`    | 840dp  | 12          |
| `large`       | 1200dp | 12          |
| `extra-large` | 1600dp | 12          |

각 항목은 자기 클래스부터 **위로** 적용됩니다. 그래서 레이아웃 하나는 보통 다섯 개가 아니라 두 개면 끝나고, 적지 않은 클래스는 그 아래 클래스가 말한 값을 그대로 유지합니다.

```tsx
<MPGridItem span={{ compact: 12, medium: 6, expanded: 4 }} />
```

휴대폰에서는 전체 폭, 600dp부터 절반, 840dp부터 3분의 1입니다.

**이건 일부러 Tailwind의 브레이크포인트가 아닙니다.** Tailwind는 640/768/1024/1280에서 바뀌는데, 같은 생각을 다른 숫자로 말한 것입니다. 그리드는 한쪽 기준에서 다시 흐르고 그 옆의 `md:` 유틸리티는 다른 기준에서 다시 흐른다면, 정확히 한 폭에서만 미묘하게 어긋나고 나머지 모든 폭에서 추론이 불가능한 레이아웃이 됩니다. 사다리가 둘이라면 이 라이브러리는 명세가 정의한 쪽을 택합니다.

직접 만든 유틸리티도 그리드와 함께 바뀌게 하려면, 같은 폭에 이름을 붙이면 됩니다.

```css
@theme {
  --breakpoint-medium: 600px;
  --breakpoint-expanded: 840px;
  --breakpoint-large: 1200px;
  --breakpoint-xlarge: 1600px;
}
```

## 머터리얼 자신의 그리드

compact 윈도우에서 4열에 16dp 간격, medium부터 12열에 24dp. 한 줄이면 되고, 그것이 명세가 그리는 레이아웃입니다.

기본값은 **아닙니다**. 기본값은 12열에 16dp 간격입니다. 600dp에서 나눗수가 저 혼자 바뀌는 기본값은 휴대폰에서 `span={6}`의 의미를 소리 없이 바꿔 놓고, 적어 둔 적 없는 폭에 산술이 의존하는 그리드는 화면만 봐서는 읽어 낼 수 없기 때문입니다.

## offset

아이템 **앞에** 비워 두는 열입니다. 행 안의 절대 위치가 아니라, 앞으로 밀어 넣는 공간입니다.

12열 행의 첫 번째에서 `offset={4}`에 `span={4}`면 가운데 3분의 1이 되고, 이미 4열을 가져간 아이템 뒤에서는 같은 offset이 4열을 더 건너뛰어 마지막 3분의 1에 놓입니다. `span`과 같은 방식으로 반응형입니다.

## 폭이 진짜 CSS인 이유

한 열은 `(100% + 간격) * span / columns - 간격`이고, 네 개의 폭에서 다시 계산되어야 하며, 그 열 개수는 **부모**에 선언되어 있는 엘리먼트의 폭입니다.

Tailwind는 이 중 무엇도 표현할 수 없습니다. Tailwind는 소스 텍스트를 훑어서 클래스를 찾는데 `columns`는 런타임에 호출자가 고르는 숫자이고, JavaScript로 조립한 클래스 이름은 Tailwind가 결코 보지 못하는 클래스 이름입니다. 그래서 산술은 스타일시트에 한 번만 쓰이고, 인스턴스마다 다른 숫자는 인라인 커스텀 프로퍼티로 도착합니다. 이 라이브러리에서 `color`가 배경까지 도달하는 방식 그대로입니다.

열 개수와 두 간격은 그리드에 선언되어 아이템에게 **상속**되며, React 컨텍스트로 전달되지 않습니다. 편법이 아닙니다. 미디어 쿼리는 React가 알지 못하는 사이에 상속된 커스텀 프로퍼티를 바꿀 수 있고, 그래서 아이템이 자신을 배치하는 기준이 되는 열 개수는 항상 지금 화면에 실제로 적용된 값입니다. 컨텍스트라면 같은 말을 하기 위해 윈도우 클래스가 바뀔 때마다 하위 트리를 다시 렌더해야 합니다.

행보다 넓은 span은 넘치는 대신 행에 맞춰 잘립니다. `span={99}`가 의미한 것이 그것이기 때문입니다.

## 그리드가 일부러 아닌 것들

**표면.** `variant`도 `color`도 패딩도 없습니다. 그리드는 그 안에 있는 표면들의 배치이고, 자기 시트를 그리기 시작하는 순간 페이지의 가장 바깥 요소로는 쓸 수 없게 됩니다. 시트가 필요하면 [MPBox](./box)나 [MPCard](./card)로 감싸세요.

**페이지 여백.** 그건 [MPContainer](./container)이고, 질문이 서로 다르기 때문에 별개의 컴포넌트입니다. 내용이 창 가장자리에서 얼마나 떨어져 있는가와, 내용이 자기를 어떻게 나누는가는 다른 질문입니다. 컨테이너는 그리드를 담는 것만큼이나 문단 하나도 잘 담고, 그리드에 컨테이너가 반드시 필요하지도 않습니다.

**분할 패널.** 손잡이로 나뉘는 두 영역이 필요하면 [MPPanes](./panes)를 쓰세요.

## 중첩

`MPGridItem` 안의 `MPGrid`이지, 아이템이면서 동시에 그리드인 것이 아닙니다. 안쪽 그리드는 자기 하위 트리에 대해 열 개수를 다시 선언하고, 그것을 감싼 아이템은 바깥 그리드가 준 폭을 그대로 유지합니다.

```tsx
<MPGrid>
  <MPGridItem span={6}>
    <MPGrid columns={2}>
      <MPGridItem span={1}>페이지의 4분의 1</MPGridItem>
      <MPGridItem span={1}>또 4분의 1</MPGridItem>
    </MPGrid>
  </MPGridItem>
</MPGrid>
```

## 접근성

- 그리드는 레이아웃이므로 role을 갖지 않고 아무것도 알리지 않습니다. 알리는 것은 그 안의 내용입니다.
- DOM 순서가 곧 읽히는 순서입니다. `offset`은 아이템을 문서에서 옮기지 않은 채 행 안에서만 밀어냅니다. 그게 핵심입니다 — 시각적으로만 존재하는 재배치는 스크린 리더가 결코 듣지 못하는 재배치입니다.
- 배치 자체가 의미를 갖는 경우를 위해 `render`가 있습니다. 그리드에 `render={<ul />}`, 아이템에 `render={<li />}`를 주면 카드 목록이 실제로 목록이 됩니다.
