# MPScrollZone

<p class="mp-lede">한 방향으로 놓이고 그 방향으로 스크롤되는 띠. 카드나 칩, 아바타, 썸네일이 상자를 가로질러 혹은 아래로 흐르고, 원하는 만큼의 줄로 배치되며, 휠도 손가락도 없는 포인터를 위한 버튼 두 개가 붙습니다.</p>

<Demo src="scroll-zone/hero" :minHeight="420" />

::: fw react

```tsx
import { MPChip, MPScrollZone } from 'material-plus-ui';

<MPScrollZone label="Categories">
  <MPChip>Espresso</MPChip>
  <MPChip>Filter</MPChip>
  <MPChip>Cold brew</MPChip>
</MPScrollZone>;
```

:::

::: fw flutter

```dart
import 'package:material_plus_ui/material_plus_ui.dart';

const MPScrollZone(
  label: 'Categories',
  children: <Widget>[
    MPChip(child: Text('Espresso')),
    MPChip(child: Text('Filter')),
    MPChip(child: Text('Cold brew')),
  ],
);
```

## 스크롤 컨테이너이고, 그것뿐입니다

폰에서 쓸어 넘기기, 트랙패드 두 손가락 드래그, 화살표 키, 스크롤바는 모두 브라우저의 것이고 어느 것도 가로채지 않습니다. 그 위에 얹은 것은 세 가지입니다. 그중 무엇도 할 수 없는 포인터를 위한 버튼 두 개, 페이지를 넘기기보다 잡아끄는 것으로 읽히는 띠를 위한 마우스 드래그, 그리고 `wheel`이 요청할 때만 띠의 축으로 돌려지는 휠.

아무것도 변형하지 않습니다. 트랙을 `translate`로 옮겼다면 라이브러리의 나머지가 지키는 규칙에 예외를 요구해야 했을 텐데, 스크롤 오프셋은 그럴 필요가 없습니다. 그 덕에 RTL에서 아무 말 없이도 반대 방향으로 흐르고, 스크롤바가 정직해지며, 포커스를 받은 자식을 브라우저가 알아서 화면 안으로 끌어옵니다.

:::

::: fw flutter

## 스크롤 뷰이고, 그것뿐입니다

손가락, 트랙패드, 키보드는 Flutter 자신의 것이고 어느 것도 가로채지 않습니다. 그 위에 더하는 것은 그중 아무것도 못 하는 포인터를 위한 버튼 한 쌍, 넘기는 것보다 끌어당기는 것으로 읽히는 띠를 위한 마우스 드래그, 그리고 `wheel`이 요청할 때만 띠가 달리는 축으로 돌려 놓는 휠입니다.

아무것도 변형하지 않습니다. 띠는 스크롤 오프셋이고, 그래서 오른쪽에서 왼쪽으로 쓰는 글에서는 따로 말하지 않아도 반대로 달립니다.

:::

## `lines`가 MPCarousel과 갈라지는 지점입니다

캐러셀은 한 번에 하나이고, 그 하나가 무엇인지 압니다. `value`가 있고, 인덱스가 있고, *이 앞의 슬라이드*를 뜻하는 화살표가 있고, 지금 어디인지 알려 주는 표시점 줄이 있습니다.

스크롤 존에는 그중 아무것도 없습니다. 자기가 놓인 자리보다 긴 선반일 뿐이라서 보고할 현재 항목이 없고, 썸네일 두 줄은 캐러셀이 아예 담을 수 없는 모양입니다.

::: fw react

```tsx
<MPScrollZone lines={2} gap={12}>
```

:::

::: fw flutter

```dart
MPScrollZone(lines: 2, gap: 12, children: shelf)
```

:::

::: fw react

플렉스 행이 아니라 그리드이고, 의도한 것입니다. 줄바꿈하는 행은 상자 가장자리에서 접히지만 여기서 필요한 것은 행 수를 고정하고 열을 필요한 만큼 늘리는 쪽입니다.

:::

::: fw flutter

자식은 `lines`개씩 묶여 가로 띠에서는 한 열이 되므로, 버튼을 한 번 누르면 열의 절반이 아니라 열 하나가 통째로 움직입니다.

:::

## 버튼이 어디 서느냐가 끝에서의 동작을 정합니다

`inline`은 버튼을 띠 옆, 레이아웃 안에 둡니다. 스크롤러가 버튼이 시작하는 자리에서 끝나므로 항목은 버튼 밑으로 미끄러지는 대신 버튼의 가장자리에서 잘립니다. `overlay`는 띠의 양 끝 위에 얹어 상자의 모든 픽셀을 내용에 남기고, 항목이 버튼 밑을 지나가게 둡니다. 버튼 아래 있는 것이 계속 이어지는 사진인 선반이 원하는 쪽입니다.

인라인 버튼이 앉은 자리는 그 버튼이 갈 곳을 잃어도 그대로 열어 둡니다. 자리가 사라졌다 나타나면 끝에 막 닿은 포인터 밑에서 띠의 크기가 바뀌고, 비워진 자리는 가벼워진 행이 아니라 모든 독자가 처음 마주치는 가장자리에 놓인 군더더기 여백으로 읽힙니다.

그래서 `buttons="auto"`는 두 가지로 갈라지고, 그 차이는 없앴을 때 치르는 값입니다.

| 배치      | 넘치지 않을 때 | 끝에 닿았을 때    |
| --------- | -------------- | ----------------- |
| `inline`  | 버튼 없음      | 그리되 `disabled` |
| `overlay` | 버튼 없음      | 제거              |

`buttons="always"`는 첫 페인트부터 둘 다 그리고, 끝에서는 사라지는 대신 `disabled`가 됩니다. 내용이 요청으로 늦게 도착하는 띠가 원하는 쪽입니다. 0.5초 뒤에 포인터 밑에서 버튼이 솟지 않습니다.

::: fw react

서버에서 렌더링하는 페이지에도 이쪽이 맞습니다. `auto`에서는 띠가 넘치는지를 페이지가 하이드레이션되고 측정한 뒤에야 알 수 있으므로, 서버 마크업에는 버튼이 없다가 나중에 인라인 버튼 둘이 나타납니다. 그 바람에 띠가 움직이고, 버튼이 한 줄보다 크면 그 아래 내용까지 밀립니다. `always`나, 띠 옆이 아니라 위에 그리는 `buttonPlacement="overlay"`는 아무것도 움직이지 않습니다.

:::

## 휠은 요청하기 전까지 페이지의 것입니다

페이지에서 빼앗은 휠은 페이지의 것입니다. 선반을 지나쳐 내려가려던 독자가 거기 붙들리는 것이야말로 가로 띠가 저지를 수 있는 가장 미움받는 일이라, `wheel`은 기본이 꺼짐입니다.

켜더라도 가져간 것은 끝에서 돌려줍니다. 앞에 남은 것이 없는 띠는 갇히는 곳이 아니라 지나쳐 가는 곳이 됩니다. 트랙패드의 가로 스와이프는 건드리지 않습니다. 그것은 이미 띠를 스크롤하고 있어서 여기서 답하면 요청한 것의 두 배를 움직이기 때문입니다. 세로 띠는 이 prop을 통째로 무시합니다. 거기서는 휠이 이미 띠가 흐르는 방향을 가리킵니다.

::: fw react

## 띠는 이름을 가진 탭 스톱입니다

그래야만 합니다. 아니면 포인터가 없는 독자는 띠를 움직일 방법이 아예 없습니다. 그리고 아무것도 알리지 않는 탭 스톱은 자기가 무엇인지만 말하는 탭 스톱보다 나쁘므로, 어느 쪽이든 `role="group"`과 이름을 답니다.

`label`은 띠 _안에_ 무엇이 있는지입니다. "카테고리", "최근 파일" 같은 것. 없으면 기본값이 그것이 무엇인지를 `locale`이 정한 언어로 말합니다.

버튼이 하는 일은 키보드도 할 수 있습니다. `hold` 모드에서는 홀드 자체가 포함됩니다. 버튼 위에서 Enter나 Space를 누르고 있으면 누르는 동안 계속 움직이는데, 포인터만 생각한 구현이 빠뜨리는 절반이 이것입니다.

:::

::: fw flutter

## 띠는 이름을 가진 포커스 정지점입니다

스크롤할 곳이 남아 있는 동안 띠는 그 자체로 포커스 정지점입니다. 그렇지 않으면 포인터가 없는 사용자는 포커스 받을 것이 하나도 없는 띠를 움직일 수 없습니다. 띠 방향의 화살표 키는 한 줄, Page Up과 Page Down은 한 화면, Home과 End는 양 끝으로 옮깁니다. 띠는 언제나 이름을 가진 시맨틱 컨테이너입니다. `label`은 띠 _안에_ 무엇이 있는지("카테고리", "최근 파일")이고, 없으면 기본값이 그것이 무엇인지를 `locale`이 정한 언어로 말합니다.

:::

::: fw react

## 드래그는 포인터가 뜻을 보일 때까지 기다립니다

누르는 순간에는 아무것도 가져가지 않습니다. 포인터 캡처도, 문서의 선택 영역도. 이 띠 위의 누름은 그 안의 카드를 클릭한 것인 경우가 훨씬 많으므로, 캡처는 포인터가 몇 픽셀을 넘어 움직인 뒤로 미룹니다. 그것이 평범한 클릭이 텍스트를 선택하고 자기가 누른 것에 포커스를 줄 수 있게 지켜 줍니다.

움직인 뒤라면 `pointerup`을 뒤따르는 클릭은 내려가는 길에 삼켜집니다. 그러지 않으면 드래그를 놓을 때마다 띠가 마침 멈춰 선 자리의 카드가 열립니다.

터치는 그대로 둡니다. 손가락은 이미 스크롤하고, 브라우저 자신의 스크롤에는 어떤 핸들러도 재현하지 못하는 관성과 고무줄 효과와 스크롤바가 딸려 옵니다.

:::

::: fw flutter

## 마우스로 띠 끌기

`drag`는 띠의 드래그 동작이 응답하는 장치에 마우스를 더합니다. Flutter의 제스처 경합은 이미 포인터가 어느 정도 움직여야 누름을 드래그로 판정하므로, 띠 안의 카드를 평범하게 누르면 여전히 클릭이고, 카드 위에서 끝난 드래그는 그 카드를 열지 않습니다. 손가락과 트랙패드는 `drag`와 상관없이 띠를 스크롤합니다.

:::

::: fw flutter

## React 빌드와 다른 점

| React | Flutter | 이유 |
| --- | --- | --- |
| CSS 길이를 받는 `gap` | 논리 픽셀 단위의 `double` | CSS 길이가 없습니다. |
| `mode="hold"`면 Enter나 Space를 누르고 있는 동안 이동 | 키는 한 번 누를 때마다 항목 하나 | 홀드는 포인터만 따릅니다. 키 입력은 탭으로 처리합니다. |
| `scrollbar`는 브라우저의 바를 보여 줌 | `scrollbar`는 얇은 `RawScrollbar`를 그림 | 여기서 Flutter는 플랫폼 바를 그리지 않습니다. |
| 버튼은 `MPIconButton` | 버튼은 아이콘만 가진 `MPButton` | 같은 것입니다. `MPIconButton`은 레이블 없이 아이콘만 가진 `MPButton`입니다. |
| — | `controller` | 띠를 바깥에서 움직이기 위해 Flutter에서 더했습니다. |

:::
